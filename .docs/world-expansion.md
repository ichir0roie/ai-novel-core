# 世界の展開(作者モード・人物モード)の設計

本筋(メインストーリー)は作者が書き、AI がその枝葉(補う話・別軸で進む話)を半自動で広げていく仕組みの設計。
実装済み。決めたことは末尾の「決まったこと」に並べる。使い方はスキル `expand`(作者モード)・`auto-act`(人物モード)と `data_access_logic/readme.md` の「世界の展開」。

## 目指す形

- **作者モード**: 作者が一言(「北の港で疫病が流行る」「ノアには姉がいた」)を言うと、それに関わるアイデア・出来事・人物と関係・来歴の行を AI が足し、
  関わる既存の行を直して、つじつまを合わせる。作者の一言が本筋になり、AI が足した行はその肉付けになる
- **プロットは出来事で持つ**: 筋(プロット)は話の枠ではなく出来事(`event`)で持つ。大きな筋を親の出来事にし、場面を子の出来事として時刻つきでぶら下げる(`parent_event_id`)。
  AI は話(`episode`)・作品(`story`)を作らない
- **人物モード**: 同じ仕組みを人物が使う。人物が自分の知ること・ミーム・行動原理から動き、出来事・アイデア・人物を**足す**。既にある行は消さず、
  直すのは `end` を付ける(居場所を離れる・関係が終わる・持ち物を失う)ことだけ
- **出自**: 行ごとに「作者が作ったか / AI が作ったか」を持ち、AI は作者の行に触らない

## 今あるもの(使えるもの)

| 欲しいもの | 今あるもの | 足りない所 |
| --- | --- | --- |
| 関わる行を探す | `SearchIdeas` / `ResolveIdeas`(アイデアだけ)、表の API の `q`(題・本文の部分一致) | 人物・出来事・話・場所・ミームをまたいで一言から引く入口が無い |
| アイデアを足す | `ResolveIdeas` / `AddIdeas`(当たらない語を候補として足す)、`CommitIdea` | — |
| ミームを足す | 本文を渡した `CommitEpisode` の確定のあと(話の本文からだけ) | 展開からは足さない(似たミームばかり増えるので) |
| 出来事を起こす | `GenerateEvent`(場所を軸に、種から候補 → サイコロ → 記録。当事者の来歴・居場所も動かす) | 人物の狙いから起こす道が無い。消す・直すを含む(居場所の行の `end` を閉じる) |
| 人物を作る | `GenerateCharacter` / `GenerateCharacters`(世界との検め・名付け・人数の上限つき) | — |
| 筋(プロット)を立てる | 出来事の親子(`parent_event_id`)、生成に後の時刻の出来事を渡して矛盾させない決まり(`LATER_EVENTS_NOTE`) | 出来事は一件ずつ起こすだけで、筋として親子に組み立てる段が無い |
| 人物が知ることだけで動く | `ReadKnowledge`(知る相手で絞った材料)、人物役 `character-actor`(話の手番の中だけ) | 話の外で、人物が自分から動く道が無い |
| つじつま合わせ | スキル `story-director` の「矛盾を確かめる」観点、`auto-revision` | 人(セッションの Claude)が読んで判断するだけで、機械で回す段が無い。直した記録はスクラッチパッドの控え |
| 作者の判断待ち | `ListPendingReviews`(本文に残った TODO) | 食い違いを「判断待ち」として残す置き場が無い |
| 誰が作ったか | 無い(API の鍵の名前をログに出すだけ) | 行の出自・書き手の区別・守り |
| 何を変えたか | 無い | 一回の展開で足した・直した・消した行の記録と、取り消し |

## 足りないもの(この設計で足すもの)

1. 行の出自(`origin`)と、呼び出しごとの書き手(`writer`)、AI が作者の行に触れない守り
2. 展開の記録(一回の展開を一行、そこで変えた行を一行ずつ)と、展開ごとの取り消し
3. 子の行を一行ずつ足す入口(今は来歴・知る相手の配列をまるごと置き換える入口しか無い)
4. 一言から関わる行を表をまたいで引く入口
5. 作者が直すかを決める「食い違い」の置き場
6. 作者モードの流れ、人物モードの流れ、それを回し続けるスキル
7. 画面: 出自の印と絞り込み、展開の一覧と差分・取り消し、食い違いの一覧

## 1. 出自と書き手

### 行の出自(`origin`)

物語の中身を持つ表に `origin` 列を足す。値は `user`(作者)/ `ai`。

- 対象: `story` `episode` `episode_character` `character` `character_parameter` `character_location` `character_relation` `character_relation_history`
  `character_history` `character_skill` `character_skill_history` `event` `event_character` `idea` `idea_history` `location` `location_history`
  `meme` `oracle` `event_seed` と、知る相手の四表(`*_knower`)
- 対象にしない: `event_summary`(本文から作り直す派生)、`style_preference`(作者だけが書く)、`narou_part`、`personality_level`
- `db/schema.py` に `OriginMixin`(`origin: Mapped[str]`、既定 `user`)を置き、上の表のクラスに足す。子の行(来歴・知る相手)も自分の `origin` を持つ。
  作者の人物に AI が来歴の行を足したとき、その行だけが `ai` になる
- 作者が `ai` の行を画面で直したら、その行は `user` になる(作者が手を入れた行は作者のものとして守る)

### 呼び出しごとの書き手(`writer`)

書き込みのたびに、誰の手で書くかを `contextvars` で持つ(`db/writer.py` を新設)。

| 書き手 | 誰 | 足した行の出自 | 直す・消す |
| --- | --- | --- | --- |
| `user` | 画面(API の鍵 `gui`)、作者が確かめて確定する Claude のセッション | `user` | どの行も |
| `ai` | 作者モードの展開 | `ai` | `ai` の行だけ |
| `ai_append` | 人物モード | `ai` | `end` で終わりを付けることだけ(下の「`end` を付ける」)。消さない |

- 守りは `db/guard.py` に置き、SQLAlchemy の mapper の事象(足す・直す・消す)で行ごとに走らせる。足す行に出自を入れ、書き手が許さない直し・消しがあれば
  `ProtectedRowError` で止める(トランザクションごと戻る)。入口ごとに書く守りでなく db の層一つで守るので、来歴の配列をまるごと置き換える入口(`UpdateCharacter` など)を
  AI が呼んでも、外れた作者の来歴の行は消せない。親を消して子が連れて消える場合も同じに守る。`delete(...)` / `update(...)` の一括の書き込みは `do_orm_execute` で当たる行を引いて守る
- `ai` の書き手が AI の行を消すとき、その行を指す作者の行(作者の話の名前だけ出る人物の行・作者の来歴の知る相手など)も一緒に消える形なら、その作者の行で止まる
- **`end` を付ける**: 書き手 `ai_append` が直してよいのは `end` 列だけで、空なら時刻を入れ、入っていればそれより前に早める直し(没年まで続く居場所の行を、移る時刻で終えるなど)。
  ほかの列が一つでも変わる直し、`end` を空に戻す・先へ延ばす直し、`end` を `start` より前にする直しは止める。同じトランザクションで足した行を整える(親を結ぶなど)のは、足すことに数える。`end` を持つ表は `character`(没年)・`character_location`・`character_relation`・`character_history`・
  `character_skill_history`・`idea_history`・`event`・`location`。居場所を移すのは、今の居場所の行に `end` を付けて、移動先の行を足す(`character/moves.py` の `update_locations` と同じ形)。
  許す直しは守りの中で列の名前(`APPENDABLE_COLUMN`)で持つので、あとで広げられる
- API は `x-novel-writer` / `x-novel-expansion` / `x-novel-generated` ヘッダで書き手を受ける。鍵 `gui` は常に `user`、web のセッションの鍵は省けば `user`(今の動きを変えない)。展開の流れは自分で `ai` / `ai_append` を立てる
- 今の AI の生成の入口(`GenerateEvent` `GenerateCharacter(s)` `AddIdeas` `ResolveIdeas` の候補、ミーム・種の抜き出し、話の確定のあとに足す関係)が足す行は、書き手が `user` でも出自を `ai` にする
  (作者が確かめずに入った行なので。流れを `db.writer.generated` で包む)。直す・消すの守りは書き手で決まるので、今の入口の動きは変わらない
- ミームの分類・対づけと種のまとめは今ある行を直すので、AI の書き手のあいだは、その書き手が直せる行だけに回す(作者の行は作者が回すときに直る)

### 今ある行の出自

マイグレーションで、今ある行はすべて `user` にする(AI が既存の行に触らない、いちばん安全な形)。

## 2. 展開の記録

### 表

```
expansion(展開)                       一回の展開を一行
  id, created_at, updated_at
  mode         'author' | 'character'
  prompt       作者の一言(作者モード)/ 人物の狙い(人物モード)。作者の一言は本筋の正として、後の展開のつじつま合わせでも読む
  story_id     どの作品の枝か(省けば作品を限らない)
  actor_id     人物モードで動いた人物(character)
  time         展開の時刻(一言の時刻・人物が動いた時刻)
  location_id  展開の場所
  status       'running' | 'done' | 'failed' | 'reverted'
  summary      何を足し・直したかの要約(AI が書く)

expansion_change(展開で変えた行)       変えた行を一行ずつ
  expansion_id
  table_name, row_id
  op           'add' | 'update' | 'delete'
  before       直す・消す前の行(JSONB)。足した行は空
  reason       なぜ変えたか(どの一言・どの食い違いのため)

expansion_conflict(食い違い)           作者の行と食い違うが、AI が直せないもの
  expansion_id
  table_name, row_id   食い違う作者の行
  detail       何と何が食い違うか
  proposal     こう直せば合う、という案
  status       'open' | 'accepted' | 'dismissed'
```

- 変えた行は、展開の id が立っているあいだ(書き手を問わない)、守りが行ごとの事象で自動で `expansion_change` に書く(入口ごとに記録を書かない)
- **取り消し**(`RevertExpansion(expansion_id)`): `expansion_change` を逆の順にたどり、足した行を消し、直した・消した行を `before` に戻す。
  その行を後の展開か作者が直していたら(`updated_at` が記録より新しい)取り消さずに止め、どの行かを返す
- 足した行がどの一言から生まれたかは `expansion_change` から引ける(行どうしを結ぶ汎用の表は作らない。行どうしの関わりは今の外部キー・中間表で持つ)
- 食い違いの一覧は `review.list_pending_reviews` に足し、本文の TODO と並べて出す。作者が案を受けたら、書き手 `user` で直す

## 3. 足りない入口

### 一行ずつ足す入口

今の `UpdateCharacter` などは来歴・知る相手の配列をまるごと置き換える。人物モードは足すことと `end` を付けることしかしないので、一行を足す入口を置く(作者モード・既存のスキルも使える)。

| 入口 | 足すもの |
| --- | --- |
| `character.append_history.AppendCharacterHistory` | 人物の来歴の行(知る相手つき) |
| `character.append_relation_history.AppendRelationHistory` | 関係の来歴の行 |
| `location.append_history.AppendLocationHistory` | 場所の来歴の行 |
| `idea.append_history.AppendIdeaHistory` | アイデアの呼び名の行 |
| `character.add_knower.AddKnower` | 既にある来歴・呼び名の行に、知る相手を一人足す(人物が話を聞いて知った、など) |

### 表をまたいで引く入口

`query.world_query`(新設)と `world.search_world.SearchWorld(keywords, time=None, location_id=None, story_id=None, limit=None)`。
`ResolveIdeas` と同じ `IdeaDraft` の語で、人物(名前・芯・来歴)・出来事(名前・本文)・話(題・プロット)・場所(名前・芯・来歴)・アイデア(今の `dictionary_query`)・ミーム・作品の筋書きを部分一致で引き、
当たった行の id・表・出自・要点を返す。当たった人物の関係・当事者の出来事・場所の配下は、段を一つ広げて添える。

## 4. 作者モード(展開)

スキル `expand`(合図は「ex<作品id> <一言>」か、作品を限らないなら「ex <一言>」)。セッションの Claude が流れを回し、AI の段は今の生成を使う。
作者に尋ねず、認めも待たずに AI の行を足して直す(作者の行には触らないので、待たずに入れても作者の本筋は崩れない。合わなければ展開ごと取り消す)。

1. **受ける**: `expansion` を一行足す(`prompt` に一言、書き手 `user`)。ここから先は書き手 `ai`、展開の id を立てる
2. **読み解く**: 一言を「主張」に分ける(設定・出来事・人物・関係・筋)。主張ごとに時刻・場所・関わる人物を決める。決まらなければ、作品の書き進めた所(本文のある話の一番新しい時刻)とその場所を取り、要約に書く
3. **引く**: 主張の語で `SearchWorld` と `ResolveIdeas` を引き、関わる行を集める
4. **広げる**: 主張ごとに、要るものだけを足す。一回の展開で足す行は 30 行ほどまで(スキル `expand` の決まり)
   - 設定 → アイデアと呼び名(`ResolveIdeas` / `CommitIdea`)
   - 出来事 → 出来事(`GenerateEvent` の場面の指定に主張を渡す)と、当事者・場所の来歴
   - 人物 → `GenerateCharacter`(主張を `plot_text` に)と関係
   - 筋 → 出来事の木。筋の全体を親の出来事(`start` / `end` で期間を持つ)にし、場面を時刻つきの子の出来事として足す。
     本筋の書き進めた所より先の時刻の出来事は、後の生成(出来事・人物モード)に「後に決まっている出来事」として渡り、筋を守らせる。
     サブキャラクターに未来を書かない決まり(`data_access_logic/readme.md` の「人物の来歴」)は来歴の行の決まりなので、先の出来事の当事者にはしてよいが、来歴の行は出来事の時刻が来るまで足さない
5. **つじつまを合わせる**: 足した行と 3 で引いた行を、作者の一言(これまでの展開の `prompt` すべて)・作者の行と照らす。観点はスキル `story-director` の「矛盾を確かめる」(時刻・人物・関係・知ること・設定・場所・伏線)
   - 食い違う相手が `ai` の行 → 直すか消す(作者の一言と作者の行に合わせる)
   - 食い違う相手が `user` の行 → 直さずに `expansion_conflict` に残し、直す案を添える
   - 直したことで新しい食い違いが出ていないかを、もう一巡だけ確かめる(二巡で止める。広がり続けないように)
6. **返す**: `expansion.summary` を書き、`status` を `done` にする。足した・直した・消した行の数と要点、作者に残した食い違いを返す

作者の一言が作者の行と正面からぶつかる(「ノアには姉がいた」のに、作者の来歴に「一人っ子」とある)ときは、一言を正として AI の行を広げ、作者の行は食い違いに残す。

## 5. 人物モード(自走)

人物が自分から動く。流れ `flows/act.py`(`claude -p` で回る、`GenerateEvent` と同じ形の流れ)と入口 `expansion.act_character.ActCharacter(character_id=None, time=None, nudge=None, seed=None)`。
書き手は `ai_append`。足すことと `end` を付けることだけをし、消さない。

1. **動く人物を選ぶ**: 渡されなければ、その時刻に生きて居場所のある人物のサブキャラクター(`main_character` が false)の中から、行動力の重み(`constants.ACTOR_WEIGHTS`)で引く
2. **時刻を決める**: その人物が最後に出た出来事・話より後で、サブキャラクターに未来を書かせない決まり(`data_access_logic/readme.md` の「人物の来歴」)を守る時刻。後に決まっている出来事(`LATER_EVENTS_NOTE`)とは矛盾させない
3. **狙う(人物の目)**: `ReadKnowledge` と同じ材料(知る相手で絞った来歴・関係・アイデア、本人のミーム・行動原理・性格)と、居合わせる人物・場所の直近の出来事から、
   人物が「何を狙って何をするか」を一手で書く(人物役 `character-actor` の一手と同じ形。筋書き `plot` は渡さない)。`nudge` は作者からの軽い方向づけ
4. **裁く(作者の目)**: 狙いと行動から、世界で起きたことを決める。成否はサイコロ(`GenerateEvent` の候補 → 記録と同じ)。結果として足すもの:
   - 出来事(当事者は居合わせる人物から)と、当事者ごとの来歴の行
   - 新しいアイデア(人物が考えた・広めた。呼び名の行の知る相手は人物と聞いた相手)
   - 新しい人物・対象(生まれた子・雇った者・作った組織。`GenerateCharacter` で)と、その人物との新しい関係の行
   - ミームは抜き出さない(ミームは話の本文の確定のあとにだけ抜き出す)
   - 終わったこと: 居場所を離れた(今の居場所の行に `end`、移動先の行を足す)、関係が終わった・持ち物を失った・死んだ(その行に `end`)
5. **書く**: 足すことと `end` を付けることだけ。`expansion`(`mode=character`、`actor_id`)に記録する
6. **筋にまとめる**: 人物が新しい狙いで動き始めたら、その筋の親の出来事(`end` は空)を一つ足し、続く手の出来事をその子として足す。
   狙いが果たされた・潰えたら、親の出来事に `end` を付けて筋を閉じる。この親の出来事の並びが「別軸で進むストーリー」になる

回し続けるのはスキル `auto-act`(「自走」)。`auto-revision` と同じく 5 時間ごとの使用量が切れる前に止め、一手ごとに動いた人物と足した行を一行ずつ返す。

## 6. 今ある仕組みの改廃

| 仕組み | どうする | わけ |
| --- | --- | --- |
| スキル `story-director` | 作者モードに畳む。作者の行への提案と認めの流れ(2・3)は、食い違いの案を作者が受ける道としてそのまま使い、控え(スクラッチパッド)は `expansion_change`(書き手 `user`)に替える | 指示 → 矛盾の確かめ → 直す、の骨組みが同じ。直す記録を db に一本化する |
| `GenerateEvent` | 入口は残す(画面・作者モードが場面を名指しして使う)。候補 → 記録の段を人物モードの「裁く」と共通にする | 場所を軸に起こすか、人物の狙いから起こすかの違いだけ |
| 出来事の種(`event_seed`) | 残す。人物モードの「狙う」に、思いつきの元として渡す | 筋の型の貯まりとして使える |
| `GenerateCharacters` | 残す(場所に人を撒く)。足した行の出自は `ai` | — |
| スキル `auto-revision` | 残す。本文の推敲で、作者が自分で回すものなので書き手は `user` のまま | — |
| スキル `run-ai-tasks` | 残す | — |

## 7. 画面

- 表の一覧・詳細に出自の印(`AI`)と、出自での絞り込み
- 展開の一覧(新しい順。一言・モード・動いた人物・足した/直した/消した数・状態)と、展開ごとの差分(`before` と今)、取り消しのボタン
- 食い違いの一覧(作者の行・中身・案)と、受ける / 捨てるのボタン(受けたら書き手 `user` で直す)
- 画面には AI のボタンを置かない今の決まり(`.docs/claude-tasks.md`)は保つ。展開を回すのは Claude のセッション

## 8. 段取り

一段ずつ、実装 → 確かめ → 網羅テスト → プルリクで進める。

1. 出自と書き手: `origin` 列とマイグレーション、`db/writer.py`、`db/guard.py` の守り、API のヘッダ、AI の生成の入口が足す行を `ai` に、画面の印と絞り込み
2. 展開の記録: `expansion` / `expansion_change` / `expansion_conflict`、変えた行の自動の記録、`RevertExpansion`、食い違いを `ListPendingReviews` に、画面の展開の一覧
3. 入口: 一行ずつ足す入口、`SearchWorld`
4. 作者モード: スキル `expand`、`story-director` を畳む
5. 人物モード: `ActCharacter` と流れ、スキル `auto-act`、`GenerateEvent` と段を共通に、筋の親の出来事の開け閉め

## 決まったこと

- プロットは出来事で持つ。AI は話・作品を作らない
- 人物モードは足すことのほか、`end` で終わりを付けることを許す(居場所の移動もこれで行う)。作者の行にも付けてよい(取り消せる)
- 今ある行の出自は、すべて `user` にする
- 作者が AI の行を直したら、その行は `user` になる
- AI が作者の人物・場所・アイデアに、出自 `ai` の来歴・呼び名・知る相手の行を足すのは許す
- 作者が回す AI の道具(`auto-revision`・`ep` の本文)は、今のまま書き手 `user`
- 作者モードは認めを待たずに AI の行を入れ、合わなければ展開ごと取り消す。作者の行は案にして認めを待つ
- 人物モードで動くのはサブキャラクターだけ
