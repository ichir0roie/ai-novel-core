name: interactive-episode
description: 話(episode)の手番を、ユーザが語り部を務めてチャットで一手ずつ回す(インタラクティブモード)。プロットか登場人物・場所の決まった話で、このセッションの Claude が先に話の情報・設定(アイデア)・関係を整え、人物役(character-actor)を起こす。ユーザが場面と行動を出すたびに手番の行を足し、対象の人物の一手が返ったら見せて指示を待つ。終わりの合図で手番を閉じて人物役を止め、本文を書いて確定する。「ep61 in」(61 は話の id)、「インタラクティブで書きたい」「語り部は自分がやる」「場面を出すから人物を動かして」などの依頼で使う。
---

入口・呼び方・本文の書き方は、スキル `episode` の「入口」「本文に起こす」「書くとき」のとおり。
スキル `episode` の手順 6(手番を回す)を、Claude が語り部として自動で回す代わりに、ユーザが語り部を務めて場面と行動を出して回すもの。
「ep<話id> in」がこのスキルを始める合図(Claude が手番を自動で回して、終えたらまとめを報告するのは「ep<話id>」で、スキル `episode`)。

- 語り部はユーザ。このセッションの Claude は、ユーザの出した場面と行動を手番の行(要求)に起こし、返った一手を見せるだけにする。場面を自分で先へ進めない・ユーザの出していない出来事を足さない
- ユーザの場面・行動に、プロットにも材料にも無い固有の語(獣・道具・店・制度・呼び名など)が出たら、手番の行を足すときに `add-ideas` でアイデアに足す(書き方はスキル `episode` の「新しい語を足す」)
- 人物が場面でどう動くかは人物役が決める。Claude は人物役の一手を書き換えない

## 1. 整える(Claude がする)

1. **登場人物・場所・関係を整える**: スキル `episode` の「セッションの前に整える」の 1〜5。プロットか登場人物のどちらかが要る(どちらも無ければ始めず尋ねる)。すでに結んである話でも飛ばさない
2. **語り部の材料を読む**: `.venv/bin/python -m tool.episode_session stage --episode <episode>`。中身はプロット・場所・登場人物の表層(名前・年齢・性別・体格・装い・外見)・知り合いの組だけ。人物の内側と、だれが何を知っているかは人物役が自分のデータから出すので、ここには無い
3. **ユーザに返す**: 時刻・場所・登場人物(人物役を起こす人物)・整えたこと(「セッションの前に整える」の 6)・足した設定の候補(照らしたとき)・プロットの場面(あれば)を短く返し、最初の場面を待つ。直す指示があれば(プロットを直したときも)1 からやり直す

## 2. 人物役を起こす

最初の場面を受けたら(整えた中身を直す指示でなければ)、人物役を起こしてから手番を足す。人物役は起きたときに `knowledge` を読むので、関係・設定を整え終えてから起こす。

0. **前の行を見る**: `read --episode <id>` が空でなければ、ユーザに「消して始めるか」を尋ねる。消すなら `clear --episode <id>`。最後が終了の行のまま続けると、人物役がすぐ止まる
1. 台詞・行動のある登場人物ごとに、エージェント `character-actor` を一つ裏で(`run_in_background`)起こす。最初のメッセージには話の id・人物の id だけを書く
2. 端役(屋台の主・通行人など)と群衆は人物役を起こさない。ユーザの出した言葉どおりに、語りへ書く。ユーザが名前を出さない限り、端役に名前を付けず、役割か見た目で書く(スキル `episode` の「登場人物・場所」)
3. 人物役が「終わった」と返して止まったのに、まだ手番を閉じていなければ、同じメッセージでもう一度起こす(`knowledge` を読み直して番を待つ)

## 3. 手番を回す(ユーザの場面ごと)

ユーザのメッセージ一つを、場面と行動の指示として受け、次を繰り返す。

1. **対象の人物を決める**: ユーザが名指しした人物。名指しが無ければ、出された行動を向けられた人物。決めかねるときは足す前に尋ねる
2. **要求を足して待つ**: スキル `episode` の「語り部の決まり」「手番の要求を足す」に沿って語りと要求を書き、`add --episode <id> --turns - --wait` で足す(Bash の timeout は 3600000)。このスキルで違うのは次だけ
   - ユーザの出した場面・端役の動きは、その場の人物みなに見える・聞こえるなら語り(`narration`)に、一人にだけ分かることはその人物の `request` に書く
   - ユーザが登場人物の行動を指示したら(「A が戸を開ける」)、その人物の `request` に、この手番で求めることとして書く(「戸を開けるところまで」)。内心・セリフは人物役に任せる
   - ユーザが時間を進めた・移動させたら、`time` を新しい時刻にし、そのあいだのことを語りにまとめる
   - 場面の途中で新しい人物が台詞・行動を持つことになったら、`CastEpisode` で登場人物に足し(まるごと置き換わるので今の人物も渡す)、その人物について「セッションの前に整える」の 3・4(関係・知る相手)を済ませ、人物役を起こしてから要求を足す
3. **見せて待つ**: 返った一手(`answers`)を、人物ごとに次の形で見せ、ユーザの次の指示を待つ(時刻は足したときの `time`)。次の手番を自分から足さない

   ```
   **<人物名>**(<時刻>)
   - 内心: …
   - 行動: …
   - セリフ: 「…」
   - 狙い: …
   ```

   - プロットがあり、一手が大筋から外れそうなら、見せるときに一行添える(直すかはユーザが決める。プロットは直さない)

## 4. 終える(終わりの合図)

ユーザが終わりを告げたら(「終わり」「ここまで」「本文にして」など)、手番を閉じて本文へ進む。

1. **閉じる**: `close --episode <id>` で終了の行を足す。人物役はそれを読んで止まる。止まった知らせが来ない人物役は `TaskStop` で止める
2. **プロットが空なら書く**: セッションの行から、`ai/instructions/plot.py` の `PLOT_FORMAT_INSTRUCTION` の形(`## 場面` / `## 狙い`)でプロットを書き、`CommitEpisode` に `id`・`plot_text` を渡して入れる(プロットに名前の出る人物が拾われる)
3. **本文を書いて確定する**: スキル `episode` の手順 7〜10 と「話のあとに、知ったことを足す」のとおり。筋はセッションの行だけから取る(「本文に起こす」)
   - 「本文は自分で書く」と言われたら、1・2 までにして本文は書かない。GUI の話のセッションの画面(`/episode_session?episode=<id>`)の Write で書けることと、書き終えたら「ep<id> 書いた」(画面の Finish ↗ でも同じ)で反映すること(スキル `episode` の「ユーザが書いた本文を反映する」)を一行ずつ添えて終える

## 報告する

スキル `episode` の「報告する」のとおり。手番の数は、ユーザが出した場面の数と、足した手番の行の数を書く。
