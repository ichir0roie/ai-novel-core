description: 作者(ユーザ)・語り部(このセッションの Claude)・人物役の順に一巡しながら、話(episode)の本文を代わる代わる書き進める(インタラクティブモード)。作者がチャットで本文を書く(か場面・指示を出す)たびに、語り部がその先を予測して場面を組み、人物役(character-actor)に手番を回し、返った一手を本文に書き足していく。一巡したら作者に番を返す。終わりの合図で手番を終え、書けた本文を世界に反映する。「ep61 in」(61 は話の id)、「インタラクティブで書きたい」「書きながら人物を動かしたい」「自分の書いた続きを人物に演じさせたい」などの依頼で使う。
---

入口・呼び方は、スキル `episode` の「入口」のとおり。
「ep<話id> in」がこのスキルを始める合図(Claude が手番を最後まで自動で回して本文を書くのは「ep<話id>」で、スキル `episode`)。

## 役と流れ

| 役 | だれ | すること |
| --- | --- | --- |
| 作者 | ユーザ | このチャットで本文を書く。場面・指示だけを出す、何も書かずに続きを任せる(「続けて」など)こともある |
| 語り部 | このセッションの Claude | 作者の書いたことを本文に入れ、先を予測して場面を組んで人物役に手番を回し、返った一手を本文に書き足す |
| 人物役 | エージェント `character-actor`(登場人物ごと) | 語り部の要求に、その人物の一手を返す |

作者が書く → 語り部が場面を組む → 人物役が動く → 語り部が本文に書き足す、を手番の着地まで繰り返し、一巡したら作者に番を返す。
番の受け渡しはチャットでする。語り部が一巡を終えて返答を終えると作者の番になり、作者の次の発言で語り部の番に戻る。
手番の行は db に置かず、手番のファイル(スキル `episode` の「手番を回す(セミオート)」)に置く。本文は一手ごとに db の話の本文(`main_text`)へ書き足すので、アプリの話の画面で伸びていくのを見られる。

- 作者の書いた中身(起きたこと・人物の言動・台詞の言うこと)は正。語り部は中身を変えない・消さない
- 作者の文がプロットのような書き方(箇条・あらすじ・「〜する」と段取りだけを並べた文)なら、語り部がその箇所を本文の文に起こしてから本文に入れる(下の「作者の書き方を起こし直す」)。それ以外の作者の文はそのまま本文の終わりに入れる
- 作者の書いた人物の言動・内心は、その人物が既にしたこととして扱う。人物役に、した・言ったことを言い直させない
- 人物が場面でどう動くかは人物役が決める。語り部は人物役の一手を書き換えない(言い回しを本文の文体に起こすだけ)
- 端役(屋台の主・通行人など)と群衆は人物役を起こさず、語り部が語りと本文に書く。名前を付けず、役割か見た目で書く(スキル `episode` の「登場人物・場所」)

## コマンド

スキル `episode` の「語り部の決まり」の表(`stage`・`appearance`・`add`・`add-ideas`・`moves`・`read`・`clear`)に加えて、次を使う。いずれも `.venv/bin/python -m tool.episode_session <コマンド>`。

| すること | コマンド |
| --- | --- |
| 今の本文の全文を読む | `text --episode <id>` |
| 本文の終わりに書き足す | 書き足す文を Write でスクラッチパッドのファイルに書き、`append --episode <id> --file <ファイル>`。空行を置くなら文の頭に空行を書く |
| 本文の一か所を置き換える | `{"old": <置き換える文>, "new": <置き換えた文>}` を Write でスクラッチパッドのファイルに書き、`replace --episode <id> --edit <ファイル>`。`old` は本文にちょうど一度だけ出る長さで切る |

## 1. 整える

1. **登場人物・場所・関係を整える**: スキル `episode` の「セッションの前に整える」の 1〜6。プロットか登場人物のどちらかが要る(どちらも無ければ始めず尋ねる)。すでに結んである話でも飛ばさない
2. **語り部の材料を読む**: `stage --episode <id>` で場面の材料(プロット・場所・登場人物の表層・知り合いの組)を読み、登場人物と知り合いの組を手番のファイルに写す。本文を書き足すので、本文の材料(スキル `episode` の手順 7 の `ReadEpisodeBrief`)も読み、スクラッチパッドのファイルに書き出しておく(書き方・文体の見本・視点・前の話はここから取る。語りと要求も、本文と同じくこの「書き方」で書く。読み直すと要約の確かめが走り直すので、セッションの間はこのファイルを使う)
3. **今の本文を読む**: `text --episode <id>`。本文があれば、作者はその続きから書く

## 2. 始める

1. **前の行を見る**: `read --episode <id>` が空でなければ、ユーザに「消して始めるか」を尋ねる。消すなら `clear --episode <id>`(前の行が残ると、前の場面の語りと一手が人物役に届く)
2. **人物役を起こす**: 台詞・行動のある登場人物ごとに、エージェント `character-actor` を一つ裏で(`run_in_background`)起こす。最初のメッセージには話の id・人物の id だけを書く。人物役は起きたときに `knowledge` を読むので、1 を整え終えてから起こす
3. **作者に番を渡す**: 時刻・場所・登場人物(人物役を起こした人物)・整えたこと(「セッションの前に整える」の 7)を短く書き、次を一行ずつ添えて返答を終える
   - 作者が次に書くこと。本文が空なら書き始める場面(プロットの最初の場面があればそれ)、本文があれば「続きをどうぞ」
   - このチャットに本文を書けば語り部の番になる。書かずに任せるなら「続けて」、場面や指示だけでもよい
   - 掛け合いのあいだは、アプリの話の画面で本文を直さない(語り部の書き足しと消し合う)
   - 終えるときは「終わり」

## 3. 一巡を回す

### 読む

作者の発言を、次のどれかに分けて読む。どれか決めかねるときだけ、作者に一言で尋ねる。

- 本文: 地の文・台詞で書いた文。作者の書いたことの中身になる
- 場面・出来事: 「隊商が着く」「ノアが先に気づく」のような、起きたことだけを書いた文。作者が書いたことと同じく扱い、本文には語り部が起こした文で入れる(下の「作者の書き方を起こし直す」)
- 進め方の指示(「ノアはもっと怒る方向で」): 本文には入れず、要求と着地点に効かせる
- 続きを任せる(「続けて」など): 今の本文の終わりから、作者の狙いを予測して進める

### 予測する

作者の書いたことから、次の三つを決めてから手番を足す。

1. **起きたこと**: 作者の書いた人物の言動・内心、場面・時刻・場所の移り、新しい出来事。これは事実で、動かさない
2. **作者の狙い**: その文が次に何を呼ぶか(問いかけには返事、物音には振り向き、決めたことには動き出し)。プロットがあれば、いまどの場面のどこにいて、次にどこへ向かうか
3. **一巡の着地点**: 作者の書いたことへの人物の反応と、それが起こす直後の動きまで。作者が決めるべき分かれ目(新しい出来事・人物の登場・場面の切り替え・大きな選択)の手前で止める。手番は二〜六ほどを目安にし、作者の書いていない出来事を足して先へ進めない。作者がプロットのように先の場面まで書いたなら、着地点は作者の書いた所の終わり(そこまでは作者の決めたこと)

- 作者が前の文(語り部の書き足した文を含む)の直しをチャットで頼んだ: `replace` で直す。起きたことが変わったなら、関わる人物の次の `request` に「さっきの〜は〜だった」と伝える。人物役の演じた手番と大きく食い違うなら、スキル `episode` の「やり直す」の 1・4・5 で、その手番から消して起こし直す
- 作者の文に、材料に無い固有の語が出たら `add-ideas` で足す(スキル `episode` の「新しい語を足す」)
- 作者の文に、新しい人物が台詞・行動を持って出たら、`CastEpisode` で登場人物に足し(まるごと置き換わるので今の人物も渡す)、その人物について「セッションの前に整える」の 3・4 を済ませ、`stage` を読み直して手番のファイルに写し、人物役を起こしてから手番を足す

### 作者の文を本文に入れる

手番を足す前に、作者の書いた本文を `append` で本文の終わりに入れる。

- 作者の文は言うことを変えずに入れる。誤字と書き方の決まり(セリフの終わりの「。」など)だけは直してよい
- 作者の文が途中で切れていれば(セリフの前で止まっているなど)、そのまま入れ、語り部の書き足しをその続きから始める

### 手番を回す

スキル `episode` の「語り部の決まり」「手番の要求を足す」のとおり、手番の JSON をファイルに書いて `add --episode <id> --turns <ファイル>` で足し、人物役に番を送る(同時に動く組は一度に)。一手は本文に起こすので、「終わった」に添えられた行動・セリフでなく、`moves` で内心まで読む。人物役は手番のファイルを見張らない。このスキルで違うのは次だけ。

- 作者の書いた人物の言動は、その場の人物みなに見える・聞こえるなら語り(`narration`)に三人称で書く(本人も `witness_ids` に入れる。本人には自分のしたこととして届く)
- 作者の書いた人物の内心は、その人物の `request` にだけ書く(「あなたは〜と思った」)。ほかの人物には届けない
- 作者の書いた場面・端役の動き・時間の移り(`time` を新しい時刻にする)は語りに書く
- 作者が台詞まで決めて書いたやり取りは、語りに三人称で順に書いて渡し、言った本人の `request` に「語りにある、あなたの言葉はもう言ったこと」と添える。人物役には、そのあいだの仕草・胸のうちと、やり取りを受けた反応だけを求める
- 作者の書いた台詞・出来事が、人物役の演じた手番と食い違えば(作者が台詞を書き換えたなど)、関わる人物の次の `request` に「さっきの〜は〜だった」と伝える
- 着地点までの手番を回したら、返った一手を読んで次を足すことを繰り返す。途中でユーザに見せたり尋ねたりしない

### 本文に書き足す

人物役から「終わった」が返って一手を読むたびに、その分を本文に起こして `append` で書き足す(アプリの話の画面では、本文がそのつど伸びていく)。

- スキル `episode` の「本文に起こす」「書くとき」と、1-2 で書き出した材料の「書き方」に沿う。作者の文の文体・視点・人称・語の選び方に合わせ、作者の文の直後から続く文にする
- 作者がもう書いた言動を、言い直して繰り返さない
- 人物の狙いは、作者の書いた内心と `moves` の内心・狙いから取る。ほかの人物のセリフが狙いを取り違えて言った所は、言った人物の受け取り方として書き、動いた人物の心の声・後悔・詫びに移さない(スキル `episode` の「本文に起こす」)。作者に渡す返答に、取り違えのあった所を一行添える
- 視点の決まった話では、視点人物以外の内心は書かない(行動・セリフと、視点人物から見えることだけ)
- 一度に書き足すのは、返った一手の分だけ。着地点より先を書かない

### 作者の書き方を起こし直す

作者の文がプロットのような書き方(場面・出来事だけを書いた文)なら、その中身を、一巡の手番の一手と合わせて本文の文に起こしてから `append` で入れる(作者の文をそのまま本文に入れない)。

- 作者の書いた台詞は、言うことを変えずに入れる
- 作者が、語り部の起こした箇所をチャットで書き直した・元に戻したら、作者の版を `replace` で入れて正とし、もう一度起こし直さない
- チャットには、起こした箇所を一行書く

### 作者に渡す

着地点まで書き足したら、返答を終えて作者に番を返す。

- 返答には、一巡で起きたことを一〜三行と、足した手番の数・プロットから外れた所(人物役が要求の行動を断ったなら、その理由)と、人物の決めたことと食い違う状況を起こした所(あれば。起こし方は書き方の語り部の範囲の「プロットを状況として起こす」)、作者が次に決めること・書くこと(「隊商は丘の上で止まった。だれが先に降りるか」)を一文で書く
- 書き足した本文は貼らない(アプリの話の画面にある。作者に頼まれたら `text` で読んで貼る)

### 語り部の番に作者が口を挟んだら

語り部の番のあいだにユーザがチャットで場面・指示を出したら、手番は止めず、まだ足していない手番と着地点に効かせる(本文なら、書き足しの区切りで作者の文として入れる)。「まて」「ストップ」なら、それ以上手番を足さず、書き足し終えた所で作者に番を返す。

## 4. 終える

ユーザが終わりを告げたら(「終わり」「ここまで」など)、手番を終えて本文を反映し、手番のファイルを消す。

1. **手番を終える**: 人物役にはもう番を送らない
2. **プロットが空なら書く**: セッションの行と本文から、`ReadWritingStyle` で読んだプロットの範囲の書き方でプロットを書き、`CommitEpisode` に `id`・`plot_text` を渡して入れる
3. **本文を反映する**: スキル `episode` の「ユーザが書いた本文を反映する」の 2〜7 のとおり。本文は作者と語り部が書いたままにし、ここでは直さない。本文の材料(`ReadEpisodeBrief`)は手番のファイルの行も語の元にするので、手番のファイルを消す前に読む
   - 「反映はあとで」と言われたら 1・2 までにし、反映は「ep<id> 書いた」であることと、手番のファイルはセッションが終われば消えるので、あとの反映は本文から読むことを一行ずつ添えて終える
   - 本文を通して整えたいと言われたら、スキル `revise-episode` に移る
4. **手番のファイルを消す**: 報告に使う手番の行の数を `read` で数えてから、`clear --episode <id>`。反映をあとにするときも、`revise-episode` に移るときも消す(「ep<id> 書いた」は、セッションの行が無ければ本文から読む)

## 報告する

スキル `episode` の「報告する」のとおり。手番の数は、作者の番の数(作者の発言を受けて回した一巡の数)と、足した手番の行の数を書く。
