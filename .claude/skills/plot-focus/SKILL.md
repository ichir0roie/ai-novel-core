---
name: plot-focus
description: 一つの話(episode)のプロットだけに集中して、ユーザが書きなぐるメモを受けるモード(プロット集中モード)。メモを切り分けて、この話のプロット(`plot_text`)を書き直し、人物どうしの関係・人物の来歴・設定(アイデア)を db に反映する。先の話のことは後の話の枠・人物の筋書き・作品の筋書きに置いて、話を目の前の話へ戻す。本文は書かない。「ep61 plot」(61 は話の id)、「プロットに集中したい」「プロットを書きなぐるから整理して」「本文は書かずにプロットだけ詰めたい」などの依頼で使う。
---

`CLAUDE.md` のルールに従う。入口・呼び方はスキル `episode` の「入口」のとおり(手元は `.claude/docs/db.md`、web のセッションは `.claude/docs/web-db.md`)。
「ep<話id> plot」がこのスキルを始める合図。

- 目の前の話は一つ(対象の話)。このモードのあいだ、話を対象の話から動かさない。ユーザのメモが先の話へ流れたら、置き場所に置いたことを一行で返し、対象の話の問いへ戻す
- 本文(`main_text`)は書かない・直さない。語り部・人物役も起こさない。本文に進むのは、ユーザがこのモードを終えて「ep<話id>」「ep<話id> in」を頼んだときだけ
- プロットを書くのはユーザ。Claude はメモを `ai/instructions/plot.py` の `PLOT_FORMAT_INSTRUCTION` の形に整えて入れるだけにする。メモに無い出来事・人物の動きを足さない。整えるときに足した言葉は、場面のつなぎ(場所・出る人の書き起こし)までにする
- メモを読んで反映するのに、ユーザの確かめは待たない(書きなぐりを止めないため)。反映したものは毎回の返答に並べ、違えばユーザが次のメモで直す。尋ねるのは、メモが今のプロット・前の話と食い違って、どちらを取るか決められないときだけ
- 一回の返答で問いは一つまで。問うのは対象の話のことだけにする

## 入口

スキル `episode` の「入口」の表に加えて、次を使う。

| すること | 入口・呼び方 |
| --- | --- |
| 関係を読む | `character.list_character_relations.ListCharacterRelations` `{'character_id': …}` |
| 関係を足す | `character.commit_character_relation.CommitCharacterRelation` `{'relation': {…}}` |
| 関係を直す・来歴を足す | `character.update_character_relation.UpdateCharacterRelation` `{'relation': {'id': …, …}}`(`histories` はまるごと置き換わる) |
| 人物の筋書き(`plot`)を直す | `character.update_character.UpdateCharacter` `{'character': {'id': …, 'plot': …}}` |
| 作品の筋書き(`text`)を直す | `story.update_story.UpdateStory` `{'story': {'id': …, 'text': …}}` |
| 話のプロットだけを入れる(AI を回さない) | 下の「プロットを入れる」 |

### プロットを入れる

プロットは手番ごとに入れ直すので、`CommitEpisode` の AI の段(ミームの抜き出し・要約)を回さず、GUI で直したときと同じく確定の db の段だけで入れる(名前だけ出る人物の拾い直しはこの段で走る。後回しの AI はスキル `run-ai-tasks` で回る)。プロットはスクラッチパッドのファイルに置いて読む。`synced` は話の今の値をそのまま渡す(渡さないと false になる)。

- web のセッション: `curl -sS -X PATCH -H "$h" -H 'content-type: application/json' --data-binary @<scratchpad>/<名>.json "$api/api/tables/episode/records/<話id>"`(本文は `{"plot_text": …, "synced": …}`。`jq -n --rawfile p <プロットのファイル> --argjson s <synced> '{plot_text: $p, synced: $s}'` で組む)
- 手元:

```
.venv/bin/python -c "
from pathlib import Path
from db.schema import get_env_session
from gui.api import records, tables
with get_env_session() as s, s.begin():
    records.update_record(s, tables.spec_of('episode'), <話id>,
                          {'plot_text': Path('<scratchpad>/<名>.txt').read_text(encoding='utf-8'), 'synced': <synced>})
"
```

## 1. 始める

1. **話の行を読む**: 対象の話の題・時刻(`start`)・作品・プロット・字数(`letters`)・`synced` を読む
   - 話の id が無ければ、どの話かを尋ねる。新しい話なら、スキル `episode` の手順 1 で枠を足してから始める
   - 本文があれば(`letters` が 0 でない)、プロットを変えても本文は変わらないことを一行添える(本文を合わせるのはスキル `revise-episode`)
   - 時刻が空なら、前後の話から決めて先に入れる(スキル `episode` の手順 1)
2. **材料を読む**: `ReadEpisodeCasting(episode_id)`(AI を回すので web では `run_in_background`。出力はスクラッチパッドへ書き出して Read する)で、登場人物・名前だけ出る人物と、それぞれの関わった話を読む(読み方はスキル `episode` の手順 2)。登場人物ごとに関係を読む(`ListCharacterRelations`)
3. **置き場所を読む**: 作品の話の並び(`ReadEpisodes` `{'story_id': …, 'count': 500, 'text': False}`)から、対象の話より後の枠(題・時刻・プロットの有無)を控える。作品の筋書き(`story` の `text`)も読む。どちらも返答には出さない(先へ目を向けさせないため)
4. **ユーザに返す**: 題・時刻・場所・登場人物と、今のプロット(全文。300〜500 字なので貼ってよい)、その話の前の話のあらすじを二三行で返し、メモを待つ。後の枠の一覧は出さない

## 2. メモを受ける(ユーザのメッセージごと)

ユーザのメッセージ一つを、書きなぐったメモとして受け、次を繰り返す。

1. **切り分ける**: メモを、次のどれに当たるかで一片ずつ分ける。一片が二つに当たれば、両方に反映する

   | メモの中身 | 反映する先 |
   | --- | --- |
   | 対象の話で起きること・場面の順・誰がどこで何をするか・狙い | 対象の話のプロット(下の 2) |
   | 対象の話に出る(台詞・行動のある)人物・舞台が変わる | `CastEpisode`(スキル `episode` の「登場人物・場所」。登場人物はまるごと置き換わるので今の人物も渡す)。db にいない人物・場所は作る |
   | 人物どうしの間柄・知り合ったいきさつ・間柄の変化 | 関係(下の 3) |
   | 人物の身の上・過去・立場・秘密 | 人物の来歴(下の 4) |
   | 世界の固有の語(獣・道具・制度・呼び名など)とその説明 | 設定(下の 5) |
   | 対象の話より後のこと | 置き場所(下の 6) |
   | 対象の話より前の話と食い違うこと | 反映せず、食い違う話(id と題)と箇所を一行で伝えて、どちらを取るか尋ねる |

2. **プロットを書き直す**: 今のプロットにメモを織り込み、`## 場面` / `## 狙い` の形に書き直す
   - メモの順でなく話の中の順に並べ直す。場面を分ける・まとめる・入れ替えるのはよい
   - メモで消した・上書きした場面は残さない。ユーザが「保留」「迷っている」と書いたものは、`## 迷い` の節に `- <メモ>` で置く(プロットの形に無い節。本文を書く Claude は迷いを筋に使わない)
   - 字数の目安(300〜500 字)を越えても、メモを削って縮めない。越えたら、どの場面が膨らんでいるかを返答で一行伝える
   - 書いたら「プロットを入れる」で入れる
3. **関係を反映する**: `ListCharacterRelations` で今の関係を読んでから直す
   - 無い組は `CommitCharacterRelation` で足す(`start` は知り合った時刻。分からなければ対象の話の時刻)
   - ある組は `UpdateCharacterRelation` で直す。`text` は時期を限らない芯だけ、起きたこと・変わったことは起きた年の `histories` の行に足す(今の行もまるごと渡す。`data_access_logic/readme.md` の「関係の芯と来歴」)。間柄そのものが変わるなら、`end` で区切った新しい関係の行にする
   - 対象の話の時刻より後に起きることは、関係にも来歴にも書かず、6 の置き場所へ回す
4. **人物の来歴を反映する**: 時刻を渡さない `ReadCharacter(character_id)` で今の行をすべて読み、その年の行に書き足す(無ければ年の行を足す)。`UpdateCharacter` で配列ごと渡す
   - 秘密は `knowers` を本人だけ(渡さない)にする。知る相手がメモにあればその人物を入れる
   - 主要人物(`main_character` が true)でも、ユーザがメモに書いたことは反映してよい(作者が書いたものなので)。すでにある説明は書き換えず足すだけにし、食い違えば尋ねる
   - 年の決まらない構想は `start` を空にした行に書く
5. **設定を反映する**: 語ごとに `SearchIdeas` で既にあるかを引く。無ければ `AddIdeas`(`episode_id` は対象の話)で足し、あれば説明が食い違うときだけ `UpdateIdea` で直す(食い違いが大きければ尋ねる)。人名・場所の名前は足さない
6. **先のことを置く**: 対象の話より後のことは、詰めずにそのまま置く(膨らませない・問い返さない)
   - 後の枠のどれかの話だと読めれば、その枠のプロットの末尾の `## 先のメモ` の節に `- <メモ>(ep<対象の話id> のときのメモ)` で足す(節が無ければ空行を挟んで見出しから足す。入れ方は「プロットを入れる」)
   - 一人の人物の行く末なら、その人物の筋書き(`plot`)の末尾に足す(`UpdateCharacter` の `plot`。今の値を読んでから足す)
   - どちらでもなければ、作品の筋書き(`story` の `text`)の末尾の `## 先のメモ` の節に足す(`UpdateStory`)
   - 話の枠は新しく作らない(スキル `episode` の「作品の筋の検討」と同じ)
7. **返す**: 次の形で短く返し、次のメモを待つ。本文の下書き・台詞の例は書かない

   ```
   ## プロット(ep<話id>)
   <書き直したプロットの全文>

   ## 反映
   - 関係: <人物>—<人物> <足した/直した中身>
   - 来歴: <人物> <年> <足した中身>
   - 設定: <語> <足した/直した>
   - 登場人物・場所: <変えた中身>

   ## 置いた
   - <メモの頭> → <置き場所(ep<id> / <人物>の筋書き / 作品の筋書き)>

   <対象の話についての問い(あれば一つ)>
   ```

   - 何も無い節は省く。「置いた」は一片につき一行で、置いた中身を繰り返さない

## 3. 終える

ユーザが終わりを告げたら(「ここまで」「プロット終わり」など)、次を返して終える。

- 最後のプロットの全文と、このモードで反映した関係・来歴・設定・登場人物・場所と、置いたメモの一覧(置き場所ごと)
- `## 迷い` の節が残っていれば、そのことを一行で添える
- 本文に進むなら「ep<話id>」(自動)か「ep<話id> in」(語り部をユーザが務める)を、と一行添える。自分から本文に進まない
