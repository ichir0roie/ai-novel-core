description: ユーザが話(episode)の本文を GUI で書くあいだ、先に登場人物・場所・関係を整えてから、語り部と登場人物を裏で起こし、保存(Ctrl+S)のたびの本文の差分に反応(感想・同意・反対・修正案)を返させる。反応は GUI の本文への反応の画面(`/episode_comment?episode=<id>`)の左に時刻順に並ぶ。このセッションの Claude は本文を書かない・直さない。「ep61 com」(61 は話の id)、「書きながら人物に意見を言わせたい」「本文に反応して」などの依頼で使う。
---

入口・呼び方は、スキル `episode` の「入口」のとおり。
「ep<話id> com」がこのスキルを始める合図。本文はユーザが書く。このセッションの Claude は、語り部役と人物役を起こして見守るだけにし、本文を書かない・直さない。

## 1. 整える

役を起こす前に、スキル `episode` の「セッションの前に整える」の 1〜4(5 の設定と照らすのは任意)で、登場人物・場所・関係を整える。プロットか登場人物のどちらかが要る(どちらも無ければ始めず尋ねる)。すでに結んである話でも飛ばさない。役は、ここで結んだ登場人物と、整えた関係・知る相手から自分のデータを読む。

## 2. 材料を読む

1. `episode.read_episode_brief.ReadEpisodeBrief` で話の材料を読み、`.cache/episode_comment/<話id>-brief.json` に JSON のまま書く(語り部役はこのファイルを読む)
2. 材料の `この話` の `登場人物` から、人物役を起こす人物を決める(名前だけ出る人物は起こさない)
3. `.venv/bin/python -m tool.episode_comment latest --episode <id>` で、一番新しい差分の id(`diff_id`)を読む。役はこれより後の差分だけに反応する(前のセッションの差分・終わりの合図に反応しない)

## 3. 役を起こす

1. エージェント `narrator-commenter` を一つ裏で(`run_in_background`)起こす。最初のメッセージには、話の id・待ち始める差分の id(2-3 の `diff_id`)・材料のファイルのパスだけを書く
2. 登場人物ごとに、エージェント `character-commenter` を一つ裏で起こす。最初のメッセージには、話の id・人物の id・待ち始める差分の id だけを書く
3. ユーザに返す: 整えたこと(「セッションの前に整える」の 6)・起こした役(語り部と人物の名前)と、画面の場所(`/episode_comment?episode=<id>`。話の画面の Comment ボタンからも開ける)、Ctrl+S(か Save)で保存するたびに反応が届くこと、書き終えたら画面の Close か「終わり」で止まることを短く書いて待つ

## 4. 見守る

- 役が「終わった」と返して止まったのに、まだ終わりの合図を足していなければ、`latest` で読み直した `diff_id` を待ち始める差分の id にして、同じ役をもう一度起こす
- ユーザがチャットで反応について尋ねたら、答えてよい。本文は直さない
- 登場人物が増えたら、`CastEpisode` で足し(まるごと置き換わるので今の人物も渡す)、その人物について「セッションの前に整える」の 3・4(関係・知る相手)を済ませてから、その人物の `character-commenter` を足して起こす
- ユーザがプロットを書き換えたと言ったら、役をすべて `TaskStop` で止め、1 からやり直して起こし直す(役は起きたときに自分のデータを読むので、起きたままでは整え直した関係が届かない)

## 5. 終える

画面の Close で、終わりの合図が足され、役はそれを読んで止まる。ユーザがチャットで終わりを告げたら(「終わり」「ここまで」など)、`.venv/bin/python -m tool.episode_comment close --episode <id>` で合図を足す。

1. 止まった知らせが来ない役は `TaskStop` で止める
2. 届いた反応の数を役ごとに短く報告し、書いた本文を世界に反映するのは「ep<id> 書いた」(画面の Finish ↗ でも同じ。スキル `episode` の「ユーザが書いた本文を反映する」)であることを一行添えて終える
