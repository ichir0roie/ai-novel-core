name: auto-revision
description: 本文のある話を、直した時刻(`episode.updated_at`)の古い順に一話ずつ推敲し、その話のプロット・本文と、関わる行(人物・関係・スキル・場所・設定・出来事・本文の無い先の話のプロット)を整え、足りない行を足す。呼ばれたセッションの中で、ユーザに尋ねず認めも待たずに回し続け、Claude の 5 時間ごとの使用量(`five_hour` の使用率)が切れる前に止める。「自動推敲」「推敲を回し続けて」などの依頼で使う。直す指示のある一話の推敲はスキル `revise-episode`。
---

「自動推敲」が始める合図。止めるまでユーザに尋ねず、認めも待たずに回す。

- db の読み書きは自分の場所の決まり(手元は `.claude/docs/db.md`、web のセッションは `.claude/docs/web-db.md`)で行う。下の例は web のセッションの呼び方
- コードは変えない。作品の中身はリポジトリに置かない
- 作品の大筋(誰が何をしてどうなるか)は変えない。変えないと解けない食い違いは直さずに報告に挙げる
- 行は消さない(話・人物・場所・設定・出来事・関係)。人物・関係・場所の来歴の今の行は書き換えず、足す。直してよいのは、推敲する話の時刻に足してある来歴の行(スキル `revise-episode` の 6)と、推敲の記録の行(同じく 7)と、下の 3 で挙げた行だけ
- 推敲する話のほかで本文のある話は、本文・プロットに触らない(直すと `updated_at` が新しくなり、その話の番が後ろへ回る)。食い違いは報告に挙げ、その話の番に直す
- 途中でユーザが止めたら、その話の直せた所までで止め、下の「終える」のまとめを返す

## 使用量を読む

止めどころは、このセッションの記録に出る使用率で決める。

1. `mcp__claude-code-remote__get_session` を `session_id` を省いて呼び、このセッションの id(`ccr.id`)を得る(始めに一度)
2. `mcp__claude-code-remote__list_events` に `session_id`・`kinds: ["rate_limit_event"]`・`limit: 100` を渡し、返った `data` の最後(一番新しい)の `rate_limit_event.internal_anthropic_catchall.rate_limit_info` を読む。`data` が空なら `before_id` に `first_id` を渡してさかのぼる
   - `unifiedWindows.five_hour.utilization`: 5 時間ごとの使用率(0〜1)。`resetsAt` はその区切り(UNIX 秒)
   - `unifiedWindows.seven_day.utilization`・`resetsAt`: 週の使用率と区切り
   - `isUsingOverage`: 上限を越えて追加の料金で回っているか
3. 読めなかったら(ツールが無い・見出しが無い・使用率が無い)、推敲を始めずに止め、読めなかったことを報告する(当て推量で回し続けない)

## 流れ

始めに、スクラッチパッドに `auto-revision/progress.md` を作り、始めの使用率(`five_hour` の `utilization` と `resetsAt`、`seven_day` の `utilization`)を書く。一話を終えるたびに、話の id・題・終えたときの 5 時間の使用率を一行足す。会話が要約されても、ここから続きを読む。

1. **止めるか決める**: 「使用量を読む」で使用率を読み、次のどれかに当たれば下の「終える」へ
   - `five_hour.utilization` が 0.95 以上
   - `five_hour.utilization` に、直前の一話で増えた分(二話目から。`progress.md` の差)を足すと 1 を越える(次の一話の途中で切れる)
   - `five_hour.resetsAt` が始めに書いた値と違う(区切りが明けた。次の 5 時間は使わない)
   - `seven_day.utilization` が 0.95 以上
   - `isUsingOverage` が true
   - 下の 2 で推敲する話が残っていない
2. **話を選ぶ**: 本文のある話を、`updated_at` の古い順に引き、このセッションでまだ推敲していない先頭の一話を取る

   ```
   api="${NOVEL_API_URL%/}"; h="x-novel-api-key: $NOVEL_API_KEY"
   curl -sS -H "$h" "$api/api/tables/episode/records?sort=updated_at&order=asc&limit=500" -o <scratchpad>/auto-revision/queue.json
   jq -c '[.items[] | select(.letters > 0) | {id, title, letters}][:5]' <scratchpad>/auto-revision/queue.json
   ```

   - 500 件で本文のある話が尽きたら `offset` を足して次を引く
   - 推敲を終えた話は `updated_at` が新しくなって後ろへ回る。次に呼ばれたときは、前の回の続きから始まる
3. **推敲する**: 選んだ話を、スキル `revise-episode` の流れ 1〜7 で直す(7 の推敲の記録には、ほかの話にも当たる直しだけを入れ、例に `自動推敲` と添える)。ただし直す指示はユーザから受けず、自分で決める
   - 材料: `ReadEpisodeBrief` に加え、前後の話(`ReadEpisodes` の並びで前後一話ずつ。前は本文、後は本文が無ければプロット)・登場人物ごとの時刻を渡さない `ReadCharacter`・関係(`ListCharacterRelations`)・場所(表の API の `location`)・出来事(`ReadEvents` の `character_id` / `location_id`)を読む
   - 直す指示を決める: 次の観点で、この話と関わる行の食い違い・足りない所を挙げ、それを直す指示を自分で書く(スキル `story-director` の 2 の 4「矛盾を確かめる」の観点も使う)
     - 本文と、この話の書き方(材料の「書き方」)・プロット・前後の話・人物の芯と来歴・関係・場所・設定との食い違い
     - 人物の狙いの取り違え: プロットに無い動機(見捨てる・裏切る・逃げる)や、それへの後悔・詫びを人物に負わせた所。ほかの人物のセリフでの推し量りが、本人の心の声・地の文の事実・来歴になった所(`revise-episode` の 2)
     - 初登場の人物の外見・性格の描写、場面の運び、会話と描写の配分の薄い所
     - 本文に出るのに db に無い人物・場所・語、話に結んでいない登場人物・場所
   - 本文とプロット: `revise-episode` の 2〜5 で書き直して `ReviseEpisode` で確定する。プロットの「## 推敲」の節には `- 自動推敲 <年/月/日(日本時間の今日)>: <決めた指示の要点>` を一行足す。プロットが本文と食い違っていれば、プロットの本体も本文に合わせて書き直す
   - 関わる行: 確定のあと、`revise-episode` の 6 と、スキル `episode` の手順 10 で人物の来歴・装い・スキルを整える。関係・場所・設定・出来事の食い違いと足りない行は、スキル `story-director` の「入口」の表と 3 の 2 の行ごとの決まりで直す・足す(提案して認めを待つ所は飛ばす)。どの行も、書く前にその文の範囲の書き方を `ReadWritingStyle` で読む
   - 先の話: この話の後にある本文の無い話のプロットが、直した本文・行と食い違えば、`story-director` の「話の行を書く」でそのプロットを直す。本文のある話は直さず報告に挙げる
   - 一話の推敲が途中で失敗したら(入口のエラーなど)、その話は直せた所までにして、何が残ったかを `progress.md` に書き、次の話へ進む
4. `progress.md` に一行足し、話の id・題と決めた指示の要点を一行だけ返答に書いて(長い報告は「終える」でまとめる)、1 へ戻る

## 終える

`progress.md` から次をまとめて返す(本文・プロット・材料のような長いものは貼らない)。

- 止めた理由と、始めと終わりの 5 時間・週の使用率
- 推敲した話ごとに: 話の id・題・字数の変わり方・決めた指示の要点・直した・足した行(表ごとに)
- 直さずに残した食い違い(大筋に触れるもの・本文のある別の話のもの)と、途中で失敗した話
