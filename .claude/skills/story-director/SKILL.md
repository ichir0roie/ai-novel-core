---
name: story-director
description: 作品(story)全体を統括するモード。呼ばれたら作品の筋書き・話の並び・人物・関係を読み込んで整理する。ユーザが指示を出すたびに、関わる話を探して矛盾を確かめ、整合を保つための編集を提案し、ユーザが認めたら影響の及ぶ行(作品・話の枠とプロット・人物・関係・スキル・場所・設定・出来事・覚え書き)を直す。話の本文(`main_text`)だけは書かない・直さない。「st3」(3 は作品の id)、「作品全体を詰めたい」「全体の整合を見ながら筋を直したい」「本文は書かずに筋と設定を整えたい」などの依頼で使う。
---

`CLAUDE.md` のルールに従う。入口・呼び方はスキル `episode` の「入口」と `data_access_logic/readme.md` の「依頼内容 → 呼ぶコード」の表のとおり(手元は `.claude/docs/db.md`、web のセッションは `.claude/docs/web-db.md`)。
「st<作品id>」がこのスキルを始める合図。

- 扱うのは対象の作品(子の章・外伝を含む)に関わるすべての行。指示がどの話・どの人物のことでも、その行と、そこから影響の及ぶ行を直す。先の話のことも、その話の枠に入れてよい(枠が無ければ足す)
- **話の本文(`main_text`)は書かない・直さない**。本文を書く・確定する道(`CommitEpisode` に `main_text` を渡す・スキル `episode` の手順 6〜9・`revise-episode`)を通らない。語り部・人物役も起こさない。本文に進むのは、ユーザがこのモードを終えて「ep<話id>」「ep<話id> in」を頼んだときだけ
- 本文は正として読む。指示が本文と食い違えば、本文以外の行を本文に合わせるか、本文を後で直す話として挙げるかを提案に書く(本文を直すかはユーザが決める。直すのはスキル `revise-episode`)
- **行を直すのは、提案をユーザが認めてから**。指示を受けたら、まず調べて提案だけを返す(下の 2)。認められた分だけ直す(下の 3)
- 筋を決めるのはユーザ。整合のために足す・直すものは提案に挙げ、指示に無い大きな出来事・人物の動きを黙って足さない

## 入口

すべての行を `data_access_logic/readme.md` の表の入口で読み書きする。よく使うものと、このモードでの決まり:

| 行 | 入口 | 決まり |
| --- | --- | --- |
| 作品の筋書き | `story.update_story.UpdateStory` `{'story': {'id': …, 'text': …}}`。子の章・外伝を足すのは `story.commit_story.CommitStory` | 作品をまたぐ大筋・まだ話の枠にしない構想はここに書く |
| 話の枠を足す・題・時刻・プロット・場所・視点を直す | 下の「話の行を書く」 | `main_text` を渡さない |
| 話の時刻・作品をまとめて直す | `episode.update_episodes.UpdateEpisodes` | `synced` は今の値を渡す |
| 話の登場人物・場所・視点 | `episode.cast_episode.CastEpisode` | 登場人物はまるごと置き換わる |
| 人物 | `CommitCharacter` / `UpdateCharacter`(芯 `text`・来歴 `histories`・筋書き `plot`・ミーム・行動原理・パラメータ)・`MoveCharacters` | 来歴・パラメータの配列はまるごと置き換わるので、今の行を時刻を渡さない `ReadCharacter` で読んでから足す |
| 関係 | `ListCharacterRelations` → `CommitCharacterRelation` / `UpdateCharacterRelation` | 下の 3 の「関係」 |
| スキル | `CommitCharacterSkill` / `UpdateCharacterSkill` | `text` は本質、身についた・伸びたなどは年の `histories` |
| 場所 | `CommitLocation` / `UpdateLocation` | |
| 設定(アイデア) | `SearchIdeas` → `CommitIdea` / `UpdateIdea`(呼び名は `histories`)。話に出た語は `AddIdeas` | 人名・場所の名前は足さない |
| 出来事 | `CommitEvent` / `UpdateEvent` | AI を回す(要約・種)ので web では `run_in_background` |
| 覚え書き | `CommitOracle` / `UpdateOracle` | 作者の考え方・世界の理のメモ。`CommitOracle` は AI を回す(検める・ミーム)ので web では `run_in_background` |
| 書き方の好み | `style_preference` の行(表の API) | 文体の好みを言われたときだけ |

### 話の行を書く

話の枠・プロットは何度も入れ直すので、`CommitEpisode` の AI の段(ミームの抜き出し・要約)を回さず、GUI で足した・直したときと同じく確定の db の段だけで書く(名前だけ出る人物の拾い直しはこの段で走る。後回しの AI はスキル `run-ai-tasks` で回る)。プロットのような長い文字列はスクラッチパッドのファイルに置いて読む。

- 欄: 新しい枠は `story_id`・`start`(`<年/月/日>`)・`plot_text`・あれば `title`。既存の話は変える欄と `synced`(今の値をそのまま。渡さないと false になる)。**`main_text` は渡さない**
- web のセッション: 足すのは `curl -sS -X POST -H "$h" -H 'content-type: application/json' --data-binary @<scratchpad>/<名>.json "$api/api/tables/episode/records"`、直すのは `-X PATCH` で `.../records/<話id>`(本文の JSON は `jq -n --rawfile p <プロットのファイル> --argjson s <synced> '{plot_text: $p, synced: $s}'` のように組む)
- 手元:

```
.venv/bin/python -c "
from pathlib import Path
from db.schema import get_env_session
from gui.api import records, tables
with get_env_session() as s, s.begin():
    records.update_record(s, tables.spec_of('episode'), <話id>,
                          {'plot_text': Path('<scratchpad>/<名>.txt').read_text(encoding='utf-8'), 'synced': <synced>})
"
```

  足すのは `records.create_record(s, tables.spec_of('episode'), {…})`

### 控え

行を直す・消す前に、直す行の今の値(直す欄だけ)を `<scratchpad>/story-director/<表>-<id>-<連番>.json` に控える。ユーザが「戻して」と言ったら、控えから戻す。

### 消す

話・人物・場所・設定・出来事などの行を消すのは、ユーザが指示で消すと言ったときか、提案に挙げて認められたときだけにする。提案には、消す行と巻き込む行を書く。本文のある話は消さない(本文を消すことになるので)。

## 1. 始める(読み込んで整理する)

呼ばれたら、まず作品全体を読み込み、整理した図を作る。この段では行を直さない。

1. **作品を読む**: 対象の作品の名前・筋書き(`text`)すべてと、子の章・外伝(`ListStories` の `parent_story_id`)を読む。作品の id が無ければ、どの作品かを尋ねる
2. **話の並びを読む**: `ReadEpisodes` `{'story_id': …, 'count': 500, 'text': False}`(子の作品のぶんも)で、話ごとの id・題・時刻・字数・`synced` を読む。登場人物・名前だけ出る人物は、web は表の API の `episode` の行(`$api/api/tables/episode/records?story_id=<作品id>&limit=500`)の `character_ids`・`mentioned_character_ids`、手元は `episode_character`(`mentioned` で分かれる)を引く。プロットと概要は `ReadEpisodeTexts` `{'episode_ids': […]}` の `plot_text`・`summary_text` で読む(本文も返るので、出力はスクラッチパッドへ書き出し、本文は読まずに概要で掴む。概要が null の話だけ本文を読む)
3. **人物を読む**: 話の登場人物・名前だけ出る人物を合わせた人物と、`ReadCast` `{'story_id': …}` の顔ぶれを、時刻を渡さない `ReadCharacter` で一人ずつ読む(芯・来歴・筋書き・居場所)
4. **関係を読む**: 3 の人物ごとに `ListCharacterRelations` `{'character_id': …}` で関係(芯・来歴・始まりと終わり)を読む
5. **整理する**: 読んだものを `<scratchpad>/story-director/<作品id>-map.md` にまとめる。指示のたびに読み直す元にし、行を直したらその分を書き換える
   - **年表**: 話を時刻の順に一行ずつ(`ep<id> <時刻> <題> 本文あり/プロットのみ/空 / 出る人物 / 要点一行`)
   - **人物**: 人物ごとに、役どころ一行・出る話の id・芯と筋書きの要点・来歴の節目(年つき)
   - **関係**: 組ごとに、間柄・始まり(時刻)・来歴の節目と、二人が一緒に出る話の id
   - **気になる所**: 読むうちに見つけた食い違い(下の 2 の「矛盾を確かめる」の観点)。ここでは直さない
6. **ユーザに返す**: 作品の筋書きの要点(三行ほど)・年表(一話一行)・主な人物と関係の要点・気になる所を返し、指示を待つ。気になる所を直すかは、ユーザが指示で決める

## 2. 指示を受けたら(調べて提案する)

ユーザのメッセージ一つを指示として受け、次の順で調べて、提案だけを返す。行はまだ直さない。

1. **指示を読み解く**: 指示が変える・決めることを一片ずつに分け、それぞれが触る人物・関係・話・語・時刻を挙げる。指示が曖昧で影響の範囲が決まらなければ、調べる前に一つだけ尋ねる
2. **関わる話を探す**: 整理の図(`<作品id>-map.md`)から、指示の人物・関係が出る話、指示の時刻の前後の話を引く。加えて、指示の語・人名・呼び名を、話の題・プロットに当てて探す(web は `curl -sS -G -H "$h" "$api/api/tables/episode/options" --data-urlencode 'q=<語>'`、手元は `episode` の `plot_text`・`title`・`summary_text` を `like` で引く)。作品の外の話(人物が関わった別の作品の話)も、人物の「関わった話」(`ReadEpisodeCasting` の `関わった話(古い順)`)で引く
3. **関わる行を読む**: 引いた話の概要とプロット、指示に出る人物の来歴・関係、語のアイデア(`SearchIdeas`)、人物・場所の出来事(`ReadEvents` `{'character_id': …}` / `{'location_id': …}`)を読む。概要で筋が掴めない所は本文を読む(本文は読むだけ)
4. **矛盾を確かめる**: 指示を入れたとして、次の観点で食い違いを挙げる
   - 時刻: 出来事・話の順、人物の年齢・生没年、関係の始まり(知り合う前の話で知り合いとして出ていないか)、居場所(その時刻にそこにいられるか)
   - 人物: 芯・来歴・筋書きと、話の中の行い・立場
   - 関係: 間柄と、話の中のやり取り・呼び方
   - 知ること: 秘密を知る相手(来歴の `knowers`)と、話の中でそれを知っている振る舞い
   - 設定: アイデアの説明・呼び名と、プロット・概要の使い方
   - 伏線: 張った話と回収する話の対応、先の話のプロットが前提にしていること
5. **提案を返す**: 直す行を、影響の及ぶ行まで含めて番号付きで挙げる。一つの指示が多くの行に及んでも、整合に要るものはすべて挙げる

   ```
   ## 指示の受け取り
   <指示を一二行で言い直したもの>

   ## 見つかった食い違い
   - <ep<id> <題> / 人物 <名> / 関係 <名>—<名> …>: <何と何が食い違うか>

   ## 提案
   1. ep<id> <題> プロット: <今> → <直したあと>(<理由: どの食い違いを解くか>)
   2. 人物 <名> 来歴 <年>: <足す・直す中身>(<理由>)
   3. 関係 <名>—<名>: <足す・直す中身>(<理由>)
   4. 新しい枠: <時刻> <題>(<理由>)
   …

   ## 本文と合わない話(本文は直さない)
   - ep<id> <題>: <本文のどこが、直したあとの行と合わなくなるか>

   <決めてほしいこと(あれば一つ)>
   ```

   - 何も無い節は省く。食い違いを解く道が二つ以上あれば、提案の中で `1a` / `1b` と並べ、どちらを取るかを「決めてほしいこと」で問う
   - プロットを直す提案は、変わる場面の行だけを書く(全文は貼らない。頼まれたら貼る)
   - 食い違いが無く直す行が一つだけでも、提案として返して認めてもらう

## 3. 認められたら(直す)

ユーザが提案を認めたら(「OK」「全部」「1 と 3 だけ」「2 は〜にして」など)、認められた番号だけを直す。直す指示が付いたら、それを入れて直す(直す中身が大きく変わるなら、提案し直す)。

1. **控える**: 直す行の今の値を控える(上の「控え」)
2. **直す**: 番号の順に、上の「入口」の表の入口で直す。行ごとの書き方:
   - プロット: `ai/instructions/plot.py` の `PLOT_FORMAT_INSTRUCTION` の形(`## 場面` / `## 狙い`)に書き直して、「話の行を書く」で入れる。ユーザが「保留」「迷っている」としたものは `## 迷い` の節に `- <メモ>` で置く(スキル `episode` は、この節が残っていれば書く前に尋ねる)。字数の目安(300〜500 字)を越えても縮めない
   - 人物: 時刻を渡さない `ReadCharacter` で今の行をすべて読み、来歴はその年の行に書き足す(無ければ年の行を足す。年の決まらない構想は `start` を空にした行)。来歴にはその年までのことだけ、先のことはその年の行へ(`data_access_logic/readme.md` の「人物の来歴」)。秘密は `knowers` を本人だけ(渡さない)にし、知る相手が決まっていればその人物を入れる。芯(`text`)は時期を限らない人物像だけ、行く末・作中の役回りは筋書き(`plot`)に書く。二人のあいだで起きたこと(出会い・やり取り・師事・対立・別れ)は関係の来歴に書き、人物の来歴には本人に起きたこと・変わったことだけを書く(秘密は人物の来歴へ)。主要人物も、認められた提案どおりに直す
   - 関係: `text` は時期を限らない芯だけ、起きたこと・変わったことは起きた年の `histories` の行に足す(今の行もまるごと渡す。`data_access_logic/readme.md` の「関係の芯と来歴」)。間柄そのものが変わるなら、`end` で区切った新しい関係の行にする。関係の来歴に書いたことは、人物の来歴に繰り返さない
   - 設定: 無ければ `CommitIdea`(話に出る語なら `AddIdeas`)で足し、あれば `UpdateIdea` で直す。作中の呼び名は `histories` に書く
   - 話の登場人物・場所: `CastEpisode`(登場人物はまるごと置き換わる)。db にいない人物・場所は作る(スキル `episode` の「登場人物・場所」)
3. **読み直して確かめる**: 直した行を読み直し、提案どおりに入ったかを見る。整理の図を書き換える
4. **返す**: 直した行を一行ずつ(`<番号> <行>: 直した`)と、本文と合わなくなった話を返し、次の指示を待つ。入らなかったものがあれば、そのわけを書く

## 4. 終える

ユーザが終わりを告げたら(「ここまで」「終わり」など)、次を返して終える。

- このモードで直した行の一覧(表ごと。足した/直した/消した)
- 本文と合わなくなった話・`## 迷い` の節が残っている話・整理で見つけて手を付けていない「気になる所」の一覧
- 本文に進むなら「ep<話id>」(自動)か「ep<話id> in」(語り部をユーザが務める)を、本文を合わせるなら `revise-episode` を、と一行添える。自分から本文に進まない
