---
name: story-director
description: 作品(story)全体を統括するモード。ユーザが書きなぐるメモを切り分けて、作品の筋書き・話の枠(題・時刻・プロット・登場人物・場所・並び)・人物・関係・スキル・場所・設定(アイデア)・出来事・覚え書きなど、すべての行に反映する。話の本文(`main_text`)だけは書かない・直さない。「st3」(3 は作品の id)、「作品全体を詰めたい」「書きなぐるから全体に反映して」「本文は書かずに筋と設定を整えたい」などの依頼で使う。
---

`CLAUDE.md` のルールに従う。入口・呼び方はスキル `episode` の「入口」と `data_access_logic/readme.md` の「依頼内容 → 呼ぶコード」の表のとおり(手元は `.claude/docs/db.md`、web のセッションは `.claude/docs/web-db.md`)。
「st<作品id>」がこのスキルを始める合図。

- 扱うのは対象の作品(子の章・外伝を含む)に関わるすべての行。メモがどの話・どの人物のことでも、その行へ反映する。先の話のことも、その話の枠に入れてよい(枠が無ければ足す)
- **話の本文(`main_text`)は書かない・直さない**。本文を書く・確定する道(`CommitEpisode` に `main_text` を渡す・スキル `episode` の手順 6〜9・`revise-episode`)を通らない。語り部・人物役も起こさない。本文に進むのは、ユーザがこのモードを終えて「ep<話id>」「ep<話id> in」を頼んだときだけ
- 本文のある話(`letters` が 0 でない)の題・プロット・時刻・登場人物を変えても、本文は変わらない。変えたら、本文とずれた話として返答の「本文とずれた話」に挙げる(合わせるかはユーザが決める。合わせるのはスキル `revise-episode`)
- 筋を書くのはユーザ。メモに無い出来事・人物の動き・設定を足さない。整えるときに足す言葉は、決まった形(プロットの `## 場面` / `## 狙い` など)へのつなぎまでにする
- メモを反映するのに、ユーザの確かめは待たない(書きなぐりを止めないため)。反映したものは毎回の返答に並べ、違えばユーザが次のメモで直す
- 尋ねるのは、メモが今の行・前の話の本文と食い違ってどちらを取るか決められないときと、消すとき(下の「消す」)だけ。一回の返答で問いは一つまで

## 入口

すべての行を `data_access_logic/readme.md` の表の入口で読み書きする。よく使うものと、このモードでの決まり:

| 行 | 入口 | 決まり |
| --- | --- | --- |
| 作品の筋書き | `story.update_story.UpdateStory` `{'story': {'id': …, 'text': …}}`。子の章・外伝を足すのは `story.commit_story.CommitStory` | 作品をまたぐ大筋・まだ話の枠にしない構想はここに書く |
| 話の枠を足す・題・時刻・プロット・場所・視点を直す | 下の「話の行を書く」 | `main_text` を渡さない |
| 話の時刻・作品をまとめて直す | `episode.update_episodes.UpdateEpisodes` | `synced` は今の値を渡す |
| 話の登場人物・場所・視点 | `episode.cast_episode.CastEpisode` | 登場人物はまるごと置き換わる |
| 人物 | `CommitCharacter` / `UpdateCharacter`(芯 `text`・来歴 `histories`・筋書き `plot`・ミーム・行動原理・パラメータ)・`MoveCharacters` | 来歴・パラメータの配列はまるごと置き換わるので、今の行を時刻を渡さない `ReadCharacter` で読んでから足す |
| 関係 | `ListCharacterRelations` → `CommitCharacterRelation` / `UpdateCharacterRelation` | 下の「切り分ける」の 関係 |
| スキル | `CommitCharacterSkill` / `UpdateCharacterSkill` | `text` は本質、身についた・伸びたなどは年の `histories` |
| 場所 | `CommitLocation` / `UpdateLocation` | |
| 設定(アイデア) | `SearchIdeas` → `CommitIdea` / `UpdateIdea`(呼び名は `histories`)。話に出た語は `AddIdeas` | 人名・場所の名前は足さない |
| 出来事 | `CommitEvent` / `UpdateEvent` | AI を回す(要約・種)ので web では `run_in_background` |
| 覚え書き | `CommitOracle` / `UpdateOracle` | 作者の考え方・世界の理のメモ。`CommitOracle` は AI を回す(検める・ミーム)ので web では `run_in_background` |
| 書き方の好み | `style_preference` の行(表の API) | 文体の好みを言われたときだけ |

### 話の行を書く

話の枠・プロットは何度も入れ直すので、`CommitEpisode` の AI の段(ミームの抜き出し・要約)を回さず、GUI で足した・直したときと同じく確定の db の段だけで書く(名前だけ出る人物の拾い直しはこの段で走る。後回しの AI はスキル `run-ai-tasks` で回る)。プロットのような長い文字列はスクラッチパッドのファイルに置いて読む。

- 欄: 新しい枠は `story_id`・`start`(`<年/月/日>`)・`plot_text`・あれば `title`。既存の話は変える欄と `synced`(今の値をそのまま。渡さないと false になる)。**`main_text` は渡さない**
- web のセッション: 足すのは `curl -sS -X POST -H "$h" -H 'content-type: application/json' --data-binary @<scratchpad>/<名>.json "$api/api/tables/episode/records"`、直すのは `-X PATCH` で `.../records/<話id>`(本文の JSON は `jq -n --rawfile p <プロットのファイル> --argjson s <synced> '{plot_text: $p, synced: $s}'` のように組む)
- 手元:

```
.venv/bin/python -c "
from pathlib import Path
from db.schema import get_env_session
from gui.api import records, tables
with get_env_session() as s, s.begin():
    records.update_record(s, tables.spec_of('episode'), <話id>,
                          {'plot_text': Path('<scratchpad>/<名>.txt').read_text(encoding='utf-8'), 'synced': <synced>})
"
```

  足すのは `records.create_record(s, tables.spec_of('episode'), {…})`

### 控え

行を直す・消す前に、直す行の今の値(直す欄だけ)を `<scratchpad>/story-director/<表>-<id>-<連番>.json` に控える。ユーザが「戻して」と言ったら、控えから戻す。

### 消す

話・人物・場所・設定・出来事などの行を消すのは、ユーザがメモで消すと言ったときだけにし、消す前に何を消すか(と巻き込む行)を一行で示して確かめる。本文のある話は消さない(本文を消すことになるので)。

## 1. 始める

1. **作品を読む**: 対象の作品の名前・筋書き(`text`)と、子の章・外伝(`ListStories` の `parent_story_id`)を読む。作品の id が無ければ、どの作品かを尋ねる
2. **話の並びを読む**: `ReadEpisodes` `{'story_id': …, 'count': 500, 'text': False}` で、話ごとの id・題・時刻・字数・プロットの有無・`synced` を控える。本文のある話の中身は概要(`ReadEpisodeTexts` の `summary_text`)で掴む
3. **顔ぶれを読む**: `ReadCast` `{'story_id': …}` で作品の最後の時点の顔ぶれを読む。人物ごとの関係・来歴は、メモに出てきたときに読む(先に全部は読まない)
4. **ユーザに返す**: 作品の筋書きの要点(三行ほど)と、話の並び(一話一行: `ep<id> <時刻> <題>`・本文あり/プロットのみ/空)を返し、メモを待つ

## 2. メモを受ける(ユーザのメッセージごと)

ユーザのメッセージ一つを、書きなぐったメモとして受け、次を繰り返す。

1. **切り分ける**: メモを一片ずつ、どの行のことかで分ける。一片が二つの行に当たれば、両方に反映する

   | メモの中身 | 反映する先 |
   | --- | --- |
   | 作品の大筋・章立て・まだ話にしない構想 | 作品の筋書き(`story` の `text`)。章・外伝を分けるなら子の作品 |
   | ある話で起きること・場面の順・狙い | その話のプロット(下の 2) |
   | 話の順・時刻が動く | 話の時刻(`UpdateEpisodes`)。前後の話と時刻の食い違いが無いか確かめる |
   | まだ枠の無い話 | 枠を足す(時刻・題・プロット)。時刻が決まらなければ前後の話の間に置き、そう返す |
   | 話に出る(台詞・行動のある)人物・舞台 | `CastEpisode`。db にいない人物・場所は作る(スキル `episode` の「登場人物・場所」) |
   | 人物の人物像・身の上・過去・立場・秘密・行く末 | 人物(下の 3) |
   | 人物どうしの間柄・知り合ったいきさつ・間柄の変化 | 関係(下の 4) |
   | 人物の技・能力の身につき方 | スキル |
   | 土地・建物 | 場所 |
   | 世界の固有の語(獣・道具・制度・呼び名など) | 設定(下の 5) |
   | 話の外で起きた・起きる世の動き | 出来事 |
   | 作者としての考え方・世界の理 | 覚え書き(oracle) |
   | 本文のある話の中身と食い違うこと | 反映せず、食い違う話(id と題)と箇所を一行で伝えて、どちらを取るか尋ねる(本文は直さない) |

2. **プロットを書き直す**: 今のプロットにメモを織り込み、`ai/instructions/plot.py` の `PLOT_FORMAT_INSTRUCTION` の形(`## 場面` / `## 狙い`)に書き直して、「話の行を書く」で入れる
   - メモの順でなく話の中の順に並べ直す。場面を分ける・まとめる・入れ替える・ほかの話へ移すのはよい
   - メモで消した・上書きした場面は残さない。ユーザが「保留」「迷っている」と書いたものは、`## 迷い` の節に `- <メモ>` で置く(スキル `episode` は、この節が残っていれば書く前に尋ねる)
   - 字数の目安(300〜500 字)を越えても、メモを削って縮めない。越えたら返答で一行伝える
   - 話をまたぐメモ(「3 話の伏線を 7 話で回収」)は、両方の話のプロットに書く
3. **人物を反映する**
   - 時刻を渡さない `ReadCharacter(character_id)` で今の行をすべて読み、来歴はその年の行に書き足す(無ければ年の行を足す。年の決まらない構想は `start` を空にした行)。`UpdateCharacter` で配列ごと渡す
   - 来歴の行には、その年までのことだけを書く。先のことはその年の行へ(`data_access_logic/readme.md` の「人物の来歴」)。秘密は `knowers` を本人だけ(渡さない)にし、知る相手がメモにあればその人物を入れる
   - 芯(`text`)は時期を限らない人物像だけ。人物の行く末・作中での役回りは筋書き(`plot`)に書く
   - 主要人物(`main_character` が true)もメモどおりに反映する(作者が書いたものなので)。すでにある説明は書き換えず足す。書き換えるのは、メモが「〜に変える」と言ったときだけ
4. **関係を反映する**: `ListCharacterRelations` で今の関係を読んでから直す
   - 無い組は `CommitCharacterRelation` で足す(`start` は知り合った時刻)
   - `text` は時期を限らない芯だけ、起きたこと・変わったことは起きた年の `histories` の行に足す(今の行もまるごと渡す。`data_access_logic/readme.md` の「関係の芯と来歴」)。間柄そのものが変わるなら、`end` で区切った新しい関係の行にする
5. **設定を反映する**: 語ごとに `SearchIdeas` で既にあるかを引く。無ければ `CommitIdea`(話に出る語なら `AddIdeas`)で足し、あれば説明が食い違うときだけ `UpdateIdea` で直す(食い違いが大きければ尋ねる)。作中の呼び名は `histories` に書く
6. **返す**: 次の形で短く返し、次のメモを待つ。本文の下書き・台詞の例は書かない

   ```
   ## 反映
   - 作品: <直した中身>
   - ep<id> <題>: <プロット/時刻/登場人物・場所 の直した中身>(足した枠は「新しい枠」と書く)
   - 人物 <名>: <来歴 <年>/芯/筋書き の足した・直した中身>
   - 関係 <名>—<名>: <足した・直した中身>
   - 設定 <語>: <足した/直した>
   - <場所・スキル・出来事・覚え書き>: …

   ## 本文とずれた話
   - ep<id> <題>: <ずれた所>

   <問い(あれば一つ)>
   ```

   - 何も無い節は省く。プロットの全文は貼らない(ユーザに頼まれた話だけ貼る)

## 3. 終える

ユーザが終わりを告げたら(「ここまで」「終わり」など)、次を返して終える。

- このモードで反映した行の一覧(表ごと。足した/直した/消した)
- 本文とずれた話・`## 迷い` の節が残っている話の一覧
- 本文に進むなら「ep<話id>」(自動)か「ep<話id> in」(語り部をユーザが務める)を、と一行添える。自分から本文に進まない
