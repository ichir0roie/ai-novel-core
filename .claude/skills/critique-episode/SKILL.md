作者が書いたもの(アウトプット)を起点に、疑問・改善の提案・次のインプットを返し、作者が自分で直して書く力を上げるためのスキル。
「ep<話id> crit」(「ep<話id> 講評」も同じ)がこのスキルを始める合図。

- 本文・プロット・世界の行(人物・出来事・設定・関係)には書かない。db に書くのは講評の範囲の行(作者の課題の記録)だけ
- 直した本文を書いて見せない。どう直すかを決めて書くのは作者。技法を見せる例は、一つの提案に一つ、三文までで、作者の場面・人物を使って書き、「例」と分かるように置く
- 作者の書き方(材料の本文の行・推敲の行・作品の指示・話の指示)は作者が選んだ文体として尊重し、それに反する提案はしない。その決まり自体が読者を置いていくと読めたら、提案でなく疑問として挙げる
- 一般的なラノベ・小説の読者の目で読み、なぜ読者にそう効くかを添える。好みの押しつけ(自分ならこう書く)にしない
- 指摘を並べすぎない。直すと一番効くものから、改善の提案は三つまで。残りは「ほかに気づいた所」に一行ずつ
- 本の題・作者名を挙げるのは、確かに在ると言えるものだけ。あやふやなら挙げず、観察の課題(手持ちの本のどこを、何と比べて読むか)にする
- 世界の事実との食い違い(人物の呼び名・設定)はこのスキルの受け持ちでない。目に付いたら「ほかに気づいた所」に一行で添えるだけにする

## 入口

入口と呼び方はスキル `episode` の「入口」のとおり。どれも db だけの入口で、すぐ返る。結果はスクラッチパッドのファイルに書き出して Read で最後の行まで読む。

| すること | 入口の id | 引数 |
| --- | --- | --- |
| 話を読む(本文まで) | `episode.read_episode_texts.ReadEpisodeTexts` | `{'episode_ids': [<話id>]}` |
| 直前の話を読む | `episode.read_episodes.ReadEpisodes` | `{'story_id': …, 'count': 1, 'before': '<この話の start>', 'text': True}` |
| 作者の書き方を読む | `style_preference.read_writing_style.ReadWritingStyle` | `{'writing_style': {'scope': '本文', 'story_id': …, 'episode_id': …}}` |
| 講評の記録を読む | `style_preference.read_writing_style.ReadWritingStyle` | `{'writing_style': {'scope': '講評'}}`(全体の行のあとに講評の行が続く) |
| 講評の記録を作る | `style_preference.commit_style_preference.CommitStylePreference` | `{'style_preference': {'scope': '講評', 'text': …}}` |
| 講評の記録を書き直す | `style_preference.update_style_preference.UpdateStylePreference` | `{'style_preference': {'id': …, 'text': …}}`(行まるごと置き換わる) |

講評の行の id は、スキル `revise-episode` の手順 7 と同じく表の口で `scope=講評` に絞って読む。

## 読む観点

本文を頭から一度、読者として通して読み、引っかかった所を控えてから、次の観点で読み直す。観点は目安で、その話で効くものだけを使う。

| 観点 | 見る所 |
| --- | --- |
| 掴み | 冒頭の数行で、誰の・どこの・何の話かと、読み進める理由(問い・違和感・欲求)が立つか |
| 視点 | 視点人物が揺れていないか。視点人物が知りえないことを地の文で語っていないか |
| 場面の芯 | 場面ごとに、人物の目的・それを阻むもの・場面の前と後で変わったこと、があるか |
| 情報の出し方 | 説明の塊・設定の羅列で話が止まっていないか。逆に、読者が要る情報を後出しにしていないか |
| 見せる・語る | 感情・性格を地の文で言い切るだけの所(「彼は怒っていた」)を、行動・セリフ・仕草で見せられるか |
| セリフ | 誰のセリフか読み取れるか。口調で書き分けられているか。説明のためだけのセリフになっていないか |
| 人物の動機 | 人物の行動に、読者が追える理由があるか。都合で動かされている所が無いか |
| テンポ | 場面の長さの配分、場面転換の分かりやすさ、同じことの繰り返し |
| 描写 | 初めて出る人物・場所が読者に見えるか。五感のうち視覚だけに偏っていないか。描写の密度が場面の重さに合っているか |
| 引き | 話の終わりに、次を読みたくなる問い・変化が残るか。前の話の引きを受けているか |
| ラノベとして | キャラクターが一言・一つの行動で立つか。一話の中に読者の得る楽しみ(笑い・かっこよさ・可愛さ・驚き)があるか。改行・段落が画面で読みやすいか |

## 流れ

1. **話を読む**: `ReadEpisodeTexts` で題・時刻・プロット・本文を読む
   - 本文が空なら止まり、話の画面で書いて保存してから合図するよう伝える
   - `#` で始まる指示の行(スキル `fill-episode` の「`#` の指示」)は、作者がまだ書いていない所の覚え書きとして読み、講評しない。書いてある所だけを講評する
   - 作者が「ここは自分で書いた」「この場面だけ見て」と言ったら、そこだけを講評する
2. **周りを読む**: 作品の直前の話があれば `ReadEpisodes` で本文を読み、前の話の引きと、この話の入りの繋がりを見る。作者の書き方(本文の範囲)と講評の記録を `ReadWritingStyle` で読む
   - 人物・設定の材料(`ReadEpisodeBrief`)は読まない。初めてこの話を開いた読者に何が見えるかを講評するので、db にしかない事実で本文の足りない所を埋めて読まない
   - プロットは、作者が書こうとしたこと(狙い)として読む。狙いと本文の効き方がずれている所が、提案の一番の種になる
3. **講評を書く**: `<scratchpad>/critique-<話id>/critique.md` に、次の形で書く。引用は本文の文の頭 20 字ほどを「」で置き、作者が本文の中で探せるようにする
   - `## 良かった所`: 一つか二つ。どこが・なぜ読者に効いているか。次も続けてよいことを具体的に
   - `## 読者の疑問`: 読んでいて湧いた問いを、本文の順に。それぞれに、作者が狙った謎として効いている(読み進める理由になる)か、読者が置いていかれる(誰が・どこで・なぜが分からず止まる)かを添える。どちらか読み切れないものは、作者への問いとして書く
   - `## 改善の提案`: 三つまで、効く順に。それぞれ「所(引用)」「観点(上の表の名前)」「読者にどう効いているか」「直す方向」「例(要るときだけ。三文まで)」
   - `## 次のインプット`: 提案に結び付いた、学ぶと効く技法・考え方を一つか二つ。それぞれに、短い説明と、次の二つを付ける
     - 観察: 手持ちのラノベ・小説で、どこを何と比べて読むか(例: 一巻の冒頭 3 ページで、主人公の名前・目的・違和感が何行目に出るかを数え、自分の話の冒頭と並べる)
     - 練習: 作者の作品の人物・場面を使った、十数分で書ける短い課題(例: この話の〇〇の場面を、〇〇の視点から 300 字で書き直す)。書いたらチャットに貼って見せるよう添える
   - `## 前からの課題`: 講評の記録の課題のうち、この本文で直っていたもの・まだ残るものを、引用を添えて。記録が無ければ節ごと省く
   - `## ほかに気づいた所`: 提案に入れなかった所を一行ずつ(誤字・言い回し・世界の事実との食い違いも、ここに一行で)
4. **返す**: `critique.md` の中身をそのまま返答に書く(講評がこのスキルの仕上がり)。最後に、直して書いたら「ep<話id> crit」でもう一度見ること、練習を書いたら貼れば講評することを一行添える
5. **講評の記録に入れる**: この講評で見つけた課題を、講評の範囲の行に整理して入れる。作者が自分の課題の移り変わりを読み返し、次の講評で前の課題が直ったかを見るための記録
   - 行が無ければ `CommitStylePreference` で作る。あれば `UpdateStylePreference` で行まるごと書き直す。作者の認めは待たない
   - 話ごとの日記にしない。上の「読む観点」の名前を見出しにして、その下に `- <課題>(<状態>。ep<id>: <その話でどうだったか>)` の形で置く。状態は「残る」「直りかけ」「直った」
   - 同じ課題が前からあれば、項目を重ねずに状態と例を書き換える。例は一つの項目に三つまでにし、古い例から外す
   - 「直った」が二話続いた課題は、見出しから外して末尾の `## 身に付いたこと` に一行で移す
   - 末尾の `## 学んだインプット` に、この講評で出した技法の名前を `- <技法>(ep<id>)` で足す。次の講評で同じインプットを繰り返さず、前に出したものが効いているかを見るのに使う
   - 記録の文は全体の行の書き方に従う(講評の範囲の行を読むときに、全体の行も一緒に返る)
6. **練習を受ける**: 作者が練習の答えを貼ったら、3 の形のうち「良かった所」「改善の提案(一つか二つ)」だけで短く返し、講評の記録の、その練習の元の課題の例に `練習: <どうだったか>` として足す。練習の文は db の本文には入れない

## 報告する

講評(3 の中身)のあとに、講評の記録で足した・状態を変えた課題を一行ずつ書く。`critique.md` のパス(スクラッチパッドの絶対パス)を添える。
