name: episode
description: 話のプロット(`plot_text`)・時刻・登場人物・前の話・作品を決めて、作品に話(episode)を一話ぶん書いて足す。プロット・時刻だけ決めた話(本文の無い episode)に本文だけを書くのにも使う。このセッションの Claude がプロットから登場人物・場所を推測して結び、材料を読んで自分で本文を書いて確定する。「このプロットで話を書いて」「〇〇と△△が出る話を 11579/03/02 で」「エピソードを作って」「この枠の本文を書いて」などの依頼で使う。
---

`CLAUDE.md` のルールに従う。本文は生成関数(`GenerateEpisode` の `claude -p`)に任せず、材料を読んだこのセッションの Claude が書く。
下の流れは目安で、どの材料を足して引くか・プロットをどう膨らませるか・誰をどこに出すかは、頼まれた話に合わせて柔軟に決めてよい。
迷う所(大筋を変える・時刻を動かすなど、頼まれた範囲を越える判断)だけユーザに尋ねる。プロットに要る人物・場所を作るのは尋ねなくてよい(報告に含める)。

## 回し方(場所で分ける)

入口の呼び方と、id・話の引き方は場所で違う。環境変数 `CLAUDE_CODE_REMOTE` を見て、当たる方だけを Read する。

| `CLAUDE_CODE_REMOTE` | 読むファイル | 形 |
| --- | --- | --- |
| `true` でない(手元) | `.claude/skills/episode/local.md` | db に直に繋ぎ、入口を python で呼ぶ |
| `true`(web のセッション) | `.claude/skills/episode/web.md` | db には繋がず、同じ入口を API 越しに回す(`web_session/`) |

## 流れ

人物の設定(`text`)だけを見てプロットを書かない。人物がこれまでの話で何をしていたか(どこで働き、誰と何があったか)は
話の本文にしか無いことが多い。**プロットを書く前に、出す人物が関わった話を読む**。
また本文の材料(登場人物の直近の出来事・関係、場所の出来事、後に決まっている出来事)は話に結んだ登場人物・場所から引くので、
**本文の材料を読む前に、登場人物・場所を話に結ぶ**。

1. **話の行を用意する**
   - 本文の無い枠(id を頼まれた): その行を使う。時刻(`start`)が空なら、前後の話から決めて先に入れる
   - 新しい話: 作品の話の並びを引き、同じ時刻の話が無いか確かめてから、`CommitEpisode` で枠を足す
     (`story_id`・`start` と、頼まれた人物の `character_ids`。プロットはまだ空か、頼まれた一言でよい)
   - 作品・人物・場所は名前で頼まれても、引いた id を使う
2. **人物の関わった話を読む**
   - `ReadEpisodeCasting(episode_id)` で、今の登場人物・名前だけ出る人物それぞれの「関わった話(古い順)」
     (作品を問わず、この話より前に登場したか名前が出た話)と、登場人物の候補・場所とその中の既知の場所を、id 付きで読む(AI は呼ばない)
   - 「関わった話」の本文を `ReadEpisodeTexts(episode_ids)` で読む。特に「登場」の話と、この話に近い時期の話。
     人物の設定と本文が食い違えば本文を正とし、食い違いはユーザに報告する(人物の設定を直すかはユーザが決める)
   - 本文に出てくるのに db にいない人物(上役・家族など)がいれば、その人物を使うときは同じ名前で作る
   - 関わった話が本文と比べて少なすぎる(名前が出ているのに挙がらない)ときは、`RefreshMentions()` で名前だけ出る人物を拾い直してから読み直す
3. **プロットを書いて入れる**: 読んだ話と食い違わないように、`data_access_logic/readme.md` の「補足」の `## 場面` / `## 狙い` の形で書き、
   `CommitEpisode(EpisodeCommitForm(id=…, plot_text=…))` で入れる(プロットに名前の出る人物が、名前だけ出る人物として拾われる)
4. **登場人物・場所を推測して結ぶ**(下の「登場人物・場所」)
   - `ReadEpisodeCasting` を読み直し、プロットで台詞・行動のある人物と主な舞台を決める。候補に無い人物・場所は作る
   - `CastEpisode(episode_id, character_ids=[…], location_id=…, viewpoint_character_id=…)` で結ぶ
     (登場人物はまるごと置き換え、結んだ人物は承認され、名前だけ出る人物は拾い直される。同期フラグは変えない)
   - 足した人物に関わった話があれば、2 と同じく読む
5. **設定を引く(要るとき)**: プロットに出る固有の語(呼称・制度・道具・病など)を自分で挙げ、`ResolveTerms` でアイデアと照らす。
   返った `ideas` と矛盾させず、作中の呼び名(`called`)で書く。当たらなかった語は候補のアイデアとして足される
6. **本文の材料を読む**: `ReadEpisodeBrief(episode_id)`。長いので、出力をスクラッチパッドのファイルへ書き出して Read する。返すもの:
   - 書き方(文体の決まりと、この世界の `style_preference`)・作品
   - 直前の話の本文: 同じ作品の直前の五話
   - 前の話の概要(話id つき): 同じ作品のすべての話と、登場人物が関わったすべての話(作品を問わない。重ならない)。直前の五話は除く
   - この話・結んだ登場人物(直近の出来事・関わった話つき)・名前だけ出る人物・登場人物の関係・場所の直近の出来事・後に決まっている出来事
   前の話・出来事の要約が古ければ、読む前に AI が作り直す(数分かかることがある)。概要で足りなければ `ReadEpisodeTexts` で本文を読む
7. **本文を書く**(下の「書くとき」)。書いた本文はスクラッチパッドのファイルに置く。
   書くうちに登場人物・場所を変えたくなったら、4 の `CastEpisode` で結び直し、6 を読み直してから書き続ける
8. **確定する**: `CommitEpisode(EpisodeCommitForm(id=…, title=…, main_text=<ファイルの中身>, synced=True))`。
   `synced=True` は自動で書いた話の扱い(渡さないと手で直した話として false になる)。題は、作者が決めた題があればそのまま、空なら付ける。
   登場人物・場所は 4 で結んであるので渡さなくてよい。確定すると、本文の改行が整い(`layout_novel_text`)、
   名前だけ出る人物が本文・プロットから拾い直され、概要・ミームが作り直される
9. **設定を結ぶ**: 5 で引いて本文が踏まえたアイデアがあれば `LinkIdeas(idea_ids, episode_id=…)`
10. **人物の設定に足す(確定のあと)**: 本文で起きたことのうち、サブキャラクター(`main_character` が false)の立場・仕事・住まい・
   人間関係・主要人物との関わりが変わった所や、その人物が見た・知ったことを、その人物の `text` の `# 来歴` に
   `- <年>年(<歳>歳): …` の行で年の順に差し込み、`UpdateCharacter(CharacterUpdateForm(id=…, text=…))` で直す。
   すでにある行は書き換えず、足すだけにする。この話の時刻より後のこと(後年の立場・死・予定)は書かない(`data_access_logic/readme.md` の「人物の来歴」)。
   主要人物の設定は作者が書くので触らない。人物の設定と本文が食い違っていれば、足す前にユーザに報告する

## 書くとき

- 材料の「書き方」に従う。この世界の舞台設定・既存の話から抽出した文体の癖もここに入っている
- プロットを場面まで展開したものを本文にする。プロットに無い大きな出来事は足さない(場面を厚くする描写・会話・動きは足してよい)
- 筋は前の話をそのまま受け継ぐ。語の選び方・言い回し・地の文とセリフの運びは直前の話の本文に揃える(文を写さない)
- 登場人物の直近の出来事はこの話の前に済んだこと。「この時点より後に既に決まっている出来事」と矛盾させず、先回りしない
- 前の話に出ていない人物は初登場として、外見・性格を描く
- 本文を書くので `.claude/docs/meme.md` も読む。生物・医療・兵器の話題は `ai/instructions/sensitive.py` の決まりに沿って物語に要る抽象度にとどめる
- 字数の指定は無い。中身に合わせる

## 登場人物・場所

- 登場人物(`episode_character`)は、この話で台詞・行動のある人物。`ReadEpisodeCasting` の「登場人物」「名前だけ出る人物」
  「登場人物の候補」から選び、`CastEpisode` の `character_ids` に全員を渡す(渡すとまるごと置き換わる)。
  話題・回想・噂に名前が出るだけの人物は入れない(`mentioned=true` の行として自動で拾われる)。群衆・名前の要らない通りすがりも入れない
- 呼び名が違っても(役職・続柄・あだ名など)、人物像から同じ人物と分かれば既存の人物を使う
- db にいない人物が要るなら、`CommitCharacter`(`text` は `.claude/docs/meme.md` に従う。サブキャラクターの来歴はこの話の時刻までにする)か、
  AI に組ませるなら `GenerateCharacter(CharacterForm(name=…, text=<人物像と役どころ>, location_id=…), time=<話の時刻>, plot_text=<話のプロット>)`
  で作ってから `character_ids` に入れる(プロットを渡すと、その時刻・場所で役どころを果たせる年齢になる)。作品・場所・時刻に馴染む人物にする
- 場所: 主な舞台が材料の場所より細かければ、「この場所の中の既知の場所」から選んで `location_id` にする。
  無ければ `CommitLocation(LocationCreateForm(name=…, kind=…, text=…, parent_id=<材料の一番細かい場所id>))` で足す
- 視点(`viewpoint_character_id`)は頼まれたか、プロットで決まっているときだけ入れる

## 報告する

終わったら書いた話を読み(読み方は回し方のファイル)、題・時刻・視点・字数(`letters`)・あらすじ・
足した人物・場所・結んだ設定・来歴に足した人物を短く報告する。本文・プロット・材料のような長いものは返答に貼らない。

すでに本文のある話を書き直す・書き足す(推敲する)ときはスキル `revise-episode` を使う。
GUI の「AI で本文まで書く」ボタン(待ち行列からスキル `run-ai-tasks` で回る)は、これまでどおり生成関数 `GenerateEpisode` を使う。
