description: 話のプロット(`plot_text`)・時刻・登場人物・前の話・作品を決めて、作品に話(episode)を一話ぶん書いて足す。プロット・時刻だけ決めた話(本文の無い episode)に本文だけを書くのにも使う。このセッションの Claude がプロットから登場人物・場所を推測して結び、語り部を務めて人物役に手番を最後まで自動で回し、まとめを報告して確かめを待ってから(セミオート)、材料を読んで自分で本文を書いて確定する。「ep61」(61 は話の id)、ユーザが自分で書いた本文を世界に反映する「ep61 書いた」、「このプロットで話を書いて」「〇〇と△△が出る話を 11579/03/02 で」「エピソードを作って」「この枠の本文を書いて」などの依頼で使う。ユーザが作者として本文を書き、語り部と人物役がその続きを代わる代わる書く「ep61 in」はスキル `interactive-episode`、本文を書かずに作品全体の筋・設定を詰める「st3」(3 は作品の id)はスキル `story-director`。

- 本文は材料を読んだこのセッションの Claude が書く(本文を書く生成関数は無い)
- 下の流れは目安。どの材料を足して引くか・プロットの膨らませ方・誰をどこに出すかは、頼まれた話に合わせて決めてよい
- 「ep61」(「61 をやろう」のように番号だけでも)は、話の id 61 を下の「流れ」で書く合図。その話の行(題・時刻・プロット・本文の有無)を読み、何をするかを短く返してから始める(ユーザが画面でその話を直している最中のことがある)。本文がすでにあれば、書き直すか(スキル `revise-episode`)を尋ねる
- 「ep61 書いた」は、ユーザが自分で書いた本文を世界に反映する合図(下の「ユーザが書いた本文を反映する」)
- 作品の筋の検討(どう進めるか)はスキル `story-director` の受け持ち。話(episode)の枠は頼まれたときだけ作る
- ユーザに尋ねるのは、頼まれた範囲を越える判断(大筋を変える・時刻を動かすなど)だけ。プロットに要る人物・場所は尋ねずに作り、報告に含める

## 入口

入口は id と引数で呼ぶ。呼び方・行の引き方は、手元は `.claude/docs/db.md`、web のセッションは `.claude/docs/web-db.md`(自分の場所の方だけ読む)。
`ReadEpisodeBrief`・`CommitEpisode` は AI を回すので数分かかることがある(web では `run_in_background`)。`ReadEpisodeCasting`・`ReadCharacterEpisodes` は db だけの入口で、すぐ返る。
入口と `tool.episode_session`(`stage`・`knower-gaps`・`read` など)の結果は、スクラッチパッドのファイルに書き出して Read で最後の行まで読む(`CLAUDE.md` の「ツールの使い分け」)。人物・話の材料は数万字になり、Bash の出力のままでは頭しか見えない。要る所だけを `jq` で抜くときは、書き出したファイルに当てる。

### 読む量を絞る

- 入口が返すもののうち、手順が読むと決めた所だけを読む。書き出したファイルを丸ごと Read せず、要る見出し・要る期間を `jq` で抜いてから読む
- 語り部(手順 2〜6)は、人物の来歴と `筋書き`(作者の先の予定)を読まない。人物のこれまでは、手順 2 の関わった話の本文から読む。登場人物を決める材料(`ReadEpisodeCasting`)にも来歴・筋書きは付かない。語り部が話の時刻より先や、見聞きする位置で知れないことを知ると、語り・要求に先回りが混ざる
- 来歴は、本文を書くとき(手順 7 の材料)と、話のあとに足すとき(手順 10)にだけ読む

| すること | 入口の id | 引数 |
| --- | --- | --- |
| 話の枠を足す・プロットを入れる・本文を確定する | `episode.commit_episode.CommitEpisode` | `{'episode': {…}}`。新しい枠は `{'story_id': …, 'start': '<年/月/日>', 'character_ids': […], 'plot_text': …}`、既存の話は `'id': …` と変える欄だけ(渡した欄だけが直る) |
| 登場人物・場所を決める材料を読む | `episode.read_episode_casting.ReadEpisodeCasting` | `{'episode_id': …}` |
| 人物が関わった直近の話を、本文つきで読む(人物ごとに呼ぶ) | `episode.read_character_episodes.ReadCharacterEpisodes` | `{'episode_id': …, 'character_id': …}` |
| 話を id で読む(本文まで) | `episode.read_episode_texts.ReadEpisodeTexts` | `{'episode_ids': […]}` |
| 名前だけ出る人物を拾い直す | `episode.refresh_mentions.RefreshMentions` | `{}`(すべての話)か `{'episode_ids': […]}` |
| 登場人物・場所・視点を結ぶ | `episode.cast_episode.CastEpisode` | `{'episode_id': …, 'character_ids': […], 'location_id': …, 'viewpoint_character_id': …}` |
| 本文の材料を読む(登場人物・場所を結んだあと) | `episode.read_episode_brief.ReadEpisodeBrief` | `{'episode_id': …}` |
| 登場人物の話し方を直前の五話のセリフから調整する(頼まれたときだけ) | `episode.refresh_voices.RefreshVoices` | `{'episode_id': …}` |
| 話に出た新しい語を足す | `episode_session.add_ideas.AddIdeas` | `{'episode_id': …, 'ideas': [{'keyword': …, 'description': …, 'kind': …}]}`(場所・時刻は話から取る。種別は分類のあるものから選ぶ。返るのは足した語 `added` と足さなかった語 `kept` の名前だけ) |
| 設定を引く | `idea.resolve_ideas.ResolveIdeas` | `{'ideas': [{'keyword': …, 'variants': […], 'description': …, 'kind': …}], 'location_id': …, 'time': '<話の時刻>'}` |
| 人物を足す | `character.commit_character.CommitCharacter` | `{'character': {'name': …, 'appearance': <見た目>, 'text': <説明>, 'start': …, 'location_id': …, 'histories': [{'start': '<年/月/日>', 'description': <来歴の節目>}]}}` |
| 人物を AI に組ませて足す | `character.generate_character.GenerateCharacter` | `{'character': {'name': …, 'text': <人物像と役どころ>, 'location_id': …}, 'time': '<話の時刻>', 'plot_text': <話のプロット>}` |
| 人物の来歴を読む | `character.read_character.ReadCharacter` | `{'character_id': …}`(時刻を渡さず、すべての行を読む) |
| 人物の来歴に足す | `character.update_character.UpdateCharacter` | `{'character': {'id': …, 'histories': [<今の行すべて>, …]}}`(配列はまるごと置き換わる) |
| 場所を足す | `location.commit_location.CommitLocation` | `{'location': {'name': …, 'kind': …, 'text': …, 'parent_id': …}}` |
| 本文でない文(プロット・来歴・関係・アイデアの説明)の書き方を読む | `style_preference.read_writing_style.ReadWritingStyle` | `{}`(db だけ。`text` に返る) |
| 作品の話の並び(`start` 順) | `episode.read_episodes.ReadEpisodes` | `{'story_id': …, 'count': 500, 'text': False}` |

`UpdateCharacter` の `histories`・`parameters` は配列がまるごと置き換わる(並びを変えると行の id が変わる)。時刻を渡さない `ReadCharacter(character_id)` で今の行をすべて読み(`start` が空の行も残す)、すでにある行は書き換えずに、新しい行を末尾に足して渡す。今の行の知る相手は、`knowers` を渡さなければそのまま残る。

### 入口の返す形

見出しは推測せず、ここか `jq 'keys'` で確かめてから引く(無い見出しは黙って null になる。`jq` の書き方は `.claude/docs/setup.md` の「jq」)。web のセッションで `flows.run` から返るものは `.result` に包まれない。

- `ReadEpisodeCasting`: `この話`(`話id`・`題`・`時刻`・`場所(広い順)`・`視点`・`プロット`)・`登場人物`・`名前だけ出る人物`・`登場人物の候補`・`この場所の中の既知の場所`。`登場人物`・`名前だけ出る人物` には `人物id`・`名前`・`人物像`・`口調` などが付く(`来歴(古い順)`・`筋書き` は付かない)。`登場人物の候補` は `人物id`・`名前`・`種別`・`年齢`・`人物像` だけ。関わった話は付かない
- `ReadCharacterEpisodes`: その人物の直近の話の配列(古い順)。`話id`・`作品`・`題`・`時刻`・`出方`(`登場`・`名前だけ`)・`本文`。プロットは付かない
- `ReadEpisodeBrief`: `書き方`・`作品`・`文体の見本(古い順)`・`この話`・`この場所の直近の出来事(古い順)`・`この時点より後に既に決まっている出来事`
  - `文体の見本(古い順)` は本文の文字列の配列(`.["文体の見本(古い順)"][-1]` が直前の話。鍵は無い)
  - `この話` の中は `話id`・`題`・`時刻`・`終わり`・`場所(広い順)`・`視点`・`登場人物`・`名前だけ出る人物`・`登場人物の関係`・`設定`・`プロット`・`今の本文`
- `ReadEpisodeTexts`: 列名の英語(`id`・`title`・`main_text`・`summary_text` など)の配列
- `tool.episode_session read` の行: `id`・`kind`(`人物`・`語り`・`作者`)・`character`(人物の名前。人物の行だけ)・`time`・`witnesses`(見聞きする人物の id)・`request`(語りの行では語り)・`simultaneous`・`thought`・`action`・`speech`・`aim`

## 流れ

- **プロットを書く前に、出す人物が関わった話の本文を読む**。人物の芯(`text`)だけを見て書かない(これまでの出来事は話の本文にある)
- **本文の材料を読む前に、登場人物・場所を話に結ぶ**(材料は結んだ登場人物・場所から引く。結んだ人物は生没年を問わず出し、来歴は話の時刻に効くものだけが出る)。設定(アイデア)は話に結ばず、材料を読むときに、プロット・話のセッションの行・今の本文に出た語で引かれる
- **本文でない文も同じ書き方で書く**: プロット・語りと要求・来歴・関係・アイデアの説明は、始めに `ReadWritingStyle` で読んだ書き方(語の選び方・慣用句。世界の好みのうち効く範囲が全体の行を含む)で書く。本文は材料の「書き方」(それに本文だけの決まりを足したもの)で書く

1. **話の行を用意する**
   - 本文の無い枠(id を頼まれた): その行を使う。時刻(`start`)が空なら、前後の話から決めて先に入れる
   - 新しい話: 作品の話の並びを引き、同じ時刻の話が無いか確かめてから、`CommitEpisode` で枠を足す(`story_id`・`start`・頼まれた人物の `character_ids`。プロットは空か頼まれた一言でよい)
   - 作品・人物・場所は名前で頼まれても、引いた id を使う
2. **人物の関わった話を読む**
   - `ReadEpisodeCasting(episode_id)` で id 付きで読む: 今の登場人物・名前だけ出る人物と、登場人物の候補・場所とその中の既知の場所
   - 登場人物・名前だけ出る人物ごとに `ReadCharacterEpisodes(episode_id, character_id)` を呼び、その人物の直近の 5 話を本文で読む(作品を問わず、この話より前に登場したか名前が出た話)。結果はスクラッチパッドに書き出し、皆の分を合わせて重なりを除き(`話id` で)、`時刻` の順に本文を読んで、人物がこのところ何をしたか・何を持ち、誰と何を話したかを掴む
   - それより前の話は、要るときだけ `ReadEpisodeTexts(episode_ids)` で本文を読む(人物が初めて出る話など)。語り部は来歴を読まない(上の「読む量を絞る」)
   - 人物の設定と本文が食い違えば本文を正とし、ユーザに報告する(人物の設定を直すかはユーザが決める)
   - 本文に出てくるのに db にいない人物(上役・家族など)を使うときは、同じ名前で作る
   - 関わった話が本文と比べて少なすぎる(名前が出ているのに挙がらない)ときは、`RefreshMentions()` で名前だけ出る人物を拾い直してから読み直す
3. **プロットを書いて入れる**
   - 読んだ話と食い違わないように、`ai/instructions/plot.py` の `PLOT_FORMAT_INSTRUCTION` の形(場面ごとの見出し `# <場所と時間>` と地の文・台詞だけ)で書く。言葉は `ReadWritingStyle` の書き方に沿う(上の「本文でない文も同じ書き方で書く」)
   - 今のプロットに「〜は迷っている」の文(スキル `story-director` が置いた、作者が決めかねているメモ)が残っていれば、書く前にどちらを取るかユーザに尋ねる
   - `CommitEpisode` に `id`・`plot_text` を渡して入れる(プロットに名前の出る人物が、名前だけ出る人物として拾われる)
4. **登場人物・場所・関係を整える**: 下の「セッションの前に整える」の 1〜4(その 5 は次の手順 5)。手番を回さない話(台詞・行動のある人物が一人だけ・ユーザが一人で書くよう頼んだ)でも、登場人物・場所は結ぶ
5. **設定と照らす(任意)**
   - 設定は 7 の材料を読むときに引かれる。プロットが世界の設定と食い違っていないかを手番の前に確かめたいときだけ、プロットに出る固有の語(呼称・制度・道具・病など)を自分で挙げ、`ResolveIdeas` でアイデアと照らす(`location_id` は 4 で結んだ場所、`time` は話の時刻。当たらなかった語は候補のアイデアとして足される)
   - 返った `ideas`(当たったものとその上位)にプロットと食い違うものがあれば、プロットを直して 3 から入れ直す
6. **手番を回す**(下の「手番を回す(セミオート)」): このセッションの Claude が語り部を務め、人物役に場面を手番で最後まで演じさせる。終えたらまとめを報告して待ち、ユーザが認めたら 7 へ進む。指摘があれば、人物それぞれに意見を求め、その意見を尊重して、その手番から回し直す。本文の材料は、認められるまで読まない
7. **本文の材料を読む**: `ReadEpisodeBrief(episode_id)`。長いので、出力をスクラッチパッドのファイルへ書き出して Read する。中身:
   - 書き方(文体の決まりと、この世界の `style_preference`)・作品
   - 登場人物の話し方: 材料の登場人物には、話の時刻の口調・一人称・二人称などがそのまま入る(自動では調整しない。ユーザに頼まれたときだけ、`RefreshVoices` で直前の五話のセリフから調整してから読む)
   - 文体の見本: 同じ作品(親の作品の章・外伝を含む)の直前の話の本文を、新しい話から字数の上限まで。直前の話だけで上限を超えるときは、その頭だけ
   - この話・結んだ登場人物(直近の出来事・関わった話つき)・名前だけ出る人物・登場人物の関係・設定・場所の直近の出来事・後に決まっている出来事
   - 設定: プロット・話のセッションの行(手順 6 で回したとき)・今の本文から AI が元ごとに挙げた語でアイデアを引き、当たったもの(時期の決まったもの)とその上位(下位は付かない)。当たらなかった造語は候補のアイデアとして足されて入る。名前は、アイデアの履歴のうち話の場所・時刻に効く行の作中の呼び名(無ければ本質の名前)。履歴の行は場所を問わず話の時刻までに始まったものをすべて添える
   - 人物の来歴・スキルの来歴・アイデアの履歴の行には「知る相手」が付く。どの行も知る相手だけが知る(本人・関係のある人物・効く場所に住む人物も、知る相手に入っていなければ知らない)。人物の芯(人物像)は本人と関係のある人物が知る。スキルの「本質」は作者だけが読む
   - 前の話の中身は、手順 2 で読んだ本文と、材料の登場人物の来歴・関係から受け継ぐ。出来事の要約は作り直さず、そのときのまま入る。語を挙げるのには AI を呼ぶ
8. **本文を書く**(下の「書くとき」に沿う。手順 6 で手番を回したときは「本文に起こす」にも沿って、セッションの行を地の文にする)
   - 書いた本文はスクラッチパッドのファイルに置く
   - 書くうちに登場人物・場所を変えたくなったら、4 の `CastEpisode` で結び直し、7 を読み直してから書き続ける。書くうちに新しい固有の語を使うなら、`ResolveIdeas` で照らして返った `ideas` を踏まえる(当たらない語は候補として足される)
   - 書き終えたら、確定の前に、本文・プロット・セッションの行に出た固有の語のうち、材料の「設定」に無いものをすべて挙げ、`AddIdeas` でまとめて足す(どの語を足すか・種別は「新しい語を足す」のとおり)
9. **確定する**: `CommitEpisode` に `id`・`title`・`main_text`(ファイルの中身)を渡す
   - 確定のあと、その本文からミームと出来事の種が抜き出される
   - 題は、作者が決めた題があればそのまま、空なら付ける
   - 登場人物・場所は 4 で結んであるので渡さなくてよい
   - 確定すると、本文の改行が整い(`layout_novel_text`)、名前だけ出る人物が本文・プロットから拾い直され、ミームが作り直される。本文の中で住まい・拠点が変わった登場人物は、AI が移動先を決めて居場所を移す(レスポンスの `moves` に人物 id と場所 id の組で返る。報告に含める。違っていれば `MoveCharacters` で移し直す)。本文で会った・知り合いだと分かった登場人物どうしには、AI が関係を足す(始まりは話の時刻。レスポンスの `relations` に返る。報告に含める。違っていれば `UpdateCharacterRelation` で直す)
10. **人物の設定に足す(確定のあと)**
    - 対象は、本文の確定後に限り、主要人物・サブキャラクターを問わない(主要人物の設定も、本文の結果に応じて直してよい)。本文を書く前・書く途中には主要人物の設定を触らない
    - 足す前に、登場人物ごとに、話の始め(材料の人物の装い・体格・直近の出来事)と本文の終わりを突き合わせ、次の項目で変わったものを一人ずつすべて挙げる。小さな変化(物を受け取った・荷に括った・袖を繕った・痣を人に見られた)も落とさない
      - 持ち物・武器: 手にした・手放した・壊れた・人に渡した・身に着ける場所を変えた。人に渡した物は、渡した側と受け取った側の両方に書く
      - 身なり・体: 着る物、傷とその治り、体つき、人前で見せた印
      - 住まい・居場所、立場・仕事、人間関係、見た・知ったこと
      - 変わったものが無い人物は、無いと報告に書く
    - 本文で変わった立場・仕事・住まい・人間関係・主要人物との関わりと、その人物が見た・知ったことを、来歴(`histories`)に足す
    - 来歴の行は、材料の「書き方」のうち本文でない文にも効く所(語の選び方・慣用句)に沿い、本文に出た言葉か日常の言葉で書く。要約のための言い回し・慣用句(「耳で拾う」「胸に置き直す」)を使わない。人物が出した指示・条件・確かめを一つずつ並べず、後の話に効く決めごとだけを書く(人物役は来歴を読んで演じるので、行の言い回しはセリフに、並べた指示は「いつも条件を付けて確かめる人物」という癖に移る)
    - 知らせる相手は行の `knowers` に入れる(周りの人物も知ることはその人物か住む場所を、本人だけが知ることは本人だけを入れる)。`knowers` を渡さない新しい行は本人だけが知る
    - `start` はこの話の時刻(`'<年/月/日>'`)。この話で起きたことを一行にして、`UpdateCharacter` で足す(入口の表の下の書き方。同じ年の別の行に書き足さない。後の出来事が前の話に漏れ、知る相手も分けられなくなる)
    - この話の時刻より後のこと(後年の立場・死・予定)は書かない(`data_access_logic/readme.md` の「人物の来歴」)
    - 人物の設定と本文が食い違っていれば、足す前にユーザに報告する
    - 本文で身なり・持ち物・武器・傷・人前で見せた印が変わった人物は、出来事の行に加えて、種別(`kind`)「装い」の来歴の行を直す。体つきが変わったなら体格(`parameters` の `build`)の行も足す。人物役も語り部もその時刻に効いている装いの行・体格を今の見た目として読むので、出来事の行だけ足すと前の持ち物のまま演じる(新しい剣を手にした人物が、体格の「木剣を振るう」のまま木剣を握った)
      - 装いの行は、身に着けている物ごとに一行にする(「腰に木剣」「灰色の外套」)。新しく身に着けた物は、この話の時刻を `start` にした行を足す。外した・手放した・壊れた物は、その行の `end` にこの話の時刻を入れる。物が変わった(外套が裂けた・剣が折れた)なら、前の行に `end` を入れ、変わった後の物の行を同じ時刻から足す(「腰に木剣」に `end`、「拾った大剣を背に」を足す)。変わらない物の行は書き直さない
      - 体格に持ち物が書いてあれば、持ち物を抜いた体格の行も同じ時刻で足す(足す行には変える欄だけを書く)。この話の時刻より後に始まる作者の行は直さない
      - 隠している物・印(袋の中の物、服の下の印)は装いに書かず、種別「持ち物」「隠し事」などの行にして、知る相手(`knowers`)を絞る。装いの行は見た人にそのまま知れる(`data_access_logic/readme.md` の「人物の本文と来歴」)
      - 覚えておくべきこと(約束・見た光景・教わったこと)は種別「記憶」の行にしてよい

## 手番を回す(セミオート)

手順 6 では、このセッションの Claude が語り部を務め、台詞・行動のある登場人物一人ずつの人物役(エージェント `character-actor`。opus・effort low(手番の返りを速くするため)、道具は Bash と Read)に場面を手番で演じさせる。手番はユーザに尋ねずに話の最後まで自動で回す。回し終えたら、セッションのまとめを報告してユーザの確かめを受ける。指摘があれば、関わる人物それぞれに意見を求め、人物の意見を尊重して、その手番から消して回し直す。

手番の中身(語り・要求・一手)は db に置かず、語り部と人物役が同じ機械で読み書きする手番のファイル(`.cache/episode_session/e<話id>/`。`tool.episode_session` のコマンドで扱う)に置き、番は語り部と人物役が知らせ合って回す。手番のファイルはセッションが終われば残さない(web ではコンテナと一緒に消える)。人物役はファイルを見張らない。語り部が番の行を足して、その行の id を人物役に SendMessage で送り、人物役はその行だけを読んで一手を入れ、「終わった <id>」と返して止まる。止まった人物役は、次の番が送られるまで何もしない。

- 人物役が読むのは、本人の外見・芯・ミーム・行動原理と、関係のある人物の外見・芯と、それぞれの来歴・スキル(名前と来歴)とアイデアの呼び名・受け止め方のうち知っているものだけ(知る相手に当たるもの。`data_access_logic/readme.md` の「来歴・履歴を知る相手」)。筋書き(`plot`)は渡らない
  - アイデアは、はじめに読む材料(`knowledge`)にはプロットに名前の出るものだけが入る。手番の要求に出た語は、人物役がそのつど `ideas`(入口は `character.read_known_ideas.ReadKnownIdeas`)で引き、知っているものだけを読む
- 台詞・行動のある登場人物が一人だけの話と、ユーザが一人で書くよう頼んだときは、人物役を起こさず手番も回さない。手順 6 を飛ばし、このセッションの Claude がプロットから書く
- 端役(db に人物としていない屋台の主・通行人など)と群衆は、人物役を起こさずに語り部(このセッションの Claude)が演じ、語りに書く(名前を付けない。下の「登場人物・場所」)。話の登場人物(`episode_character`)に結んだ人物は、サブキャラクターでも人物役を起こす
- 芯(`text`)に、関係のある人物も知らないはずの秘密(出生の秘密など)が書いてあれば、その人物の来歴(知る相手を絞った行)へ移すようユーザに伝える
- 手番を回すあいだプロットは直さない。人物役の一手でプロットから外れても、引き戻さない(語りでプロットの結果へ導かない)。外れたまま話の最後まで進め、外れた所をまとめに書く
- プロットにある人物の台詞(「」で括ったもの)と行動は、作者の意図として、その人物の手番の要求で渡す(下の「プロットの台詞と行動を渡す」)。言うか、どう言うかは人物役が決める
- ユーザが作者として本文を書きながら、その続きを人物に演じさせたいときは、スキル `interactive-episode` に移る

### 語り部の決まり

- 受け持つのは、プロットの進行と、場所・時刻・その場にいる人物・見える・聞こえることの管理だけ。人物が何を思い、何を知っていて、どう動くかは人物役が自分のデータから決める。人物役の一手を書き換えない
- このセッションの Claude は手順 2 で人物の芯と関わった話の本文まで読んでいるが、語りと要求には、見聞きする人物の位置で見える・聞こえることだけを書く。その人物の知らない人物像・来歴・設定の履歴・秘密は、場面で明かされた(言った・見せた)ときだけ書く
- 人物の体・持ち物・力(翼・灯り・傷・武器など)が、本人の意思と関わりなく動いた・開いた・光ったとは書かない(「羽ばたいたつもりはないのに」「勝手に」)。それを使うか、どう使うかは人物役が決める。語りに書くのは、人物役の一手で使ったものが、どう働いたか(結果)だけ
- 人物役の一手(行動・セリフ)は、見聞きする人物(`witness_ids`)にそのまま届く(内心・狙いは届かない)。語り部は書き写さない。一手の結果(当たった・倒れた・噛み折られた)は語り部が決めて語りに書く
- 手番の要求を出せるのは、人物役を起こした人物だけ。人物役のいない人物の手番を足すと、その行が埋まらず、後の手番が回らない
- 場面の材料は `stage` で読む(プロット・時刻・場所(広い順)とその説明・登場人物の人物 id と外から見て分かること(名前・年齢・性別・体格・装い・外見)・知り合いの組(関係の名前と人物 id の組))。`stage` は、登場人物と知り合いの組を手番のファイルにも写す。手番を足す(`add`)前に一度読み、登場人物・関係を結び直したら読み直す(写す前は `add` が断られる)
  - 体格は話の時刻の値、装いは話の時刻に効いている装いの来歴の行(身に着けている物ごと。持ち物・武器・見せている傷や印)。語りと要求で人物の持ち物に触れるときは、ここに合わせる。食い違って見えたら(前の話で持ち物が変わったのに装いが古いなど)、手番の前にユーザに伝える
  - 場所の説明は設定の書き言葉で書かれている。語りと要求には、その言い回し(「上の段・下の段」「歩廊」)を写さず、視点人物が見てそのまま言える言葉(「上のほう」「城壁の上の通路」)に直す。語りの言葉は人物役のセリフにも移る
- 「知り合い」に無い二人は初対面として扱う。一手は名前付きで届くので、初対面の相手を `witness_ids` に入れると断られる。その人物の一手は、見た目(`appearance` で読む。名前は返らない)で語りか要求に書く。名前・経歴は、名乗る・噂を聞くなど、その場で分かったときだけ書く

| すること | コマンド |
| --- | --- |
| 材料を読み、登場人物と知り合いの組を手番のファイルに写す | `.venv/bin/python -m tool.episode_session stage --episode <episode>` |
| 初対面の相手の見た目を読む | `.venv/bin/python -m tool.episode_session appearance --character <相手の人物 id> --time '<時刻>'` |
| 手番の要求を足し、人物役に番を送る | 下の「手番の要求を足す」 |
| 番を送った行に一手が入るまで待つ(一手は出さない) | `.venv/bin/python -m tool.episode_session wait --episode <episode> --record <行の id>`(組の手番は `--record` を重ねる。`{"filled": […]}` が返る。待ちきれなければ `pending` も返る) |
| 足した手番の一手を読む(内心・狙いまで要るときだけ) | `.venv/bin/python -m tool.episode_session moves --episode <episode> --after <行の id>`(`--after` より後の一手と、まだ埋まっていない行の id) |
| 場面に出した新しい語をアイデアに足す | 下の「新しい語を足す」 |
| セッションの行をすべて読む | `.venv/bin/python -m tool.episode_session read --episode <episode>` |
| ある行から後を消す(やり直す) | `.venv/bin/python -m tool.episode_session clear --episode <episode> --from <行の id>` |

### 流れ

人物役を起こす前に、「セッションの前に整える」を済ませておく(手順 4)。

0. **前の行を消す**: 本文を作り直すなどで、この話にもうセッションの行があれば(`read --episode <id>` が空でない)、`clear --episode <id>` で消してから起こす(前の行が残ると、前の場面の語りと一手が人物役に届く)
1. **人物役を起こす**: 台詞・行動のある登場人物ごとに `character-actor` を一つ、裏で(`run_in_background`)起こす(起こす前に、話の登場人物の一覧と起こす人物を突き合わせ、漏れが無いか確かめる)。最初のメッセージには話の id・人物の id だけを書く(材料は人物役が `knowledge` で自分で読む)。人物役は材料を読み終えると「用意できた」と返して止まる。全員の「用意できた」を受けてから番を送る
2. **場面を組む**: `stage` を読み、プロットの場面(`#` の見出しごと)から、場面ごとに場所・時刻・その場にいる人物・その場面の着地点を決める
3. **手番を最後まで回す**: 下の「手番の要求を足す」で語りと要求を足し、人物役に番を送り、返った一手(人物の内心・行動・セリフ・狙い)を読んで次を足す。これを話の最後まで繰り返す。途中でユーザに尋ねたり、一手ずつ見せたりしない
   - 次に誰を動かすかは語り部が決める。直前の行動を向けられた人物、場面を着地点へ進める人物を先にする。黙って見ているだけの人物は手番を飛ばしてよい(見聞きした語りと一手は、次の番にまとめて届く)
   - プロットから外れたら、そのまま進める。結果を要求で押しつけず、プロットへ戻すための状況(人を来させる・言わせる)も足さない。次の場面は、外れた結果から自然に続く形で組み直す。外れた所はまとめに書く
   - プロットの台詞と行動は、その場面のその人物の手番で、作者の意図として渡す(下の「プロットの台詞と行動を渡す」)。人物役が言わなかった・違う言葉にした台詞を、あとの手番で言わせ直さない
   - 場面を飛ばす(時間を進める・移動する)ときは、そのあいだに起きたことを語り部が決め、語りと新しい時刻(`time`)にまとめて渡す
   - 語りに新しい固有の語を出したら、そのつど足す(下の「新しい語を足す」)
4. **待つ**: 話の最後まで進んだら、人物役は止めたままにする(また番が送られるのを待つ)。下の「まとめ」を報告し、ユーザの返事を待つ
5. **返事を受ける**
   - 認めた(「OK」「本文にして」など): 手順 7 へ進む。人物役にはもう番を送らない
   - 本文は自分で書く(「本文は自分で書く」「自分で書く」など): 人物役にはもう番を送らず、手順 7 から先へは進まない。次を一行ずつ添えて終える
     - 本文は GUI の話の画面の本文(`main_text`)に書くこと。書き終えたら「ep<id> 書いた」で反映する
     - 手番の行はこのセッションの手番のファイルにだけあり、セッションが終われば消えること。行をそのまま見たければ、言われたらチャットに貼る
   - 指摘があった: 下の「やり直す」

### 手番の要求を足す

語りと要求の JSON を Write でスクラッチパッドのファイル(`<scratchpad>/turns-<episode>.json` など。毎回上書きしてよい)に書き、そのパスを渡して足す。足した行(語りの行と手番の行。`id`・`character` など)が返り、待たずに終わる。

- Write と `add` を同じ返答の中で並べない。Write が通ったのを確かめてから `add` を打つ(Write が断られたまま `add` を打つと、前の手番のファイルがもう一度足される)。前の行が二重に入ったら、`clear --from <二重に入った最初の行の id>` で消してから足し直す

```json
{"narration": "<その場の何人もに見える・聞こえるようになったこと>",
 "witness_ids": [1, 21, 22],
 "turns": [{"character_id": 1, "time": "11589/05/18 15:54", "request": "<返す範囲>"},
           {"character_id": 21, "time": "11589/05/18 15:54", "request": "<その人物にだけ見える・聞こえること>\n<返す範囲>"}]}
```

```bash
.venv/bin/python -m tool.episode_session add --episode <episode> --turns <scratchpad>/turns-<episode>.json
```

- `narration`(語り)は、手番の前に一つだけ足す語りの行。`witness_ids` の人物それぞれの次の番で届く。同じ状況を人物ごとの `request` に書き写さない。語りが要らなければ省く(`turns` の配列だけを渡してもよい)
- 手番の人物の一手は、`witness_ids` の人物(手番に `witness_ids` を書けばその人物)の次の番に、名前付きで届く。その場にいて見える・聞こえる人物を入れる。離れた場所にいる・眠っているなど、見聞きしない人物は入れない(届けない一手は、要るなら語りに書く)
- 語りを付けずに手番だけを足すときも、`witness_ids` を必ず書く(全体か手番ごとに)。どちらも無い手番は断られる。一人きりの場面など、誰にも見せない一手は `[]` を書く
- 人物役に届くのは、前の自分の番から後に足された語りと、ほかの人物の一手(行動・セリフ)。前の番で届いたもの・自分の一手は届け直さない
- 語りは誰にも同じ言葉で届くので、三人称で書く(「お前は」と書かない)。一人にだけ見える・聞こえることは、その人物の `request` に書く
- 足したら、手番の行ごとに、その人物役へ SendMessage で `番: 行 <id>` とだけ送る。手番は足した順(行の id の順)にしか埋まらないので、一人に送り、`終わった` が返ってから次の人物に送る(先に送ると、人物役は「番でない」と返して止まる。そのときは前の手番が埋まってから送り直す)
- 番を送ったら、`wait --episode <episode> --record <行の id>` で一手が入るまで待つ。`wait` は一手を出さない
- 人物役は `終わった <id>: <行動>「<セリフ>」` と、一手を添えて返す。次を組むのはこれで足りる。同じ一手を `moves` で読み直さない(同じ中身が会話に二度積もる)。内心・狙いまで要るとき(視点人物の胸の内で次の語りを決めるなど)と、返りの形が崩れていたときだけ、`moves --episode <episode> --after <足した最初の行の id - 1>` で読む(`pending` が空でなければ、埋まっていない行の人物役に送り直す)
- 人物役がエラー(db への接続など)を返したら、同じ `番: 行 <id>` を一度送り直す。転送が 1 時間ごとに張り直されるので、そのあいだに当たったときは送り直しで済む
- 前の人物の一手を受けて結果を語る要求は、その一手を読んでから足す。結果を待たない手番は、一度にまとめて足してよい(番は一人ずつ送る)
- 何人かが受け持ちの違う動きを同時にするとき(火事で一人が梁を押さえ、二人が下敷きの人を引き出し、一人が窓の順を告げる)は、`"simultaneous": true` を付けて足し、番を全員に一度に送る(SendMessage を一つの返答の中で並べる)。全員の `終わった` を受けてから次を組む
  - 組の手番は、前の人物の一手を待たずに番が開き、組の中のほかの人物の一手は今の番では届かない(次の番で届く)。前の人物の一手を受けて動く手番(応じる・異を唱える)は、組にしない
  - 下の「同じ問いを並べない」はそのまま。組にするのは、それぞれの受け持ちが要求で決まっている手番だけ
- 同じ場にいる何人もに、同じ問い(「狼を見つけたときの反応」)を並べて求めない。答えの決まった問いを並べると、皆が同じことを言い、やり取りにならない
  - 出来事への反応は、まず一人(気づくのが早い・口を開く立場の人物)に求める。ほかの人物には、その一手を受けての一手(応じる・異を唱える・自分の受け持ちに動く・黙って従う)を求める。前の人物の一手は届いているので、まとめて足すときも「<前の人物>の言葉・動きを受けて」と書く
  - 皆が同じ結論に行き着く手がかり(御者の話など)を語りに書いたときほど、先に一人に言わせ、残りはそれを受けさせる
- `request` には、その人物にだけ見える・聞こえるようになったこと(あれば)と、この手番で求めること(要るなら返す範囲。「返事だけ」「歩き出すところまで」)を書く
  - 本文だけを書き、「この手番で求めること:」のような見出しを付けない。人物役は `request` 全体を語り部の要求として読む
- 語りは前の語りからの変わり目だけにし、状況の全体を書き直さない
- `time` には、その手番の作中の時刻を、材料の「この話」の時刻と同じ形で書く(語りの行には最初の手番の時刻が入る)。人物役には返らない
- 語りと `request` に年の数(材料の時刻の五桁の年)を書かない。時の流れは「翌朝」「三日後」のように、前の手番からどれだけ経ったかで書く
- 一手は、その人物の場面の一区切り(言いたいことを言い、動き、相手の返事を待つところまで)にする。出来事・人物の変化・本文に書く中身を減らさない範囲で、手番の数を絞る
  - 場面を進めない手番は回さず、語りにまとめる: 許しを求めて受ける往復(「行かせて」「分かった」)、段取りの確かめ、移動、人を帰す・呼ぶといった運び
  - 戦い(攻めと受け・当たったか外れたか)と、感情のやり取り(打ち明ける・言い争う・別れる・想いを伝える・言葉を受けて心が動く所)は、まとめずに一手ずつ手番で回す
  - 進めるだけの場面は数手で着地させ、手番は戦い・感情の山場に回す。同じやり取りを繰り返させない
- 手番を足さずに語りだけを足す(場面を締める・時間を飛ばす)ときは、`"turns": []` と、語りの時刻 `"time"` を渡す(時刻が無いと断られる)。手番を足すときの語りの時刻は、渡さなければ一つ目の手番の時刻になる

### プロットの台詞と行動を渡す

プロットの「」で括った台詞は、作者がその人物に言わせたい言葉で、地の文に書いたその人物の行動は、作者がさせたい動き。どちらも決まった一手ではなく、誘導として渡す。人物役は、自分ならどう言うか・どう動くかを考えて一手にする。

- 場面がその台詞・行動の所まで来たら、言う・する人物の手番の `request` に、作者の意図として書く。「作者はこの場面で、あなたが「<台詞>」と言うことを考えている。」「作者はこの場面で、あなたが<行動>ことを考えている。」と書き、続けて返す範囲を書く
- 渡すのは、言う・する本人の分だけ。ほかの人物の受け方・結果(相手が泣く・倒れる)は渡さない(結果は語り部が一手から決める)
- 台詞・行動に、その人物の知らないこと(見ていない出来事・明かされていない名前や秘密)が入っていれば、その人物の知ることのできる言葉に直して渡す。直せなければ渡さない
- 人物役の一手が意図と違っても(言い換えた・言わなかった・正反対のことを言った)、書き換えない・言わせ直さない。その一手から次を組む
- 渡した台詞・行動と、それがどう返ったかは、まとめに書く(下の「まとめ」)

### 新しい語を足す

語りと要求に、プロットにも材料にも無い固有の語(獣・魔物、道具、料理、店や商会、制度・決まり、作中の呼び名、仕事の名前など)を出したら、ためらわずにアイデアに足す。迷ったら足す。人名と場所の名前は足さない。

語の配列を Write でスクラッチパッドのファイル(`<scratchpad>/ideas-<episode>.json` など)に書き、そのパスを渡す。

```json
[{"keyword": "泥鰻", "description": "倉の地下水路に棲みつく、犬ほどもある鰻のような獣", "kind": "モンスター"}]
```

```bash
.venv/bin/python -m tool.episode_session add-ideas --episode <episode> --ideas <scratchpad>/ideas-<episode>.json
```

- 本文を書き終えたあと(手順 8)に `AddIdeas` で足すときも、この決まりで語を選ぶ
- `description` は、その場面でその語が何を指すかの一文(`ReadWritingStyle` の書き方に沿う)。`kind` は種別。分類の無い種別を渡すと、選べる種別の一覧を添えて断られるので、その中から選び直す
- 返る `added` は候補として足した語、`kept` は足さなかった語(既にある語か、人名・場所の名前)
- 手番を足す合間に、いくつかまとめて渡してよい。人物役には、ほかの語と同じく語りか要求で伝える(その語を知っているかは、人物役が自分で引く)

### まとめ

回し終えたら(やり直したあとも)、セッションの行(`read --episode <id>`)から次の形で報告する。セッションの行そのものは貼らない。

```
### 場面1: <場所>・<時刻> — <どう着地したか>
- #<行の id> <人物名>: <行動の要約>「<セリフの要約>」
- …
```

- 一手を一行にする。行の id は、ユーザがやり直す所を指すのに使う。内心・狙いは、行動・セリフから読めない向きのとき(隠している・偽っているなど)だけ短く添える
- 端役・群衆の動きと場面の飛ばし(時間・移動)は、それを書いた語りの次の行に添える
- 二人以上が同じ行動・同じ中身のセリフを返した手番(やり取りになっていない所)は、報告する前に、二人目の手番から消して、一人目の一手を受けさせて回し直す(「やり直す」の 4〜6。人物に意見は求めない)
- 終わりに、手番の行の数、プロットから外れた所(無ければ「なし」)、渡したプロットの台詞・行動ごとの返り(`「<台詞>」→ #<行の id> 意図どおり / 言い換えた「<言った言葉>」 / 言わなかった`。渡していなければ「なし」)、足した語を書き、「認めれば本文へ、直すなら行の id か場面で指摘を」と一行添える
- やり直したあとは、残した手番は場面の見出しだけにし、回し直した行から後を一行ずつ書く。その前に、人物ごとの意見(受け入れた・受け入れなかった所と理由)を一行ずつ書き、受け入れなかった所をどう扱ったかを添える

### やり直す

ユーザの指摘から、回し直す最初の手番の行を決める。行の id で指されればその行、場面・出来事で指されれば、それが最初に効く行。決めかねるときは尋ねる。

1. **それまでの人物役を使わない**: 人物役は演じた手番を自分の文脈に持っているので、消す手番を覚えたまま続けさせない。もう番を送らない(止まったままにしておく。動いている途中なら `TaskStop` で止める)
2. **人物に意見を求める**: その行から後に手番のある人物と、指摘が名指しした人物それぞれに、`character-actor` を一つずつ意見を返す役として起こす(互いに待たないので、まとめて裏で起こし、全員の返りを待つ)。行を消す前に起こす(意見の役は、指摘された手番を `played` で読んでから答える)
   - メッセージには、話の id・人物の id・「意見を返す」・回し直す行の id・その人物に向けた指摘を書く
   - 指摘は、その人物の知ることのできる言葉に直して渡す。その人物の知らない人物像・来歴・秘密・ほかの人物の内心は書かない(「B は実は妹だから、A はもっと疑う」なら「この場で A はもっと B を疑うのでは、という指摘」)
   - 返るのは、受け入れるか(受け入れる・一部受け入れる・受け入れない)、その人物としての理由、自分ならどう動くか
3. **意見を尊重する**: 回し直しの要求は、人物の意見に沿わせる
   - 受け入れた所と、人物が自分ならこう動くと返した所は、その人物の `request` に、この手番で求めることとして書く(内心・セリフは人物役に任せる)
   - 受け入れなかった所は、要求で押しつけない。状況(場面の運び・端役・時間)の指摘でも、それを受ける人物が受け入れなかった動きは求めない
   - 関わる人物がみな受け入れず、回し直しても変わる所が無いなら、消さずに意見をまとめて報告し、返事を待つ(人物役を流れの 1 と同じメッセージで起こし直しておく)
   - 指摘がプロットの大筋を変えるなら、手順 3 でプロットを直して入れ、「セッションの前に整える」をやり直してから回し直す
4. **その行から後を消す**: `clear --episode <id> --from <行の id>`(その行を含む)
5. **人物役を起こし直す**: 流れの 1 と同じメッセージで起こす。人物役は `knowledge` と `played`(残った自分の手番)を読み直し、「用意できた」と返して止まる
6. **回し直す**: 3 で決めた要求で、消した行から流れの 3 で最後まで回す。場面の運び・端役・時間の指摘は、語りに書く
7. **また待つ**: 流れの 4 のとおりまとめ(人物ごとの意見を含む)を報告し、返事を待つ

## ユーザが書いた本文を反映する

「ep61 書いた」は、ユーザが自分で書いた本文(GUI の話の画面で保存したものか、スキル `interactive-episode` で作者と語り部が書いたもの)を確定し、手順 8〜10 と「話のあとに、知ったことを足す」で世界に反映する合図。本文はユーザのもので、このセッションの Claude は書き足さない・直さない(確定のときに改行が整うだけ)。

1. **話を読む**: `ReadEpisodeTexts([id])` で題・時刻・プロット・本文を読む
   - 本文が空なら止まり、書いて保存してから合図するよう伝える
2. **登場人物・場所を確かめる**: 登場人物・場所が結んでなければ(手番を回さずに書いたなど)、本文から「セッションの前に整える」の 2 のとおり台詞・行動のある人物と主な舞台を決めて `CastEpisode` で結ぶ。視点は頼まれたときだけ入れる。時刻(`start`)が空なら、前後の話から決めて先に入れる
3. **材料を読む**: 手順 7 の `ReadEpisodeBrief`。設定は、プロット・セッションの行・今の本文から引かれる
4. **新しい語を足す**: 手順 8 の終わりのとおり、本文・プロット・セッションの行に出た固有の語のうち材料の「設定」に無いものを `AddIdeas` でまとめて足す
5. **確定する**: `CommitEpisode` に `id`・`main_text`(1 で読んだ本文をそのまま)を渡す。題は、作者が決めた題があればそのまま、空なら付けて渡す。`main_text` を渡すので、居場所の移動(`moves`)と関係(`relations`)も手順 9 のとおり返る
6. **人物の設定と、知ったことを足す**: 手順 10 と「話のあとに、知ったことを足す」のとおり。セッションの行が無ければ本文から読む。本文がセッションの行とずれていれば、本文に従う
7. **報告する**: 「報告する」のとおり(本文を書いた・人物役を起こしたの項は除く)。本文と人物の設定・前の話・設定が食い違って見えた所は、直さずに報告に書く

## セッションの前に整える

人物役を起こす前に、毎回この順で登場人物・場所・関係を整える。手番を自動で回す「ep<話id>」(手順 4)・ユーザが作者として書く「ep<話id> in」(スキル `interactive-episode`)で共通の流れ。人物役(`character-actor`)は起きたときに自分のデータを読むので、整える前に起こすと、古い登場人物・関係のまま演じる。

- 登場人物・場所がもう結んである話でも飛ばさない。ユーザが画面でプロットを書き換えたあと、結んだ登場人物・場所・関係が追いついていないことがある
- 整えたあとにプロットを直したら(ユーザの指示・手番への指摘で)、人物役を起こす(起こし直す)前に、また 1 からやり直す

1. **話と人物を読む**: `ReadEpisodeCasting(episode_id)` で、今のプロット・時刻・結んである登場人物・場所・視点と、候補を読む
   - 時刻(`start`)が空なら、前後の話から決めて先に入れる
   - 登場人物が関わった話は、手順 2 のとおり読む(このセッションで読み終えた人物は読み直さなくてよい)
2. **登場人物・場所を結び直す**: プロット(書きかけの本文があれば、それも)と今の結びを突き合わせる(下の「登場人物・場所」)
   - 台詞・行動があるのに結んでいない人物は足す。プロットから消えた(台詞・行動の無くなった)人物は外す。主な舞台がプロットと違えば場所を変える。候補に無い人物・場所は作る
   - 食い違いが無ければ結び直さない。あれば `CastEpisode(episode_id, character_ids=[…], location_id=…, viewpoint_character_id=…)` で結ぶ(登場人物はまるごと置き換わるので残す人物も渡す。名前だけ出る人物は拾い直される)
   - 足した人物に関わった話があれば、手順 2 と同じく読む
   - プロットが無ければ、結んである登場人物・場所をそのまま使う。プロットも登場人物も無ければ始めず、プロットか登場人物を尋ねる
3. **関係を整える**: 登場人物ごとに `character.list_character_relations.ListCharacterRelations(character_id)` で関係を読み、プロット・前の話と突き合わせる
   - 関係(`character_relation`)の無い二人は、人物役には初対面として渡る。前の話・プロットから、この話より前に知り合っているはずの二人に関係が無ければ、`CommitCharacterRelation` で足す(`start` は知り合った時刻。話の時刻より後にしない)。この話で初めて会う二人には足さない(確定のときに足される)
   - 間柄がプロット・前の話と食い違えば、`UpdateCharacterRelation` で直す(`text` は時期を限らない芯だけ、起きたことは出来事ごとの `histories`(`start` は起きた時刻)。`data_access_logic/readme.md` の「関係の芯と来歴」)
   - 芯(`text`)に、関係のある人物も知らないはずの秘密があれば、来歴(知る相手を絞った行)へ移すようユーザに伝える
4. **知る相手の抜けを確かめる**: `.venv/bin/python -m tool.episode_session knower-gaps --episode <id>` で、登場人物の来歴のうち、ほかの登場人物の名前が出るのにその人物が知る相手に入っていない行を見る(人物役は知る相手の行しか読まないので、居合わせた出来事・仲間うちで知れ渡ったことを知らずに演じる)。返った行は下の「知る相手の抜けを埋める」のとおり、一覧にしてユーザに確かめてから足す
5. **設定と照らす(任意)**: 手順 5
6. **返す**: 結び直した登場人物・場所(変えなければ「そのまま」)、足した・直した関係、知る相手を足した行を短く書く。そこからはスキルごとに進む(「ep<話id>」は手番へ、「ep<話id> in」は人物役を起こして作者に番を渡す)

## 知る相手の抜けを埋める

「セッションの前に整える」の 4 の `knower-gaps` で行が返ったら、行ごとに読み、名前の出た人物が居合わせた・聞いたはずかを決める。名前が出ても、居合わせていない・人づてにも聞いていない行は足さない。

- 足す行を「#<来歴の id> <持ち主>: <行の要約> → <足す人物>(知った時刻)」の一覧にして、ユーザに確かめてから足す
- 一つの行に、名前の出た人物が知るはずのことと知らないはずのこと(本人だけの秘密・その場にいなかった出来事)が混ざっていれば、その行には足さない。知るはずの所だけを新しい来歴の行(起きた時刻を `start` に、知る相手を本人と知るはずの人物)にして足す(入口の表の下の書き方)
- 知る相手を足すのは `character.update_knowledge.UpdateKnowledge`(`{'knowledge': {'knower_id': <知る人物>, 'character_histories': [{'id': <来歴の id>, 'known': true, 'start': '<知った時刻>'}]}}`)。知った時刻は、その出来事の時刻か、あとで聞いた時刻(合流した時刻など)。話の時刻より後にしない
- 名前が出ない行にも抜けはある(仲間になる前の出来事を、仲間になってから聞いた・見せられたなど)。人物の体・持ち物(翼・灯り・傷など)のように仲間うちで知れ渡っているはずのことは、名前が出なくても、持ち主の来歴に知る相手が足りているかを見る

## 話のあとに、知ったことを足す

本文を確定したあと(手順 9 のあと)、このセッションの Claude がセッションの行(`read --episode <id>`)を読み、話の中で人物が知ったことを db に残す。足すのは主要人物・サブキャラクターを問わない(手順 10 の来歴の書き足しとは別)。関係と知る相手(`knowers`)は、本文の結果に応じて、尋ねずに足す。知った時刻(`start`)はその話の時刻にし、それより前の話には効かないようにする。

- 初めて会って名乗り合った・言葉を交わした人物どうしの関係は、確定のときに AI が足す(手順 9)。足りない組・前から知り合いだったと分かった組があれば、尋ねずに関係(`character.commit_character_relation.CommitCharacterRelation`)を足す。知り合った時刻が決まっていなければ、`start` は話の時刻にする。`relation` は短い名前(「宿を貸した旅人」など)、`text` は時期を限らない間柄、`start` は話の時刻、会ったいきさつは `histories` に話の時刻の行(`{'start': '<年/月/日>', 'description': …}`)で書く。すでにある関係に話で起きたことを足すときも、`text` には書かず、話の時刻の行を足す(`data_access_logic/readme.md` の「関係の芯と来歴」)
- 話の中で明かされた来歴(打ち明けた秘密・名乗った身の上)は、聞いた人物を、その行の知る相手(`knowers` に `{"knower_id": <聞いた人物>, "start": "<話の時刻>"}`)に足す(入口の表の下の書き方)
- 話の中で初めて知った設定(アイデア)も同じく、`UpdateIdea` の `knowers` に足す
- 何を足したかを、報告に書く

## 本文に起こす

手順 6 で人物役に手番を回したときだけ。

- 筋はプロットではなく、`read --episode <id>` で読んだセッションの行から取る(演じた場面がプロットからずれていれば、セッションの行に従う)。行は手番の順(id の順)に、語り部の要求(状況)・人物の内心・行動・セリフ・狙いを持つ
- 材料は手順 7 で書き出したファイルを使う(読み直すと要約の確かめが走り直す)
- 視点に沿って小説にする。人物役のセリフは中身(言うこと・言わないこと)をそのまま使い、言い回しは人物の口調と文体の見本のセリフに揃えて直す。描写は地の文で厚くする。視点人物の内心は、その人物の行の内心から地の文に起こす。視点人物以外の内心は、語りが許す範囲でだけ書く
- 何人もが同じ中身のセリフ・行動を返した所は、一手ずつ並べて写さない。一人に言わせ、ほかの人物はそれを受ける動き・短い返事にまとめる(会話の受け渡しにする)
- 読者がもう読んだ中身をなぞるセリフは、中身をそのまま使う決まりの外にする。その場にいなかった人物へ見聞きしたことを伝え直す所は要点の一、二文に縮めるか地の文にし、許しを求めて受ける往復・決まったことの確かめ・同じ指示の言い直しは、短い返事か動作にまとめる
- セリフの言い回しに、来歴・場所の説明の書き言葉や慣用句(「耳で拾う」「顔役で出る」「下の段」)が混ざっていれば、その人物が普段使う言葉に直す

## 書くとき

- 材料の「書き方」に従う。文体(システムの決まりと、この世界の `style_preference`)のほか、文体の見本の読み方、名前だけ出る人物と端役の扱い、設定の呼び名と仕組みの書き方、生物・医療・兵器の抽象度、歳に合った振る舞いの決まりが入っている(`data_access_logic/episode/brief.py` の `_guide`)。ここに同じことは書かない
- 知る相手の限られた来歴・履歴は秘密として扱う。知らない人物の台詞・内心・視点の地の文には出さず、場面で明かされたときだけ書く
- 登場人物の直近の出来事はこの話の前に済んだこと。「この時点より後に既に決まっている出来事」と矛盾させず、先回りしない
- 前の話に出ていない人物は初登場として、外見・性格を描く
- 人物の持ち物・武器・身なりは、材料の来歴の種別「装い」「持ち物」の行(話の時刻に効いているもの。終わった行は材料に入らない)と体格に合わせる。装いの行が無ければ、手順 2 で読んだ関わった話の本文で、最後に手にした・手放した物を確かめてから書く(装いが空のまま、前の話で短剣を差した人物に、荷に括った棒を振らせた)

## 登場人物・場所

- 登場人物(`episode_character`)は、この話で台詞・行動のある人物。`ReadEpisodeCasting` の「登場人物」「名前だけ出る人物」「登場人物の候補」から選び、`CastEpisode` の `character_ids` に全員を渡す(まるごと置き換わる)
- 話題・回想・噂に名前が出るだけの人物は入れない(`mentioned=true` の行として自動で拾われる)。群衆・名前の要らない通りすがりも入れない
- db に人物として登録されている人物は名前で書く。登録されていない端役(宿の主・御者・通りすがりなど)は人物として作らず、プロット・語り・本文のどこでも名前を付けずに「隊商の主」「口笛の男」のように役割か見た目で書く(名前を付けると、同じ名の別の人物と取り違えて名前だけ出る人物に拾われる)。名前の要るほど話に関わる人物だけを、下のとおり作る
- 呼び名が違っても(役職・続柄・あだ名など)、人物像から同じ人物と分かれば既存の人物を使う
- db にいない人物が要るなら、作ってから `character_ids` に入れる。作品・場所・時刻に馴染む人物にする
  - `CommitCharacter`: 説明は `text` に書く。来歴の節目は起きた時刻(`'<年/月/日>'`。年だけ決まっていれば年の整数)を `start` にした行にし、サブキャラクターの来歴はこの話の時刻までにする
  - AI に組ませるなら `GenerateCharacter`(プロットを渡すと、その時刻・場所で役どころを果たせる年齢になる)
- 場所: 主な舞台が材料の場所より細かければ、「この場所の中の既知の場所」から選んで `location_id` にする。無ければ `CommitLocation` で足す(`parent_id` は材料の一番細かい場所id)
- 視点(`viewpoint_character_id`)は、頼まれたかプロットで決まっているときだけ入れる

## 報告する

終わったら書いた話の行(`episode`)を読み、題・時刻・視点・字数(`letters`)・あらすじ・足した人物・場所・足した設定の候補・来歴に足した人物と、人物役を起こした人物・手番の数・やり直した回数、話のあとに足した関係・知る相手を短く報告する。本文・プロット・材料のような長いものは返答に貼らない。
