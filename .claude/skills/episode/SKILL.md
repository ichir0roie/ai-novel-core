---
name: episode
description: 作者が画面で書いたプロット(`plot_text`)から、作品に話(episode)の本文を一話ぶん書いて足す(プロットは作者の書いたものを土台にし、出来事の取り込み・食い違い・頼まれたときだけ Claude が直す)。プロット・時刻だけ決めた話(本文の無い episode)に本文だけを書くのにも使う。このセッションの Claude がプロットから登場人物・場所を推測して結び、語り部を務めて人物役に手番を最後まで自動で回し、まとめを報告して確かめを待ってから(セミオート)、材料を読んで自分で本文を書いて確定し、人物役の差分を世界に入れる。「ep61」(61 は話の id)、ユーザが自分で書いた本文を世界に反映する「ep61 書いた」、「このプロットで話を書いて」「〇〇と△△が出る話を 11579/03/02 で」「エピソードを作って」「この枠の本文を書いて」などの依頼で使う。ユーザが場面を一つずつ出し、語り部と人物役が場面ごとに仮の本文を返す「ep61 in」はスキル `interactive-episode`、本文を書かずに作品全体の筋・設定を詰め、作者の一言から世界を広げる「ex3」(3 は作品の id)はスキル `expand`。
---

- 本文は材料を読んだこのセッションの Claude が書く(本文を書く生成関数は無い)
- 下の流れは目安。どの材料を足して引くか・誰をどこに出すかは、頼まれた話に合わせて決めてよい
- プロットは作者が画面で組み立てたものを土台にする。Claude が直してよいのは、話の周りの出来事の中身を話に取り込むとき・プロットが前の話・材料・出来事と食い違うとき・作者に頼まれたときだけ(`data_access_logic/readme.md` の「話のプロット」)。直すときは作者の書いた場面・台詞・順を消さずに保ち、足す・合わせる所だけを書き、直した所(前と後の要点)を報告する。気づいたこと・予定だけなら、末尾の「## メモ」の節に `- ` の箇条書きで足す
- 「ep61」(「61 をやろう」のように番号だけでも)は、話の id 61 を下の「流れ」で書く合図。その話の行(題・時刻・プロット・本文の有無)を読み、何をするかを短く返してから始める。本文がすでにあれば、書き直すか(スキル `revise-episode`)を尋ねる
- 「ep61 書いた」は、ユーザが自分で書いた本文を世界に反映する合図(`reflect.md` の「ユーザが書いた本文を反映する」)。本文に手を入れずに反映する。推敲と `#` の指示の補いは「ep61 補完」(スキル `complete-episode`)
- 作品の筋の検討(どう進めるか)はスキル `expand` の受け持ち。話(episode)の枠は頼まれたときだけ作る
- ユーザに尋ねるのは、頼まれた範囲を越える判断(大筋を変える・時刻を動かすなど)だけ。プロットに要る人物・場所・関係・知る相手は尋ねずに作り、報告に含める。取りこぼし・多少の食い違いは許し、流れを止めない

## 節の置き場

手順ごとの細かい決まりは、このディレクトリの別のファイルにある。その手順に入るときに Read する(ほかのスキルが「スキル `episode` の「<節>」」と書いた節もここで引く)。

| ファイル | 節 | 手順 |
| --- | --- | --- |
| `prepare.md` | セッションの前に整える・知る相手の抜けを埋める・プロットの前提を移す | 4 |
| `turns.md` | 手番を回す(セミオート)・語り部の決まり・手番の要求を足す・新しい語を足す・まとめ・やり直す | 6 |
| `writing.md` | 本文に起こす・書くとき・確定の前に日本語を見直す・登場人物・場所 | 8 |
| `reflect.md` | 世界に反映する・ユーザが書いた本文を反映する・報告する | 10 |

## 入口

入口は id と引数で呼ぶ。呼び方・行の引き方は、手元は `.claude/docs/db.md`、web のセッションは `.claude/docs/web-db.md`(自分の場所の方だけ読む)。
`ReadEpisodeBrief`・`ReflectEpisode` は AI を回すので数分かかることがある(web では `run_in_background`)。ほかは db だけの入口で、すぐ返る。
人物・話の材料は数万字になる。出力が頭だけになったら、逃がされたファイルを最後まで読む(`CLAUDE.md` の「ツールの使い分け」)。

| すること | 入口の id | 引数 |
| --- | --- | --- |
| 話の枠を足す・プロットを直す・本文を確定する | `episode.commit_episode.CommitEpisode` | `{'episode': {…}}`。新しい枠は `{'story_id': …, 'start': '<年/月/日>', 'character_ids': […]}`、既存の話は `'id': …` と変える欄だけ(渡した欄だけが直る)。`plot_text` はプロットの全文(スクラッチパッドのファイルに置いて読む)。確定のあとに AI は回らない |
| 登場人物・場所を決める材料を読む | `episode.read_episode_casting.ReadEpisodeCasting` | `{'episode_id': …}` |
| 登場人物が関わった直近の話を読む(本文は人物ごとの一番新しい話だけ) | `episode.read_cast_episodes.ReadCastEpisodes` | `{'episode_id': …}`(話の登場人物と名前だけ出る人物)か、`'character_ids': […]` を足してその人物だけ |
| 話を id で読む(本文まで) | `episode.read_episode_texts.ReadEpisodeTexts` | `{'episode_ids': […]}` |
| 名前だけ出る人物を拾い直す | `episode.refresh_mentions.RefreshMentions` | `{}`(すべての話)か `{'episode_ids': […]}` |
| 登場人物・場所・視点を結ぶ | `episode.cast_episode.CastEpisode` | `{'episode_id': …, 'character_ids': […], 'location_id': …, 'viewpoint_character_id': …}` |
| 本文の材料を読む(登場人物・場所を結んだあと) | `episode.read_episode_brief.ReadEpisodeBrief` | `{'episode_id': …}` |
| 手番を回していない話を世界に反映する | `episode.reflect_episode.ReflectEpisode` | `{'episode_id': …}`(`reflect.md`) |
| 登場人物の話し方を直前の五話のセリフから調整する(頼まれたときだけ) | `episode.refresh_voices.RefreshVoices` | `{'episode_id': …}` |
| 話に出た新しい語を足す | `episode_session.add_ideas.AddIdeas` | `{'episode_id': …, 'ideas': [{'keyword': …, 'variants': […], 'description': …, 'kind': …}]}`(`turns.md` の「新しい語を足す」) |
| 設定を引く | `idea.resolve_ideas.ResolveIdeas` | `{'ideas': [{'keyword': …, 'variants': […], 'description': …, 'kind': …}], 'location_id': …, 'time': '<話の時刻>'}` |
| 人物を足す | `character.commit_character.CommitCharacter` | `{'character': {'name': …, 'appearance': <見た目>, 'text': <説明>, 'start': …, 'location_id': …, 'histories': [{'start': '<年/月/日>', 'description': <来歴の節目>}]}}` |
| 人物を AI に組ませて足す | `character.generate_character.GenerateCharacter` | `{'character': {'name': …, 'text': <人物像と役どころ>, 'location_id': …}, 'time': '<話の時刻>', 'plot_text': <話のプロット>}` |
| 人物の来歴を読む | `character.read_character.ReadCharacter` | `{'character_id': …}`(時刻を渡さず、すべての行を読む) |
| 来歴の行を一つ足す | `character.append_history.AppendCharacterHistory` ほか | `data_access_logic/readme.md` の「来歴を一行だけ足して」 |
| 場所を足す | `location.commit_location.CommitLocation` | `{'location': {'name': …, 'kind': …, 'text': …, 'parent_id': …}}` |
| 書く文の書き方を読む | `style_preference.read_writing_style.ReadWritingStyle` | `{'writing_style': {'scope': '<書く文の範囲>'}}`(`text` に返る)。語りと要求は本文の範囲で、`'story_id': <作品 id>, 'episode_id': <話 id>` も渡す |
| 作品の話の並び(`start` 順) | `episode.read_episodes.ReadEpisodes` | `{'story_id': …, 'count': 500, 'text': False}` |

### 読む量を絞る

- 入口が返すもののうち、手順が読むと決めた所だけを読む。書き出したファイルを丸ごと Read せず、要る見出し・要る期間を `jq` で抜いてから読む
- 語り部(手順 2〜6)は、人物の来歴と `筋書き`(作者の先の予定)を読まない。人物のこれまでは、手順 2 の関わった話の本文から読む。語り部が話の時刻より先や、見聞きする位置で知れないことを知ると、語り・要求に先回りが混ざる
- 来歴は、本文を書くとき(手順 7 の材料)にだけ読む
- 話の外で人物たちが交わしたやり取り(スキル `character-scenes` の出来事など)は、語り部も `stage` の「話の前の出来事」「話のあいだの出来事」「話の後の出来事」で本文まで読む(`turns.md` の「語り部の決まり」)

### 入口の返す形

見出しは推測せず、ここか `jq 'keys'` で確かめてから引く(無い見出しは黙って null になる。`jq` の書き方は `.claude/docs/setup.md` の「jq」)。web のセッションで `flows.run` から返るものは `.result` に包まれない。

- `ReadEpisodeCasting`: `この話`(`話id`・`題`・`時刻`・`場所(広い順)`・`視点`・`プロット`)・`登場人物`・`名前だけ出る人物`・`登場人物の候補`・`この場所の中の既知の場所`。`登場人物`・`名前だけ出る人物` には `人物id`・`名前`・`人物像`・`口調` などが付く(`来歴(古い順)`・`筋書き` は付かない)。`登場人物の候補` は `人物id`・`名前`・`種別`・`年齢`・`人物像` だけ
- `ReadCastEpisodes`: 話ごとの配列(古い順)。`話id`・`作品`・`題`・`時刻`・`登場`・`名前だけ`(人物の名前の配列)・`本文`(人物ごとの一番新しい話だけ。ほかは null)。プロットは付かない
- `ReadEpisodeBrief`: `書き方`・`作品`・`文体の見本(古い順)`・`この話`・`この場所の直近の出来事(古い順)`・`この時点より後に既に決まっている出来事`
  - `文体の見本(古い順)` は本文の文字列の配列(`.["文体の見本(古い順)"][-1]` が直前の話。鍵は無い)
  - `この話` の中は `話id`・`題`・`時刻`・`終わり`・`場所(広い順)`・`視点`・`登場人物`・`名前だけ出る人物`・`設定`・`プロット`・`今の本文`
- `ReadEpisodeTexts`: 列名の英語(`id`・`title`・`main_text` など)の配列
- `tool.episode_session read` の行: `id`・`kind`(`人物`・`語り`・`作者`)・`character`(人物の名前。人物の行だけ)・`time`・`witnesses`(見聞きする人物の id)・`request`(語りの行では語り)・`simultaneous`・`thought`・`action`・`speech`・`aim`

## 流れ

- **手番を回す前に、出す人物が関わった話の本文を読む**。人物の芯(`text`)だけを見て動かさない
- **本文の材料を読む前に、登場人物・場所を話に結ぶ**(材料は結んだ登場人物・場所から引く)。設定(アイデア)は話に結ばず、材料を読むときに、プロット・話のセッションの行・今の本文に出た語で引かれる
- **書く文はどれも db の書き方で書く**: 書く前に、その文の範囲の書き方を `ReadWritingStyle` で読み、それに従う(このスキルの中に書き方を足さない)。範囲は、プロットとそのメモはプロット、語りと要求は本文(作品・話の id も渡す)、来歴は来歴、関係は関係、アイデアの説明はアイデア、人物の説明は人物。本文は材料の「書き方」で書く。人物役は、自分で人物役・来歴の範囲の書き方を読む

1. **話の行を用意する**
   - 本文の無い枠(id を頼まれた): その行を使う。時刻(`start`)が空なら、前後の話から決めて先に入れる
   - 新しい話: 作品の話の並びを引き、同じ時刻の話が無いか確かめてから、`CommitEpisode` で枠を足す(`story_id`・`start`・頼まれた人物の `character_ids`。作者がチャットでプロットを渡したか、書くよう頼んだときは、`plot_text` に入れる)
   - 作品・人物・場所は名前で頼まれても、引いた id を使う
2. **人物の関わった話を読む**
   - `ReadEpisodeCasting(episode_id)` で id 付きで読む: 今の登場人物・名前だけ出る人物と、登場人物の候補・場所とその中の既知の場所
   - `ReadCastEpisodes(episode_id)` を一度呼ぶ(登場人物・名前だけ出る人物の直近の話を、話ごとにまとめて古い順)。本文の付いた話(人物ごとの一番新しい話)から、人物がこのところ何をしたか・何を持ち、誰と何を話したかを掴む
   - 本文の付かない古い話は題と時刻だけ見る。プロットがその話の出来事を前提にしているときだけ、`ReadEpisodeTexts(episode_ids)` で本文を読む
   - 人物の設定と本文が食い違えば本文を正とし、ユーザに報告する(人物の設定を直すかはユーザが決める)
   - 本文に出てくるのに db にいない人物(上役・家族など)を使うときは、同じ名前で作る
   - 関わった話が本文と比べて少なすぎる(名前が出ているのに挙がらない)ときは、`RefreshMentions()` で名前だけ出る人物を拾い直してから読み直す
3. **プロットを確かめる・整える**
   - プロットが空か、本文に起こすには足りない(どの場面で誰が何をするかが読み取れない)ときは、足りない所を挙げて止まり、作者に画面で書いてもらうか、Claude が書くかを尋ねる。ユーザがチャットでプロットを渡したときは、それを `plot_text` に入れる
   - プロットの「## メモ」の節や本文に「〜は迷っている」の文(作者が決めかねているメモ)が残っていれば、どちらを取るかユーザに尋ねる
   - 読んだ話・材料とプロットが食い違うときは、作者の書いた場面と順を保ったまま食い違う所だけを直し(`CommitEpisode` に `id` と直した全文)、報告に前と後の要点を書く。大筋(誰が何をして、どう終わるか)が変わる直しは、直す前に尋ねる
   - 作者に頼まれて、話の周りの出来事(スキル `character-scenes` の当日の会話など)をこの話に取り込むときは、出来事の中身をプロットの場面として書き足す。場面の頭に、元の出来事の名前を添える(`# <場面>(出来事 <id>「<名前>」から)`)。取り込んだ出来事の本文は、客観的な事実だけに直しておく(スキル `character-scenes` の「6. 出来事を書く」)
4. **登場人物・場所・関係を整える**: `prepare.md`。手番を回さない話でも、登場人物・場所は結ぶ
5. **設定と照らす(任意)**
   - プロットが世界の設定と食い違っていないかを手番の前に確かめたいときだけ、プロットに出る固有の語(呼称・制度・道具・病など)を自分で挙げ、`ResolveIdeas` でアイデアと照らす(`location_id` は 4 で結んだ場所、`time` は話の時刻。当たらなかった語は候補のアイデアとして足される)
   - 返った `ideas` にプロットと食い違うものがあれば、ユーザに挙げて止まり、どう直すかを決めてもらってプロットを直してから、4 からやり直す
6. **手番を回す**: `turns.md`。このセッションの Claude が語り部を務め、人物役に場面を手番で最後まで演じさせる。終えたらまとめを報告して待ち、ユーザが認めたら人物役に「話を締める」を送って 7 へ進む。台詞・行動のある登場人物が一人だけの話と、ユーザが一人で書くよう頼んだときは飛ばす
7. **本文の材料を読む**: `ReadEpisodeBrief(episode_id)`。長いので、出力をスクラッチパッドのファイルへ書き出して Read する。中身:
   - 書き方(db の全体の行・作品の指示・本文の行・推敲の行・話の指示)・材料の読み方・作品
   - 登場人物の話し方: 話の時刻の口調・一人称・二人称などがそのまま入る(自動では調整しない。頼まれたときだけ `RefreshVoices` で調整してから読む)
   - 文体の見本: 同じ作品(親の作品の章・外伝を含む)の直前の話の本文を、新しい話から字数の上限まで
   - この話・結んだ登場人物(直近の出来事つき。筋書きは入らない)・名前だけ出る人物・設定・場所の直近の出来事・後に決まっている出来事
   - 設定: プロット・話のセッションの行・今の本文から AI が挙げた語でアイデアを引き、名前・呼び名に当たったものとその上位。当たらなかった造語は候補のアイデアとして足されて入る
   - 人物の来歴は、出来事の行の直近の 5 行と、話の時刻に効いている種別付きの行(持ち物など)だけが入る。「装い」は、話の時刻に身に着けている物ごとの今の姿。それより前のことは、手順 2 で読んだ関わった話から読む
   - 知る相手が人物に限られた行には「秘密」(誰だけが知るか)が付く。「秘密」の付いた行は、そこに挙がった人物だけが知る。スキルの「本質」は作者だけが読む
   - 登場人物どうしの関係は材料に入らない。要るときは手順 4 で読んだ関係から読む
8. **本文を書く**: `writing.md`。書いた本文はスクラッチパッドのファイルに置く。書き終えたら新しい語を足し、日本語を見直す
9. **確定する**: `CommitEpisode` に `id`・`title`・`main_text`(ファイルの中身)を渡す
   - 題は、作者が決めた題があればそのまま、空なら付ける。登場人物・場所は 4 で結んであるので渡さなくてよい
   - 確定すると、本文の改行が整い(`layout_novel_text`)、名前だけ出る人物が本文・プロットから拾い直される。AI は回らない
10. **世界に反映する**: `reflect.md`。手番を回した話は、人物役の差分と手番のセリフを `tool.episode_session apply` で入れる。回していない話は `ReflectEpisode`。終えたら `reflect.md` の「報告する」のとおり報告する
