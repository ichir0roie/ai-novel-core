# 手番を回す(セミオート)

スキル `episode` の手順 6。スキル `interactive-episode`・`complete-episode` も、手番の足し方・番の送り方・やり直し方はここに従う。

このセッションの Claude が語り部を務め、台詞・行動のある登場人物一人ずつの人物役(エージェント `character-actor`。opus・effort low(手番の返りを速くするため)、道具は Bash と Read)に場面を手番で演じさせる。手番はユーザに尋ねずに話の最後まで自動で回す。回し終えたら、セッションのまとめを報告してユーザの確かめを受ける。指摘があれば、関わる人物それぞれに意見を求め、人物の意見を尊重して、その手番から消して回し直す。

手番の中身(語り・要求・一手)は db に置かず、語り部と人物役が同じ機械で読み書きする手番のファイル(`.cache/episode_session/e<話id>/`。`tool.episode_session` のコマンドで扱う)に置く。手番のファイルはセッションが終われば残さない(web ではコンテナと一緒に消える)。人物役はファイルを見張らない。語り部が番の行を足して人物役に「番」と送り、人物役はいま開いている自分の行だけを読んで一手を入れ、「終わった <id>」と返して止まる。

- 人物役が読むのは、本人の外見・芯・ミーム・行動原理と、関係のある人物の外見・芯と、それぞれの来歴・スキル(名前と来歴)とアイデアの呼び名・受け止め方のうち知っているものだけ(知る相手に当たるもの。`data_access_logic/readme.md` の「来歴・履歴を知る相手」)と、本人が居合わせた過去の出来事(新しいものは本文、前のものは要約)。筋書き(`plot`)は渡らない
  - アイデアは、はじめに読む材料(`knowledge`)にはプロットに名前の出るものだけが入る。手番の要求に出た語は、人物役がそのつど `ideas` で引き、知っているものだけを読む
- 台詞・行動のある登場人物が一人だけの話と、ユーザが一人で書くよう頼んだときは、人物役を起こさず手番も回さない(手順 6 を飛ばす)
- 端役(db に人物としていない屋台の主・通行人など)と群衆は、人物役を起こさずに語り部が演じ、語りに書く(名前を付けない。`writing.md` の「登場人物・場所」)。話の登場人物(`episode_character`)に結んだ人物は、サブキャラクターでも人物役を起こす
- 芯(`text`)に、関係のある人物も知らないはずの秘密(出生の秘密など)が書いてあれば、その人物の来歴(知る相手を絞った行)へ移すようユーザに伝える
- 手番を回すあいだプロットは直さない。語り部はプロットの場面を状況として起こす(書き方の語り部の範囲の「プロットを状況として起こす」)。外れた所と、人物の決めたことと食い違う状況を起こした所をまとめに書く
- プロットにある人物の台詞(「」で括ったもの)と行動は、その人物の手番の要求に、この手番でする行動と言う中身として書く(書き方の語り部の範囲の「プロットの台詞と行動を要求に書く」)。人物役は、それを人物が自分で決めたこととして演じる。人物の芯とぶつかるときだけ断る
- ユーザが場面を一つずつ出しながら、場面ごとに人物を演じさせて仮の本文を見たいときは、スキル `interactive-episode` に移る

## 語り部の決まり

- 手番を足す前に、`ReadWritingStyle` で本文の範囲(作品・話の id も渡す)と語り部の範囲(`{'writing_style': {'scope': '語り部'}}`)を読む。語りと要求は両方の書き方で書き(語りの言葉は人物役のセリフにも本文にも移る)、手番の絞り方・プロットの台詞と行動の要求への書き方・状況の起こし方は語り部の範囲の行に従う。このファイルには、語り・要求の言い回しと場面の運び方の好みを足さない(足すのは語り部の範囲の行)
- 受け持つのは、プロットの進行と、場所・時刻・その場にいる人物・見える・聞こえること・人物の外から来る出来事(端役の言動・用事・知らせ・天気・物の在り処)の管理。人物が何を思い、何を知っていて、どう動くかは人物役が自分のデータから決める。人物役の一手を書き換えない
- 語り部は手順 2 で関わった話の本文まで読んでいるが、語りと要求には、見聞きする人物の位置で見える・聞こえることだけを書く。その人物の知らない人物像・来歴・設定の履歴・秘密は、場面で明かされた(言った・見せた)ときだけ書く
- 人物の体・持ち物・力(翼・灯り・傷・武器など)が、本人の意思と関わりなく動いた・開いた・光ったとは書かない。それを使うか、どう使うかは人物役が決める。語りに書くのは、人物役の一手で使ったものが、どう働いたか(結果)だけ
- 人物役の一手(行動・セリフ)は、見聞きする人物(`witness_ids`)にそのまま届く(内心・狙いは届かない)。語り部は書き写さない。一手の結果(当たった・倒れた・噛み折られた)は語り部が決めて語りに書く
- 語り部が決めるのは結果だけで、人物の狙い(何のために動いたか)は決めない・言い換えない。動きの行き先・的は、その一手の行動に合わせる。行動から行き先が読み取れなければ、`moves` で狙いを読んでから語る
- 手番の要求を出せるのは、人物役を起こした人物だけ。人物役のいない人物の手番を足すと、その行が埋まらず、後の手番が回らない
- 場面の材料は `stage` で読む(プロット・時刻・場所(広い順)とその説明・登場人物の人物 id と外から見て分かること(名前・年齢・性別・体格・装い・外見)・知り合いの組・話の周りの出来事(話の前・あいだ・後。本文つき))。結果はファイルに書かれ、`{"file": …}` だけが返るので、Read で最後の行まで読む。`stage` は、登場人物と知り合いの組を手番のファイルにも写す。手番を足す前に一度読み、登場人物・関係を結び直したら読み直す(写す前は `add` が断られる)
  - 体格は話の時刻の値、装いは話の時刻に身に着けている物ごとの今の姿。語りと要求で人物の持ち物に触れるときは、ここに合わせる。食い違って見えたら(前の話で持ち物が変わったのに装いが古いなど)、手番の前にユーザに伝える
  - 場所の説明は設定の書き言葉で書かれている。語りと要求には、その言い回しを写さず、視点人物が見てそのまま言える言葉に直す
  - 話の外で人物たちが交わしたやり取り(話の前・あいだの出来事)は、人物がそこで約束したこと・知ったこと・居た場所として場面の状況に効かせる。話の後の出来事は先回りせず、食い違わないためにだけ読む
- 語りと要求に物・現象の呼び名を出すときは、プロットと `stage` の言い方に揃える。どちらにも無ければ、`ResolveIdeas` で設定の呼び名を確かめてから書く
- 「知り合い」に無い二人は初対面として扱う。一手は名前付きで届くので、初対面の相手を `witness_ids` に入れると断られる。その人物の一手は、見た目(`appearance` で読む。名前は返らない)で語りか要求に書く。名前・経歴は、名乗る・噂を聞くなど、その場で分かったときだけ書く

| すること | コマンド(`.venv/bin/python -m tool.episode_session …`) |
| --- | --- |
| 材料を読み、登場人物と知り合いの組を手番のファイルに写す | `stage --episode <episode>` |
| 初対面の相手の見た目を読む | `appearance --character <相手の人物 id> --time '<時刻>'` |
| 手番を一つ足す(語りも添えられる) | `add --episode <episode> --character <id> --request '<要求>' --witness '<id>,<id>' --time '<時刻>' [--narration '<語り>']` |
| 組の手番・いくつもの手番を足す | `add --episode <episode> --turns <JSON のファイル>`(下の「手番の要求を足す」) |
| 番を送った行に一手が入るまで待つ(一手は出さない) | `wait --episode <episode> --record <行の id>`(組の手番は `--record` を重ねる。`{"filled": […]}` が返る。待ちきれなければ `pending` も返る) |
| 足した手番の一手を読む(内心・狙いまで要るときだけ) | `moves --episode <episode> --after <行の id>` |
| 場面に出した新しい語をアイデアに足す | `add-ideas --episode <episode> --ideas <JSON のファイル>`(下の「新しい語を足す」) |
| セッションの行をすべて読む | `read --episode <episode>` |
| ある行から後を消す(やり直す) | `clear --episode <episode> --from <行の id>`(人物役の差分も消える) |

## 流れ

0. **前の行を消す**: この話にもうセッションの行があれば(`read --episode <id>` が空でない)、`clear --episode <id>` で消してから起こす(前の行が残ると、前の場面の語りと一手が人物役に届く)
1. **人物役を起こす**: 台詞・行動のある登場人物ごとに `character-actor` を一つ、裏で(`run_in_background`)起こす(起こす前に、話の登場人物の一覧と起こす人物を突き合わせ、漏れが無いか確かめる)。最初のメッセージには話の id・人物の id だけを書く(材料は人物役が自分で読む)。人物役は材料を読み終えると「用意できた」と返して止まる。全員の「用意できた」を受けてから番を送る
2. **場面を組む**: `stage` を読み、プロットの場面(`#` の見出しごと)から、場面ごとに場所・時刻・その場にいる人物・その場面の着地点を決める
3. **手番を最後まで回す**: 下の「手番の要求を足す」で語りと要求を足し、人物役に番を送り、返った一手(行動・セリフ)を読んで次を足す。これを話の最後まで繰り返す。途中でユーザに尋ねたり、一手ずつ見せたりしない
   - 次に誰を動かすかは語り部が決める。直前の行動を向けられた人物、場面を着地点へ進める人物を先にする。黙って見ているだけの人物は手番を飛ばしてよい(見聞きした語りと一手は、次の番にまとめて届く)
   - 人物役の一手でプロットから外れても、引き戻す要求は出さない。その一手は起きたこととして残し、次の場面の頭か時間を飛ばす語りで、次のプロットの場面の状況を起こす。外れた所はまとめに書く
   - 人物役が断った・言わなかった・違う言葉にしたプロットの台詞と行動を、あとの手番で言わせ直さない。`終わった <id>(断った: …)` の理由は控えておき、まとめに書く
   - 場面を飛ばす(時間を進める・移動する)ときは、そのあいだに起きたことを語り部が決め、語りと新しい時刻にまとめて渡す
   - 語りに新しい固有の語を出したら、そのつど足す(下の「新しい語を足す」)
4. **待つ**: 話の最後まで進んだら、人物役は止めたままにする。下の「まとめ」を報告し、ユーザの返事を待つ
5. **返事を受ける**
   - 認めた(「OK」「本文にして」など): 人物役みなに「話を締める」を一つの返答の中で並べて送り(人物役は自分の差分を書いて「締めた」と返す。`reflect.md`)、返りを待たずに手順 7 へ進む
   - 本文は自分で書く(「本文は自分で書く」など): 人物役にはもう番を送らず、手順 7 から先へは進まない。次を一行ずつ添えて終える
     - 本文は GUI の話の画面の本文(`main_text`)に書くこと。書き終えたら「ep<id> 書いた」で反映する。推敲と補完を頼むなら「ep<id> 補完」(補ってほしい所・直し方の指示は、`#` で始まる行に書く)
     - 手番の行はこのセッションの手番のファイルにだけあり、セッションが終われば消えること。行をそのまま見たければ、言われたらチャットに貼る
   - 指摘があった: 下の「やり直す」

## 手番の要求を足す

手番一つ(と、その前の語り)は引数で足す。足した行(語りの行と手番の行。`id`・`character` など)が返り、待たずに終わる。

- 一つの返答の中で、`add` と、その手番の人物役への SendMessage(`番`とだけ)を並べて送る。人物役は、番の行が足されるまで少し待ってから読む。返りを受けたら(次の返答で)`wait --record <行の id>` で一手が入ったのを確かめる
- `add` が断られた(`error:`)ら、人物役は「番でない」と返して止まる。直して足し直し、もう一度 `番` を送る
- 組の手番(`simultaneous`)・いくつもの手番を一度に足すときだけ、JSON を Write でスクラッチパッドのファイル(`<scratchpad>/turns-<episode>.json` など。毎回上書きしてよい)に書き、`--turns` に渡す。この Write と `add` は同じ返答の中で並べない(Write が断られたまま `add` を打つと、前の手番のファイルがもう一度足される)。前の行が二重に入ったら、`clear --from <二重に入った最初の行の id>` で消してから足し直す

```json
{"narration": "<その場の何人もに見える・聞こえるようになったこと>",
 "witness_ids": [1, 21, 22],
 "turns": [{"character_id": 1, "time": "11589/05/18 15:54", "request": "<返す範囲>"},
           {"character_id": 21, "time": "11589/05/18 15:54", "request": "<その人物にだけ見える・聞こえること>\n<返す範囲>"}]}
```

- 語り(`--narration` / `narration`)は、手番の前に一つだけ足す語りの行。見聞きする人物それぞれの次の番で届く。語りが要らなければ省く
- 手番の人物の一手は、見聞きする人物(`--witness` / `witness_ids`)の次の番に、名前付きで届く。その場にいて見える・聞こえる人物を入れる。離れた場所にいる・眠っているなど、見聞きしない人物は入れない(届けない一手は、要るなら語りに書く)
- 見聞きする人物は必ず書く。一人きりの場面など、誰にも見せない一手は空(`--witness ''` / `[]`)を書く
- 人物役に届くのは、前の自分の番から後に足された語りと、ほかの人物の一手(行動・セリフ)。前の番で届いたもの・自分の一手は届け直さない
- 語りは誰にも同じ言葉で届くので、三人称で書く(「お前は」と書かない)。一人にだけ見える・聞こえることは、その人物の要求に書く
- 手番は足した順(行の id の順)にしか埋まらないので、一人に送り、`終わった` が返ってから次の手番を足す
- 人物役は `終わった <id>: <行動>「<セリフ>」` と、一手を添えて返す。次を組むのはこれで足りる。同じ一手を `moves` で読み直さない。内心・狙いまで要るときと、返りの形が崩れていたときだけ、`moves --episode <episode> --after <足した最初の行の id - 1>` で読む(`pending` が空でなければ、埋まっていない行の人物役に送り直す)
- 人物役がエラー(db への接続など)を返したら、同じ `番` を一度送り直す
- 前の人物の一手を受けて結果を語る要求は、その一手を読んでから足す
- 何人かが受け持ちの違う動きを同時にするとき(火事で一人が梁を押さえ、二人が下敷きの人を引き出すなど)は、`"simultaneous": true` を付けて `--turns` で足し、番を全員に一度に送る(SendMessage を一つの返答の中で並べる)。全員の `終わった` を受けてから次を組む
  - 組の手番は、前の人物の一手を待たずに番が開き、組の中のほかの人物の一手は今の番では届かない(次の番で届く)。前の人物の一手を受けて動く手番(応じる・異を唱える)は、組にしない
- `--time` / `time` には、その手番の作中の時刻を、材料の「この話」の時刻と同じ形で書く。人物役には返らない
- 手番の数の絞り方(一手の区切り・語りにまとめる運び・一手ずつ回す山場)は、語り部の範囲の「手番の運び」
- 手番を足さずに語りだけを足す(場面を締める・時間を飛ばす)ときは、`--narration`・`--witness`・`--time` だけを渡す(時刻が無いと断られる)

### プロットの台詞と行動を要求に書く・状況を起こす

どう書くか・どう起こすかは、書き方の語り部の範囲の行に従う。ここで決まっているのは、記録に残すことだけ。

- 要求に書いた台詞・行動と、それがどう返ったか(断ったなら、その理由)は、まとめに書く
- 人物の決めたことと食い違う状況を起こした所は、何を動かしたかをまとめに書く

## 新しい語を足す

語りと要求に、プロットにも材料にも無い固有の語(獣・魔物、道具、料理、店や商会、制度・決まり、作中の呼び名、仕事の名前など)を出したら、ためらわずにアイデアに足す。迷ったら足す。人名と場所の名前は足さない。

語の配列を Write でスクラッチパッドのファイル(`<scratchpad>/ideas-<episode>.json` など)に書き、`add-ideas --ideas <ファイル>` に渡す。

```json
[{"keyword": "泥鰻", "variants": ["鰻", "水路の獣"], "description": "倉の地下水路に棲みつく、犬ほどもある鰻のような獣", "kind": "モンスター"}]
```

- 本文を書き終えたあと(手順 8)に `AddIdeas` で足すときも、この決まりで語を選ぶ
- `description` は、その場面でその語が何を指すかの一文(`ReadWritingStyle` で読んだアイデアの範囲の書き方で書く)。`kind` は種別。分類の無い種別を渡すと、選べる種別の一覧を添えて断られるので、その中から選び直す
- `variants` には、同じものを指す別の呼び方・縮めた呼び方と、語を組み立てている 2〜3 字の核の語を必ず入れる(1 字の語は入れない)。既にあるアイデアとは、`keyword` と `variants` の部分一致で照らすので、`keyword` だけだと、名前の違う同じアイデアを候補として重ねて足す
- 返る `added` は候補として足した語、`kept` は足さなかった語(既にある語か、人名・場所の名前)
- 手番を足す合間に、いくつかまとめて渡してよい。人物役には、ほかの語と同じく語りか要求で伝える

## まとめ

回し終えたら(やり直したあとも)、セッションの行(`read --episode <id>`)から次の形で報告する。セッションの行そのものは貼らない。

```
### 場面1: <場所>・<時刻> — <どう着地したか>
- #<行の id> <人物名>: <行動の要約>「<セリフの要約>」
```

- 一手を一行にする。行の id は、ユーザがやり直す所を指すのに使う。内心・狙いは、行動・セリフから読めない向きのとき(隠している・偽っているなど)だけ短く添える
- 端役・群衆の動きと場面の飛ばし(時間・移動)は、それを書いた語りの次の行に添える
- 二人以上が同じ行動・同じ中身のセリフを返した手番は、報告する前に、二人目の手番から消して、一人目の一手を受けさせて回し直す(「やり直す」の 4〜6。人物に意見は求めない)
- 終わりに、手番の行の数、人物の決めたことと食い違う状況を起こした所(無ければ「なし」)、プロットから外れた所(無ければ「なし」)、要求に書いたプロットの台詞・行動ごとの返り(`「<台詞>」→ #<行の id> プロットどおり / 言い換えた「<言った言葉>」 / 言わなかった / 断った(<人物の理由>)`。書いていなければ「なし」)、足した語を書き、「認めれば本文へ、直すなら行の id か場面で指摘を」と一行添える
- 報告する前に、`moves --episode <episode> --after 0` で全員の狙いを読み、ほかの人物のセリフ・語りが、ある人物の狙いを本人の狙いと違えて言った所(取り違え)を探す。終わりに「狙いの取り違え」として、`#<言った行の id> <言った人物>:「<推し量り>」 ← #<動いた行の id> <動いた人物>の狙い: <aim>` の形で挙げる(無ければ「なし」)。語り部の語り・要求が取り違えを起こしていれば、その行から「やり直す」で回し直してから報告する。人物どうしの取り違えは、起きたこととして残す
- 人物の一手で、この話より先の前提が変わったところ(誰と同じ宿にいるか・同行するか・約束・持ち物)は、終わりに「先の話に効く所」として書く。先の話のプロットとぶつかりそうなら、それも添える
- やり直したあとは、残した手番は場面の見出しだけにし、回し直した行から後を一行ずつ書く。その前に、人物ごとの意見(受け入れた・受け入れなかった所と理由)を一行ずつ書き、受け入れなかった所をどう扱ったかを添える

## やり直す

ユーザの指摘から、回し直す最初の手番の行を決める。行の id で指されればその行、場面・出来事で指されれば、それが最初に効く行。決めかねるときは尋ねる。

1. **それまでの人物役を使わない**: 人物役は演じた手番を自分の文脈に持っているので、消す手番を覚えたまま続けさせない。もう番を送らない(動いている途中なら `TaskStop` で止める)
2. **人物に意見を求める**: その行から後に手番のある人物と、指摘が名指しした人物それぞれに、`character-actor` を一つずつ意見を返す役として起こす(まとめて裏で起こし、全員の返りを待つ)。行を消す前に起こす
   - メッセージには、話の id・人物の id・「意見を返す」・回し直す行の id・その人物に向けた指摘を書く
   - 指摘は、その人物の知ることのできる言葉に直して渡す。その人物の知らない人物像・来歴・秘密・ほかの人物の内心は書かない
   - 返るのは、受け入れるか(受け入れる・一部受け入れる・受け入れない)、その人物としての理由、自分ならどう動くか
3. **意見を尊重する**: 回し直しの要求は、人物の意見に沿わせる
   - 受け入れた所と、人物が自分ならこう動くと返した所は、その人物の要求に、この手番で求めることとして書く
   - 受け入れなかった所は、要求で押しつけない
   - 指摘の芯を人物が受け入れなかったら、消す前に、人物の意見と、人物の外の状況で起こす道(断られる・場所が埋まる・知らせが来る)を並べて、どちらを取るかユーザに尋ねる
   - 関わる人物がみな受け入れず、回し直しても変わる所が無いなら、消さずに意見をまとめて報告し、返事を待つ(人物役を流れの 1 と同じメッセージで起こし直しておく)
   - 指摘がプロットの大筋を変えるなら、プロットを直し、`prepare.md` の「セッションの前に整える」をやり直してから回し直す
4. **その行から後を消す**: `clear --episode <id> --from <行の id>`(その行を含む)
5. **人物役を起こし直す**: 流れの 1 と同じメッセージで起こす。人物役は `knowledge` と `played`(残った自分の手番)を読み直し、「用意できた」と返して止まる
6. **回し直す**: 3 で決めた要求で、消した行から流れの 3 で最後まで回す
7. **また待つ**: 流れの 4 のとおりまとめ(人物ごとの意見を含む)を報告し、返事を待つ
