# 小説家になろうへの投稿(手元だけ)

話の本文を、Playwright(`tool/narou.py`)で小説家になろうへ投稿する。仮実装で、なろうの画面の URL・入力欄・ボタンはまだ実際の画面と突き合わせていない(`tool/narou.py` の頭の定数)。

## いつ動かすか

- 手元(`CLAUDE_CODE_REMOTE` が `true` でない)だけで動かす。web のセッションでは動かさない(`tool.narou` も止まる)。web で頼まれたら、手元のセッションで頼み直してもらう
- スキル `episode` の本文の確定・スキル `revise-episode` の推敲の確定のあと、ユーザに投稿を頼まれたときだけ動かす。頼まれずに投稿しない(スキル `auto-revision` の推敲でも投稿しない)

## 用意

playwright は API(Lambda のイメージ)と web のセッションに入れないよう、`requirements.txt` と分けて `requirements-narou.txt` に持つ(`.claude/docs/setup.md` の「python」)。初めての手元では、`.venv` に足してからブラウザを入れる:

```
uvx --from 'uv>=0.9' uv pip install --python .venv/bin/python -r requirements-narou.txt
.venv/bin/python -m playwright install chromium
```

## 画面の操作

`tool/narou.py` の画面の操作(開く・リンクやボタンを押す・入れる)は、みな `Site` を通す。どの操作も 1 秒の間(`OPERATION_INTERVAL_SECONDS`)を置いてから行い、読み込みを待ち、ログインの画面へ飛ばされていないかを確かめる。なろうへの負荷を下げるため、操作を足すときも `page` を直に触らず `Site` に足す。

## ログイン

最初に一度だけ、ユーザが手でログインする。Claude は代わりにログインしない(ID・パスワードを受け取らない)。

```
.venv/bin/python -m tool.narou login
```

- ブラウザは、ワークスペースの `.cache/narou/browser/` をユーザデータのディレクトリにして開く(`tool/narou.py` の `USER_DATA_DIR`。ログイン・投稿・当てはめのどれも同じディレクトリを使う)
- ブラウザが開くので、ユーザがなろうにログインする。ログインの画面を離れたら閉じる(10 分で諦める)。クッキーはユーザデータのディレクトリに残る
- 以後の操作はこのクッキーでログイン済みとして動く。ログインが切れていたら操作が止まるので、ユーザに `login` をやり直してもらう
- 同じユーザデータのディレクトリは、一度に一つのブラウザしか開けない。`--headed` で開いたままのブラウザがあれば閉じてから回す
- `.cache/narou/` はリポジトリに入れない(`.gitignore` の `.cache/`)。中身を返答に貼らない

## すでになろうにある小説・部分を当てはめる

db の作品・話より先になろうに投稿してあった小説・部分は、一覧を読んで番号を当てはめる。投稿の前に済ませておく(済ませないと、投稿の順の確かめで前の話が未投稿として止まり、投稿した話を二度足すことになる)。

1. 小説を作品に当てはめる。小説の一覧を読み、小説の題と作品の名前で組んだ案を出す:

   ```
   .venv/bin/python -m tool.narou match-novels > <スクラッチパッド>/narou-novels.json
   ```

2. 書き出したファイルを Read で読み、ユーザに示す。見出しの意味:
   - 「当てはめる」: 番号の無い作品と、題の同じ小説の組。`--apply` で書くのはこれだけ
   - 「番号が入っている」: すでに番号のある作品。触らない
   - 「番号がなろうの一覧に無い」: 番号はあるが、なろうに見当たらない。なろうで消したなら、GUI で番号を空にする
   - 「db に題の当たらないなろうの行」・「なろうに題の当たらない db の行」: 題が違って組めなかったもの。ユーザに対応を聞き、GUI で番号を入れる
3. 案を認められたら `--apply` を付けて回し直す。違う組があれば、先に GUI で直すか、`--apply` をせずに GUI で入れる
4. 部分を話に当てはめる。番号のある小説ごとに、部分の一覧を読み、サブタイトルと話の題で組む(本文の無い話は見ない)。同じ題がいくつもあれば、なろうの並びと話の `start` 順で組む。`--story <作品id>` で一つの小説に絞れる:

   ```
   .venv/bin/python -m tool.narou match-parts > <スクラッチパッド>/narou-parts.json
   ```

   出力は小説の番号ごとに、2 と同じ見出しで並ぶ。2・3 と同じく示して、認められたら `--apply` を付けて回し直す

- 一覧の URL(`NOVEL_LIST_URL`)・ページ送りのリンク(`NEXT_PAGE_LINK`)・リンクの文言から題を読む所は仮実装。初めて回すときに `--headed` で画面と出力を突き合わせる

## 投稿する

投稿先の小説は、作品の `narou_novel_id`(なろうの小説管理の画面の URL に出る小説の番号。Nコードではない)。話の作品が空なら、親の作品をたどって番号のある一番近いものを使う(章は親の作品の小説へ。別の小説にする外伝は、その作品に番号を入れる)。どこにも無ければ `post` が止まるので、ユーザに番号を聞き、GUI の作品の画面か入口 `story.update_story.UpdateStory` で入れる。

`post` は話の `narou_novel_data_id`(投稿した部分の番号。部分の管理画面の URL の `noveldataid`)で動きを変える。

- 空(まだ投稿していない): 小説の管理画面から次話投稿の画面へ進み、次話として足す。投稿したら部分の番号を話に書き戻す。同じ小説へ投稿する話のうち、この話より前(`start` 順)にまだ投稿していない話があれば、それを挙げて止まる。ユーザに伝え、先に投稿するかを尋ねる
- 入っている(投稿した): 部分の管理画面から編集の画面へ進み、今の題・本文で書き換える。推敲した話はこちらになる
- なろうの前書き・後書きと章は扱わない。要るときはユーザがなろうの画面で手で直す

1. 確認画面まで進める(投稿しない):

   ```
   .venv/bin/python -m tool.narou post --episode <話id>
   ```

   次話投稿の画面にサブタイトル(`episode.title`)と本文(`episode.main_text`)を入れて確認画面まで進み、スクショを `.cache/narou/episode-<話id>-confirm.png` に撮って止まる
2. スクショを Read で見て、サブタイトル・本文の頭と終わりが入っているかを確かめ、ユーザに示して投稿してよいか聞く
3. 認められたら `--submit` を付けて回し直す。確認画面から投稿まで押す

- 画面が開かない・リンクや入力欄が見つからないで落ちたら、`--headed` で開いて画面を確かめ、`tool/narou.py` の定数を直す(仮実装の突き合わせ)
- 投稿したのに部分の番号が読めなかったときは、警告が出る。ユーザに部分の管理画面の URL を聞き、`noveldataid` を GUI の話の画面の `narou_novel_data_id` に入れる。入れないまま `post` を回し直すと、同じ話を二度足してしまう
- なろうの画面で部分を消したら、その話の `narou_novel_data_id` を空にする
